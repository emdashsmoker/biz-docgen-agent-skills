# 기획 설계

- (승인) [확인] 승인 일자와 승인 범위를 기입. 원고 작성 착수 조건은 이 줄의 승인 기록
- 기획보고서의 설계 문서. 작성 방법은 references/planning.md 기획 설계 절
- 0단계에 기본 정보를 채움. 나머지 절은 1단계에 채움
- 목차 표의 판단문은 원고의 □ 제목으로 그대로 옮겨짐. 설계 언어(골격의 단 이름, 상황, 문제, 핵심 질문, 계통 명칭)는 이 파일에만 기재

| 항목 | 내용 |
|---|---|
| 유형 | 기획 유형 예시나 간단한 형식 예시의 유형명. 예시 밖의 유형은 유저가 부른 이름 [확인] |
| 문서 제목 | [확인] |
| 보고 대상 | 결정하거나 실행할 주체. 없으면 `없음` [확인] |
| 결과물 이용자 | 결과물을 이용하거나 누릴 사람. 주민, 기업, 방문자, 사용자, 기여자 등 [확인] |
| 분량 | 유저 지정 값 또는 모델 설계안 [확인] |
| 납품 형식 | hwpx 또는 docx(둘 다는 고지 후 허용) [확인] |
| 장표 처리 | engine 또는 split [확인] |
| 문서 구성 | 목차, 쪽번호, 표지, 간지 중 삽입 항목 [확인] |
| 웹검색 | 허용 또는 불허 [확인] |
| 문서 주체 | 사업을 추진하는 주체. 원고 표기(실명 또는 `[기업명]`) [확인] |

## 결정 사항

- (결정) 보고 대상이 기획보고서를 읽고 내릴 결정. 보고 대상이 없으면 문서로 정하는 사항. 정보 전달 문서는 독자가 문서로 할 수 있게 되는 일 [확인]
- (설득 근거) 그 결정에 보고 대상이 요구하는 근거. 예시로 예산 근거, 비교 대안, 추진 일정, 투자 회수 전망 등 [확인]

## 문제 진술

- (상황) 문서 주체와 주제의 현재 상태. 확인된 사실만 기입 [확인]
- (문제) 주체가 도달하려는 상태와 상황의 차이. 도달 상태의 근거 자료를 병기 [확인]
- (핵심 질문) 문서 전체가 답하는 질문 1개 [확인]
- (범위와 제약) 해결책이 다룰 영역, 제외 영역, 제약 조건(예산, 법령, 일정 등) [확인]
- (계통) 목표 설정, 갭 분석, 결합 중 1개와 판정 근거 1줄 [확인]

## 경쟁 구도

- 문서 주체나 대상 사업이 한정된 재원을 두고 다른 주체와 겨룰 때 작성. 해당이 없으면 이 절을 삭제
- 확인된 사실만 기입. 경쟁 우위와 열위는 장별 메시지와 □ 판단문으로 세움
