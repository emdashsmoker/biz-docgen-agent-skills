# 사전진단보고서 작성 경로

- RFP를 근거로 과업 착수 전 시점의 진단 결과를 최종보고서 체계로 작성하는 경로
- (목적) 과업 착수 전 진단 단계에서 발주처 담당자가 현황, 격차, 방향(안)을 확인하여 사전 협의와 내부 보고에 쓰는 문서. 최종보고서 체계를 갖추어 담당자가 최종 산출물을 미리 보는 초안을 겸함
- 용도는 발주처와의 사전 협의 자료, 착수보고 기초 자료, 제안 준비용 조사 자료
- 산출 범위는 전체 목차 또는 선택한 장. 통상은 장 단위 일부 산출
- 설계 순서는 RFP, 진단서, 모듈 골격, 스토리라인, 목차
    + 진단서와 보고서 스토리라인은 제안서 경로의 제안전략서와 스토리라인에 대응
    + 설계 대상은 발주처 문제의 해결 논리. 방법은 진단 설계 절의 문제해결 방법론
- 현장 조사(설문, 면담, 내부 자료 등)가 필요한 절도 공개 자료로 예비 진단을 채움. 현장 조사는 예비 진단의 검증 수단으로 설계
- 제외 대상 과업은 SKILL.md 도입부 범위 항목을 그대로 적용

## SKILL.md 적용 범위

| 구분 | SKILL.md 절 |
|---|---|
| 그대로 적용 | 이용 안내, 대화 응답, 준비, RFP 해부의 요구항목표, 과업 유형별 모듈 골격, 모듈총괄표, 원고 계위, □ 제목의 문체, 괄호 소제목, 독자 관점 서술, 자기완결 서술, 문장 규율, 원본 이미지 재사용, 조판, 렌더링 검수 |
| report.md로 대체 | 절차, 제안전략서(진단서), 장 구성, 스토리라인 확정, 분량 구성 단위, 점검 대상, 목차와 쪽번호의 기본값 |
| 적용하지 않음 | 배점표, 섹션대장, 공통 파트, Task 서술 표준, 추진체계의 배치, 심층 검토의 통제배점 기준 |

- 착수 순서는 의존성 설치, 렌더러 확보, `init 작업폴더 --kind report`, `selftest 작업폴더`, `rfp RFP파일 작업폴더`, 착수 질의
    + `init --kind report`는 assets/diagnosis.md를 00_진단서.md로 배치
- 착수 질의로 아래 항목을 한 번에 질의
    + 산출 범위. 전체 목차 또는 선택 장
    + 보고서 명칭과 발주처의 실명 표기
    + 웹검색 허용 여부. 불허 시 문헌 절의 수치는 모델 지식 값에 기준 연도와 `[확인]` 표지를 붙임
    + 현장 조사 계획의 보유 여부(조사 대상, 표본 규모, 조사 시기 등). 계획이 없으면 모델이 조사 설계안을 작성
    + 납품 형식(hwpx 또는 docx 중 1개 권장. 둘 다는 SKILL.md 산출 유형 절의 고지 후 허용), 표지 삽입 여부, 밴드 색 테마, 장표 처리 방식
    + PDF 동봉 여부. 기본은 미동봉. 근사 렌더링 안내는 SKILL.md 렌더링 검수 절의 PDF 동봉
    + 보고서 유형과 과업 유형의 판정 결과. 판정 방법은 목차 설계 절의 목차 사례 표와 SKILL.md 과업 유형별 모듈 골격 절
- 1단계는 SKILL.md RFP 해부 절의 요구항목 이관 규칙을 적용. 사전진단보고서 작업폴더에서 `rfp`는 요구항목표만 배치(배점표 없음). 이관 후 진단 설계 절로 00_진단서.md를 채움
- 2단계는 02_모듈총괄표.md(SKILL.md 모듈총괄표 절)와 02_스토리라인.md를 작성. 02_스토리라인.md는 `<SKILL>/assets/report-storyline.md`를 작업폴더에 복사 후 채움
    + 요구항목표의 배치 섹션 열에는 절 번호(예시로 2.1)를 기입
    + 산출 범위 밖의 요구항목에는 `범위 외`를 기입
    + 보고서로 답하지 않는 수행 의무 요구항목(사후지원, 교육, 보안 서약 등)도 `범위 외`로 기입. 비고 열에 사유 1줄
    + `check rfp`는 배치 섹션 값을 02_스토리라인.md 목차 설계 표의 절 번호와 대조
    + 제시와 승인은 스토리라인 확정 절
- 3단계와 4단계는 장 단위로 반복 가능. 한 장의 자료 조사를 마치면 그 장의 원고를 작성
- 세션 인계 시 state.json, 00_진단서.md, 02_스토리라인.md를 먼저 읽음. 02_스토리라인.md의 (승인) 줄로 2단계 완료 여부를 판단

## 진단 설계

- 진단 설계는 문제해결 방법론 1개를 따름. 방법론 단계는 문제 정의, 이슈 분해, 우선순위, 분석 계획, 분석, 종합, 전달. 아래 규칙은 각 방법론 단계의 세부 규칙
- 방법론 단계는 이름으로 부름. 절차 절의 작업 단계는 번호로 부름. 두 단계의 대응과 작성 위치는 아래 표

| 방법론 단계 | 작업 단계 | 작성 위치 |
|---|---|---|
| 문제 정의 | 1단계 | 00_진단서.md 발주 배경, 경쟁 구도, 문제 진술, 기대 성과 |
| 이슈 분해 | 1단계 | 00_진단서.md 진단 질문 |
| 우선순위 | 1단계 | 00_진단서.md 진단 질문 표의 우선순위 열 |
| 분석 계획 | 1단계, 2단계 | 00_진단서.md 가설(1단계), 02_모듈총괄표.md와 02_스토리라인.md 초안(2단계) |
| 분석 | 3단계 | 03_자료대장.md |
| 종합 | 3단계 | 02_스토리라인.md 확정본. 초안의 판단문과 장별 메시지를 분석 결과로 확정 |
| 전달 | 1단계, 4-6단계 | 00_진단서.md 활용 설계(1단계), 원고(4단계), 점검(5단계), 조판(6단계) |

- (발주 배경) SKILL.md 제안전략서 절의 이면 니즈 질문(발주 사정, 설득 대상, 부정 현상)을 적용. 민간기업은 경영 실적, 신규 사업 계획, 투자 유치 일정 등을 발주 사정의 재료로 사용
- (경쟁 구도) 발주처나 대상 사업이 한정된 재원을 두고 다른 주체와 겨루면 문제 정의에 경쟁 관점을 포함. 재원은 고객의 구매, 국비, 부처 예산, R&D 과제, 투자 등
    + 해당 사례는 지자체 간 국비 경쟁, 부처 간 예산 경쟁, 연구 컨소시엄 간 대형 R&D 수주 경쟁, 공기업과 공단의 수익 사업, 민간기업의 사업 성장과 기술사업화 등
    + 기입 항목은 재원과 제공자, 경쟁자와 대체재, 경쟁 조건. 확인된 사실만 기입
    + 경쟁 조건은 재원 배분의 규칙. 공모 방식, 평가 기준, 조달의 참가 자격, 가격과 진입 규제 등이 해당
    + 경쟁 우위와 열위는 진단 질문과 가설로 세움. 확인은 분석 장의 경쟁 분석
- (문제 진술) 구성은 상황, 문제, 핵심 질문, 범위와 제약. 문제는 발주처가 도달하려는 상태와 상황의 차이
    + 도달 상태의 근거는 상위계획의 목표, 제도의 요구 수준, 비교 기관이나 경쟁자의 수준, 고객의 요구 등에서 확인된 값
    + RFP 배경 문장의 요약은 문제 진술로 인정하지 않음
    + 범위와 제약은 해결책이 다룰 영역, 제외 영역, 제약 조건(예산, 법령, 일정 등). RFP와 발주 배경에서 확인
    + 핵심 질문은 발주처가 보고서를 받아 내릴 결정의 해결 방향을 묻는 질문. 예시로 "2단계 사업의 지원 대상과 규모는 무엇인가". 답은 방향(안) 절에 둠. 방향(안)의 재료는 진단 결과
- (기대 성과) SKILL.md 제안전략서 절의 성과 규칙(대상, 시점, 상태의 특정)을 적용
- (진단 질문) 문제가 생긴 이유를 묻는 이슈 트리. 해결 방향의 이슈 트리는 진단이 끝난 뒤 본 과업에서 전개
    + 뿌리 질문은 "문제 진술의 문제는 왜 생겼는가". 모든 진단 질문은 원인을 묻는 질문. 현황 사실은 03_자료대장.md에 지지, 반증, 배경 중 1개로 기록
    + 하위 질문은 상위 질문의 원인 후보를 나눈 질문. 발주처가 조치할 수 있는 원인이나 발주처가 통제할 수 없는 외부 요인에 닿으면 전개를 멈춤
    + 분해 기준은 같은 상위 질문 아래의 질문 묶음마다 시간, 구조, 유형 중 1개. 시간은 앞뒤 순서가 있는 과정의 구분. 예시로 업무 흐름의 순서, 원인에서 결과로 이어지는 과정 등. 구조는 전체를 부분으로 나눈 구분. 예시로 조직, 지역, 시스템의 구성 요소 등. 유형은 상위 개념을 종류로 나눈 구분. 예시로 원인의 종류, 기업 규모, 이용자 유형 등
    + 묶음의 질문은 2-4개. 겹침과 빠짐을 점검. 질문마다 대응 모듈을 지정. 대응 모듈이 없는 질문은 모듈을 추가하거나 질문을 삭제
- (우선순위) 기준은 문제에 미치는 영향의 크기와 발주처가 바꿀 수 있는 정도
    + 값은 상, 중, 하 중 1개. 두 기준이 모두 높으면 상, 1개만 높으면 중, 모두 낮으면 하
    + 상 질문의 절에 분석과 분량을 먼저 배정
    + 자료 확보의 어려움은 가설 표의 자료 유형과 분석 방법에서 다룸
- (가설) 말단 진단 질문마다 답을 먼저 세움. 자료로 확인하거나 기각
    + 상위 질문의 답은 종합 단계에서 하위 판정을 묶어 세움
    + 가설은 자료 수집의 범위를 정하는 기준
    + 지지 조건은 가설을 지지하게 되는 자료의 모습. 반증 조건은 가설을 기각하게 되는 자료의 모습
    + 분석 방법은 methods.md의 해당 과업 유형 절에서 고름
- (활용 설계) 결과물이 발주처의 의사결정에 쓰이도록 정하는 작성 원칙. 활용 장애, 결과물 요건, 설계 원칙의 순서로 기입. 설계 원칙은 반영 절의 원고 작성 규칙으로 쓰임

## 목차 설계

### RFP 우선 원칙

- 목차의 원천은 RFP 과업 내용. RFP 요구항목은 전부 목차에 배치. 배치 여부는 요구항목표의 배치 섹션 열로 확인
- 모델은 보고서 논리에 맞춰 RFP 구성을 조정. 조정 유형은 순서 조정, 방법 보완, 내용 정정
    + (순서 조정) RFP의 나열 순서가 장 순서 절의 흐름과 어긋나면 목차 순서를 바꿈. 예시로 RFP가 전략 수립과 내부 현황 분석을 외부 환경 분석보다 먼저 적은 경우 외부 환경 분석, 내부 현황 분석, 전략 수립 순서로 배치
    + (방법 보완) RFP가 지정한 분석 방법이 과업 목적에 비해 부족하면 보완 방법을 더함. 보완 방법은 SKILL.md 과업 유형별 모듈 골격과 methods.md에서 고름
    + (내용 정정) RFP의 사실 오류와 시효가 지난 사항(폐지된 제도, 개편된 기관명, 종료된 계획 등)은 현행 기준으로 작성
- 조정 내역은 00_진단서.md의 RFP 조정 내역 표에 기록. 2단계 승인 요청에 목차와 함께 제시

### 목차 도출

- 목차는 진단 질문과 RFP 요구항목에서 도출. 순서는 진단 질문, 모듈 골격, 스토리라인, 목차
- 장과 절의 이름은 RFP 과업 내용의 표기를 따름. 모듈 골격과 목차 사례의 명칭은 RFP 워딩으로 바꿔 씀. 바꾼 표기는 00_진단서.md RFP 용어 표에 기록
- 장의 개수와 구성은 RFP와 과업 규모에 맞춰 조정. 장의 통합, 분할, 생략 등으로 규모를 맞춤
- 장 구성의 근거는 02_모듈총괄표.md. Module 1개는 장 1개 이상, Task 1개는 절 1개에 대응. Task가 많은 모듈은 장을 나눔
    + 모듈 골격은 SKILL.md 과업 유형별 모듈 골격 표에서 가져옴. 모듈마다 답하는 진단 질문은 00_진단서.md 진단 질문 표의 대응 모듈 열로 확인
    + 모듈이 없는 장(과업 개요, 결론, 부록 등)은 목차 사례 절의 장별 절 구성 표로 보완
- 모듈에 대응하는 장의 절은 답하는 질문(진단 질문, 핵심 질문)이나 배치된 요구항목을 1개 이상 가짐. 둘 다 없는 절은 목차에서 삭제. 과업 개요, 결론, 부록 장의 절은 목차 사례 절의 장별 절 구성 표를 따름
- 절의 하위 구성은 항(1.1.1)까지 사용. 가나다는 한 절의 □가 5개 이상일 때 묶음 단위로 사용
- 제도 서식이 정해진 보고서(R&D 자체평가 결과보고서, 효과성 분석 보고서 등)는 해당 연도 지침 서식이 목차. 진단 설계는 서식 안의 서술 논리에 적용

### 장 순서

- 장 순서는 스토리라인의 흐름. 앞 장의 결론은 뒤 장의 전제. 뒤 장의 근거는 앞 장에서 확인됨
- 흐름은 methods.md 서두의 계통 표를 따름
    + (목표 설정 계통) 전략기획형과 정보화계획형. 기본계획, 중장기 전략, 발전전략, 정보화전략계획처럼 계획을 세우는 과업이 해당. 발주처가 통제할 수 없는 환경에서 발주처가 통제하는 영역으로 좁혀 들어간 뒤 목표와 처방으로 나아감. 단계는 거시환경, 미시환경, 내부현황, 벤치마킹, 전략, 이행계획
    + (갭 분석 계통) 문제해결형을 비롯한 계통 표의 갭 분석 유형. 성과분석, 실태조사, 수요조사, 제도 개선 등이 해당. 현황 진단, 목표 대비 격차, 원인 구조화, 대안 설계의 순서로 나아감
    + (사업기획형) 갭 분석 계통을 바탕으로 목표체계를 더한 흐름. 환경과 역량 분석, 문제와 이슈, 목표체계와 논리모형, 사업 내용, 타당성 검토의 순서로 나아감
    + (복합 과업) 갭 분석의 결론으로 목표를 세우는 과업. 갭 분석 장들 뒤에 목표 설정 장들을 이어 붙임. 예시로 성과분석 뒤 발전전략, 타당성 조사 뒤 기본계획
- 포함할 단계는 보고서 목적으로 정함. 포함한 단계 사이의 순서는 유지. 인접하지 않은 단계로 건너뛰는 구성은 허용
- 앞 단계의 사실은 뒤 단계의 분석 초점을 좁힘. 예시로 정책 변화가 시장 요건으로, 시장 요건이 발주처의 역량 격차로 이어짐
- 기관현황 소개(연혁, 조직, 예산, 인력 등)는 환경 분석 앞에 둘 수 있음. 역량 진단(격차, 강점과 약점 등)은 환경 분석 뒤에 둠
- 처방(전략, 과제, 실행 등)은 분석 장 뒤의 처방 장에 둠. 처방의 근거는 앞 분석 장의 시사점
- 역순 점검은 실행 과제에서 전략, 전략에서 시사점, 시사점에서 분석 사실로 거슬러 올라감. 근거가 끊기는 장이나 절은 앞 장에 근거를 보충하거나 삭제

## 스토리라인 확정

- 02_스토리라인.md는 assets/report-storyline.md 양식으로 작성. 구성은 골격, 1줄 스토리라인, 장별 메시지, 목차 설계 표, 현장 조사 설계
- 골격은 보고서 전체의 흐름. 진단과 개선을 담으면 상황, 문제, 해소(SCR). 발주처의 결정을 요청하면 상황, 문제, 질문, 답(SCQA). 장별 메시지 표의 단 열로 장과 골격을 대응
- 판단문은 원고의 □ 제목으로 그대로 옮겨짐. SKILL.md 스토리라인 확정 절의 작성 규범(□ 제목의 문체, 단문과 명사형 종결, 줄 상한, 설계 언어는 병기 열에만 기재)을 적용
- 진단 절과 예비 진단 절의 판단문은 가설에서 도출한 예상 결론. 종결은 판정 문장 종결(-으로 나타남, -인 상황 등). 가설이 없는 절의 □ 제목은 원고 작성 절의 □ 제목 규칙을 적용
- 1줄 스토리라인과 장별 메시지는 발주처의 기대 성과로 끝나는 문장
- 제시 전에 아래 항목을 자체 점검. 어긋난 행은 수정 후 제시
    + 진단 질문마다 답하는 절이 목차 설계 표에 존재
    + 가설마다 지지 조건, 반증 조건, 분석 방법이 존재
    + 요구항목표 전 행의 배치 섹션 열 기입(`check rfp` PASS)
    + 장 순서가 장 순서 절의 흐름에 부합. 역순 점검에서 근거가 끊기는 장이 없음
    + 활용 설계의 설계 원칙마다 반영 절이 목차 설계 표에 존재
    + Module과 Task 명칭이 02_모듈총괄표.md와 동일
- 제시는 한 턴. 00_진단서.md, 02_모듈총괄표.md, 02_스토리라인.md를 파일 전달 기능으로 전달
    + 확인 요청 항목은 3개 이내. RFP 조정 내역이 있으면 확인 요청 항목에 포함
- 유저가 승인하면 02_스토리라인.md 상단 (승인) 줄에 일자와 범위를 기입. 3단계 착수 조건은 승인 기록
- 승인 이후의 변경
    + 자료 조사에서 가설이 기각되면 판단문을 자료에 맞게 수정. 반영 순서는 00_진단서.md 가설 표, 02_스토리라인.md, 원고. 수정한 판단문은 유저 재확인을 거침
    + 의미가 같은 표기 다듬기는 재량. 02_스토리라인.md에 같은 표기로 반영

## 원고 작성

- 원고는 장 1개당 파일 1개. 파일명은 `NN_장이름.md`(NN은 장 순번 두 자리). build는 파일명 순으로 합본
- 제목 표기는 `#` 장, `##` 절, `###` 항, `####` 가나다. 번호(제1장, 1.1, 1.1.1, 가.)는 조판기가 부여
- 캡션 표기는 표 `<표> 제목`, 그림 `![제목](경로)`. 장별 번호(<표 2-1>, [그림 2-1])는 조판기가 부여
    + 캡션 없는 표와 그림은 번호 집계와 표 목차, 그림 목차에서 빠짐
    + 표의 요지는 표 앞의 ❍가 서술
- 분석 절은 현황 사실, 비교와 해석, 시사점 순서로 구성. 시사점은 절 끝의 시사점 항(###)에 둠
- □ 제목의 문체는 항 단위로 정함(SKILL.md □ 제목의 문체 절). 동향, 현황, 목록 항은 키워드형. 시사점, 진단, 전략 항은 명사형 종결 판단문. 진단 절과 예비 진단 절은 절 전체를 판단문으로 씀
- 서술의 주어는 분석 대상과 결과
    + 판정 종결은 lexicon.md 종결 어휘의 판정 문장 종결(-으로 확인, -으로 집계, -으로 나타남, -인 상황 등)
    + 제안서의 수행 서술(-을 수행, -을 제시 등)과 제안서 전용 어휘(제안사, 수행 방안, 산출물 시안 등)는 쓰지 않음
- 작성 방식은 두 단계로 정함
    + 핵심 질문의 처방(전략, 과제, 개선안, 제언 등)을 담는 절은 방향(안) 절
    + 나머지 절 중 자료 유형이 현장인 가설을 가진 절은 예비 진단 절. 그 밖의 절은 진단 절
- 작성 방식별 구성
    + (진단 절) 공개 자료로 결론까지 서술. 본문 수치의 출처는 `[^n]` 각주. 표 수치의 출처는 표 아래 `자료:` 줄
    + (예비 진단 절) 공개 자료로 채울 수 있는 내용을 먼저 서술. 구성 순서는 공개 자료 분석 □, 예상 결론을 담은 시사점 □, 추가 확인 사항 □, 조사 계획 표. 절의 첫 줄은 `※ 공개 자료 기준 작성 (현장 조사 결과로 보완 예정)`
    + (방향(안) 절) 진단 결과의 시사점에서 방향을 도출. □ 제목 끝에 (안)을 붙임. 확정은 발주처 협의 이후
- 예비 진단 절은 현장 자료의 종류별로 공개 대체 자료를 사용
    + (내부 자료) 발주처의 공시와 공개 문서로 내부 현황을 추정. 공공기관 경영정보 공개시스템(알리오), 지방공기업 경영정보 공개시스템(클린아이), 예산서와 결산서, 성과보고서, 감사 결과와 의회 지적사항, 기관 홈페이지의 조직과 사업 현황 등이 해당. 추정치는 산출식과 기준 시점을 표 아래 ※ 줄에 명시
    + (설문) 국가승인통계와 같은 주제의 선행 조사 결과로 예상 분포를 제시. 이 분포는 현장 조사의 비교 기준. 문항 구조 초안(영역, 문항 수, 척도 등)을 조사 계획 표 아래에 제시
    + (면담) 국정감사 답변, 공청회 자료, 보도자료 등의 공개 발언으로 이해관계자의 입장을 정리. 면담 질문 초안을 조사 계획 표 아래에 제시
- 조사 계획 표의 열은 조사명, 대상, 표본, 방법, 시기, 확인 사항. 원천은 02_스토리라인.md 현장 조사 설계 표. 확인 사항 열에는 가설을 조사로 확인할 항목으로 바꿔 씀. 예시로 "지원 기업의 매출 변화 폭"
- 수치는 3년 이상의 시계열을 우선 사용. 시계열 수치에는 증감률을 병기
    + 합계와 구성비는 `check numbers`가 검산
    + 증감률 같은 파생 수치는 코드로 계산한 값만 기재
- 분량은 □ 1개에 ❍ 2개 이상과 근거 줄 2개 이상, 절마다 표나 그림 1개 이상. `check volume`이 □ 기준을 판정

## 독자 관점 서술

- SKILL.md 독자 관점 서술 절을 적용. 아래 규칙은 사전진단보고서 독자에 맞춘 보완
- (독자) 1차 독자는 발주처 담당자. 2차 독자는 00_진단서.md의 설득 대상(예산 당국, 상급 기관 등)
    + 담당자는 □와 표를 떼어 내부 보고와 예산 설명 자료에 옮겨 씀. 옮긴 자리에서도 읽히도록 수치에는 기준 시점을 함께 적음. 예시로 "2024년 결산 기준"
    + 수치와 지표는 발주처가 쓰는 단위와 명칭으로 표기. 예시로 회계연도, 예산 단위, 성과지표 명칭, 사업명 등
- (어조) 발주처를 가르치거나 훈계하거나 발주처의 조직을 비판하는 서술은 쓰지 않음. 담당자는 이런 문장을 자기 업무를 지적하는 문장으로 읽음
    + (가르침) 발주처의 소관 업무, 제도, 기본 개념을 설명하는 서술. 이미 아는 자기 현황(연혁, 조직, 사업 목록 등)은 설득 대상의 판단에 필요한 만큼만 요약. 분량은 새로 확인한 사실, 비교 결과, 격차의 크기에 둠
    + (훈계) "반드시 OO해야 함", "OO이 시급", "인식 전환 필요" 등 당위와 촉구의 서술. 필요한 조치는 근거와 함께 방향(안)으로 제시
    + (조직 비판) 발주처의 조직, 부서, 인력, 업무 방식을 평가하는 서술. 부족한 부분은 아래 격차 서술 규칙으로 씀
- (격차 서술) 부족한 부분의 서술 대상은 이용자와 수혜자가 겪는 불편, 여건(시설, 지역, 산업), 조건(제도, 사업 구성)
    + 이미 갖춘 기반과 거둔 성과를 먼저 적음. 부족한 부분은 환경 변화가 새로 요구하는 수준과 견주어 적음
    + "부족", "한계" 같은 판단어에는 비교 대상과 수치를 붙임. 근거는 통계, 비교 수치, 이해관계자 조사 결과 등. "그간 OO에 소홀", "형식적 운영" 같은 평가어는 `check tone`이 FAIL로 판정
    + 개선 방향은 보완, 확충, 강화, 연계 등 기반을 넓히는 표현으로 씀
- (보고서 어휘) 원고의 어휘는 발주처가 받아 보는 최종보고서의 어휘
    + 진단 설계의 용어는 원고에 쓰지 않음. 가설, 반증, 검증 가설, 예비 진단, 진단 결과, 지지 조건, 뿌리 질문, 이슈 트리 등이 해당. 현장 조사로 확인할 내용은 확인 사항, 분석한 내용은 분석 결과로 씀
    + 분석 기법의 전문용어(입지계수, 산업연관분석 등)는 처음 나온 자리 아래 ※ 줄에 뜻을 1줄로 부기
- (시사점) 분석 절의 시사점은 발주처가 정하거나 준비할 사항으로 씀
    + 방향(안) 절은 사전 협의에서 발주처가 정할 사항이 보이게 씀. 선택지가 있으면 대안과 선택 기준을 함께 제시
    + 방향(안)의 효과는 주민, 기업, 이용자 등 사업 수혜자에게 일어나는 변화로 서술

## 점검

- `check all`의 보고서 대상은 요구항목 배치, 분량 구성(전 원고), 어조와 어휘, 수치 검산, 확인 표지 잔여(경고만)
- 어조 판정은 02_모듈총괄표.md의 Module과 Task 명칭, 00_진단서.md RFP 용어 표의 용어를 판정에서 제외. 화이트리스트 고정 절차는 없음
    + 과업 대상 업무의 실제 용어가 어조 판정에 걸리면(R&D 평가 과업의 평가위원, 과제 RFP 등) RFP 용어 표에 원문 표기로 추가
- `[확인]` 잔여는 5단계에 위치 목록을 한 턴에 묶어 유저에게 질의. 값을 받으면 기입. 받지 못한 자리는 유저 승인 후 문장이나 행을 삭제
- 자체 검토와 렌더링 검수 기록은 05_점검기록.md의 `## 수동 기록` 절 아래에 둠
- 자체 검토는 1회. 항목은 SKILL.md 심층 검토 절의 수치 무결성, 출처 신뢰도, 논리 비약, 독자 관점, 괄호 소제목과 아래 2개 항목
    + (가설 대응) 원고의 □ 결론이 03_자료대장.md의 판정과 일치. 기각된 가설의 판단문은 수정본으로 교체
    + (내부 어휘) 원고가 독자 관점 서술 절의 보고서 어휘 규칙에 맞음. 골격의 단 이름, 결과물 요건, Q1과 H1 같은 번호도 점검 대상. 남은 자리에는 그 뜻을 실제 내용으로 서술. `check all`의 어조 판정은 이 어휘를 판정하지 않음

## 조판

- 명령은 `build 작업폴더 --format 형식 --toc --page-number --long-table 방식`. 표지는 착수 질의 답변에 따라 `--cover` 추가
- 목차, 쪽번호, 간지는 보고서의 기본 구성. 유저가 요청한 경우에만 해제
- 간지는 장마다 본문 앞에 들어가는 쪽. 간지 쪽에는 장 번호와 장 제목만 둠. 본문은 다음 쪽의 첫 절부터 시작. 해제는 `--divider off`
- 목차 뒤에 표 목차와 그림 목차가 새 쪽으로 이어짐. 수록 대상은 캡션이 있는 표와 그림
- 장 제목은 "제N장" 밴드. 절 1.1, 항 1.1.1, 목 가.
- 산출 파일은 납품/사전진단보고서.hwpx와 .docx
- 부분 산출은 `--chapter-start N`으로 전체 목차 기준의 장 번호를 유지. 캡션 번호도 같은 장 번호로 시작
- 모듈총괄표 삽입은 선택. 과업 개요 장의 수행 방법 절에 `(삽입: 모듈총괄표)` 줄을 1회 두면 그 위치에 배치
- 목차 쪽번호는 렌더링 기준의 근사값. build 로그의 `목차 쪽번호 n/m건 기입`에서 m 전부가 기입되었는지 확인
    + 누락이 있어도 목차는 유지(보고서의 기본 구성). 누락 항목을 최종 보고에 기재. hwpx는 한/글의 차례 새로 고침, docx는 Word에서 쪽번호 기입이 필요함을 함께 안내
- 보고서 명칭은 표지(`--cover`)에 들어감. 표지를 쓰지 않으면 산출 경로의 파일명으로 반영(`build 작업폴더 납품/보고서명.hwpx`)
