# 오리지널 파트 내용 모델

- 읽는 시점과 범위는 SKILL.md 서두의 참조 파일 표. 3단계에는 파일 1개를 쓸 때 해당 절만 읽음
- 모든 모델의 원천은 세로형 정성제안서에서 널리 쓰이는 구성

## 분량 구성 단위

- 분량은 구성 단위의 수로 정함. 아래 구성 단위를 채우면 통상의 제안서 분량에 도달

| 단위 | 하한 구성 | 채움 방법 |
|------|-----------|-----------|
| □ 논점 | ❍ 2개, 근거 줄(하이픈 또는 ※) 2개, 글자 350자 | 주장을 원인과 결과로 나눔. 근거에 수치, 자료명, 사례를 각각 1줄씩 배치 |
| 배경 절 | □ 3-5개(5개는 항으로 묶음), 표 또는 그림 2개 이상 | 상위계획 인용표, 현황 통계표, 시범사업 현황표, 제도 연혁표 중 택함 |
| 특장점 절 | 역량 주장 □ 3-4개, 실적 표 3개 이상 | 주장마다 실명 과업 목록 표를 1개씩 배치 |
| 추진전략 절 | 전략 □ 3-4개, 뒷받침 표 또는 그림 2개 이상 | 방식의 견본. 단계별 수행표, 품질 지표표, 사용 장면 시나리오표, 분과 구성표, 수행 절차표, 진단 기준표 중 택함 |
| Task | 표 또는 그림 1개 이상, 본문 900자 이상 | 분석 대상 실명 목록, 사전조사 채움본, 비교 매트릭스, 진단 항목표 |

- `check volume`은 □ 논점과 Task 행의 하한을 판정. □ 아래 ❍ 부족과 Task의 표 부재는 FAIL. 근거 줄 수와 글자 수는 경고
- 배경, 특장점, 추진전략 절 단위의 하한은 코드 판정 밖. 파일을 완결할 때 직접 확인
- 하한과 상한의 원천은 scripts/proposal.py 설정부 상수(VOLUME_*, SQUARE_TITLE_MAX, LINE_MAX). 문서의 값과 어긋나면 설정부가 기준
- 계위별 줄 상한은 아래 표. □와 ※는 조판 기준 1줄. ❍, 하이픈, ․는 2줄 이내. 값은 공백 포함 글자 수(rhwp 렌더링으로 확인한 값. 어절 길이에 따라 2-3자 변동)

| 계위 | 줄 수 | 상한 |
|------|-------|------|
| □ | 1줄 | 40자 |
| ※ | 1줄 | 50자 |
| ❍ | 2줄 | 86자 |
| 하이픈 | 2줄 | 84자 |
| ․ | 2줄 | 82자 |

- `check volume`이 상한 초과를 경고. 초과 문장의 해소 방법은 분할 후 하위 계위 추가 또는 표 전환
- 하한 미달 시 아래 순서로 단위를 추가
    1. 근거 줄 추가 (수치 1줄, 자료명 1줄, 사례 1줄)
    2. ※ 주석 추가 (용어 정의, 출처 시점, 산정 기준)
    3. 표 추가 (사전조사 결과, 대상 목록, 기준표)
    4. □ 분할 (원인 □와 결과 □로 분리)

## 배경 및 필요성

- 배경 및 필요성은 WHY의 절. 절의 역할, 골격(SCQA 또는 SCR), 거시환경에서 발주처 내부로 좁히는 순서는 SKILL.md 배경 골격 절
- 배경의 □는 문장형 판단문. 예시로 `□ 정부는 [상위계획명]으로 디지털 트윈을 인프라 관리의 표준 수단으로 지정`
- ❍는 □ 판단문을 구성하는 사실 1개. 상위계획 명칭, 제도 명칭, 통계 수치를 실명으로 기재. 한 항목의 길이는 분량 구성 단위 절 줄 상한 표의 ❍ 상한 이내
- 하이픈은 ❍의 근거. 수치의 기준 시점과 출처 기관을 함께 적음
- ※는 용어 정의, 출처 시점, 산정 기준. 심사위원이 의문을 가질 지점을 미리 해소
- 표와 그림은 □마다 1개를 권장. 인용 자료의 원표 발췌 후 출처 행을 붙임
- 이면 니즈 가설은 C 단에 배치. 발주처가 겪는 문제의 규모를 수치나 지적 건수로 특정

### 배경 □ 예시

```
□ 시설 관리 데이터의 부서별 분산으로 통합 조회가 제한
- 시설관리부의 2차원 도면 관리시스템과 안전점검부의 점검 이력 데이터베이스는 부서별로 개별 운영
    + 두 시스템의 시설 식별자 체계 차이로 동일 시설의 점검 이력과 도면의 동시 조회가 제한
    + 도면 관리시스템은 [연도] 구축 당시의 좌표 체계를 유지하여 GIS 포털과 위치 정합이 불가
- [연도] 내부 감사는 점검 이력 누락 사례 [N]건에 대해 데이터 연계 방안 마련을 요구[^2]
    + 지적 사례의 [N]%는 도면과 점검 이력의 시설 식별자 불일치에서 발생
    + 감사 지적 사항은 [연도] 업무계획의 데이터 연계 과제로 반영
※ 감사 지적 건수는 [기관명] 제공 자료 기준 (착수 후 원본 대조 예정)
```

## 제안 범위 (과업 목적 및 목표)

- 제안 범위 절(32)의 첫 □는 과업 목적 및 목표. 두 항목은 ❍ 1개씩으로 분리. 각 ❍는 문장 1개
- (목적 ❍) RFP의 과업 목적 문장을 원문 워딩으로 가져옴. 여러 문장이면 핵심 명사구 중심으로 ❍ 1개(줄 상한 표의 ❍ 상한 이내)에 압축. "본 과업은", "본 연구는" 같은 자기 지시는 제거. 첫머리는 목적 내용으로 시작
    + 하이픈은 목적의 세부 내용, 근거, 기준 중 해당하는 항목. 세부 내용은 RFP 목적 문장에 딸린 하위 항목의 원문. 근거는 RFP 배경 문장의 사정(상위계획 조항, 제도 시행 시기, 지적사항)과 목적이 답하는 문제. 기준은 목적을 규정하는 조건(적용 대상, 범위, 부합해야 할 상위계획)
- (목표 ❍) RFP에 목표 문장이 있으면 원문 워딩으로 가져옴. 없으면 목적에서 도출
    + 하이픈은 세부 목표 또는 기준. 세부 목표는 목표를 구성하는 요소 1개씩. RFP 과업 세부내용의 상위 항목이 도출 재료. 기준은 목표의 도달 여부를 가르는 조건(반영해야 할 요구, 산출물의 확정 주체, 완료 시점)
    + RFP와 과업 내용에서 세부 목표가 도출되지 않으면 세부 목표를 만들지 않음. 기준만 적거나 하이픈 없이 ❍로 종결
    + 목표를 도출한 경우 `※ 목표는 과업 세부내용에서 정리` 부기
- 목적과 목표의 정의
    + 목적은 과업의 결과로 발주처가 이르려는 상위의 상태 또는 방향. 시간 범위와 분야는 RFP를 따름. "왜 하는가"의 답. 예시로 "행정업무와 대민 서비스의 AI 활용 확산", "지역 산업 구조의 고도화", "기관 경영 성과의 관리 역량 제고"
    + 목표는 과업 수행으로 달성하려는 결과. 연구와 기획 과업의 통상 목표는 과업 종료 시점까지 마치는 계획, 전략, 방안의 수립과 도출. "무엇을 어디까지 하는가"의 답. 예시로 "5개년 실행계획서 확정", "실증사업 추진계획 수립", "육성 전략 수립과 추진과제 발굴", "경영평가 등급 향상"
    + 목적은 하나. 목표는 목적에 이르는 도달점. 여러 개 가능
    + 목적과 목표는 각자의 ❍에 1회씩 둠. 수행 방법(조사, 분석, 협의)은 수행부문의 내용
- 목적, 목표, 세부 목표, 기준에 건수, 비율, 개수 같은 수치를 붙이지 않음
    + 허용하는 숫자는 계획 기간과 계획 명칭에 포함된 숫자. 예시로 "5개년 전략 수립", "2027-2031 종합계획 수립"
    + RFP 원문의 목적과 목표 문장에 포함된 수치는 원문 그대로 유지
    + 조사 규모와 산출물 수량은 수행부문의 Task 서술과 표에서 제시
- 서술 분량은 RFP가 제시한 내용의 분량을 따름. RFP의 목적과 목표가 각 1문장이면 ❍ 2개만으로 종결
- 이 절의 □에서 나오는 근거 줄 수와 글자 수 경고(`check volume`)는 해소 대상 밖
- 이어지는 □는 과업 범위. 범위의 구분마다 괄호 소제목을 단 ❍ 1개를 두는 구성을 권장
    + 구분은 RFP의 범위 서술에서 도출. 예시로 (공간적 범위), (시간적 범위), (내용적 범위)
    + 시간적 범위는 RFP를 따름. 통상 산출물이 적용되는 기간을 기재(중장기 전략이면 계획 기간)
    + 내용적 범위는 RFP 과업지시 항목을 원문 워딩으로 전부 포함. 누락은 01_요구항목표.md의 상위 항목 대조로 확인
    + 내용적 범위의 항목이 많으면 ❍ 아래 하이픈 1-3개로 나눔. 더 많으면 별도 □에서 과업 항목마다 ❍ 1개와 하이픈 1-3개로 전개
    + RFP가 명시한 제외 범위만 반영
- 절 전체가 정리 절. □는 키워드형

## 제안의 특징 및 장점

- 특장점은 통상 역량 주장 3-4개의 반복 구조. 주장마다 증거 표가 붙음. 절 분량은 통상 5-10쪽
- 역량 주장은 00_제안전략서.md의 차별화 포인트와 추진전략에서 도출
- 주장 예시 표는 문형 참고용

| 주장 예시 | □ 판단문 형태 | 증거 표 |
|-----------|---------------|---------|
| 연구책임자 전문성 | 연구책임자는 N년 경력의 학위 소지자로 분야 A 및 B의 전략기획 전문가 | 연구책임자 수행실적 표(과업명, 기간, 발주기관, 금액) |
| [기관명] 분야 실적 | 제안사는 최근 5년간 분야 A 과업 N건을 수행하여 제도와 자료 구조를 이해 | 분야별 실적 표(연도, 건수, 대표 과업) |
| 방법론 보유 | 제안사는 로드맵 수립 및 기술수준 조사의 방법론을 과업 N건에 적용 | 방법론별 실적 표 |
| 보유 도구와 자료 | 제안사는 특허 및 논문 분석 도구, 정책 문헌 DB, 기관 네트워크를 보유 | 도구 목록표, 자문 네트워크 표 |
| [기관명] 유사 과업 | 제안사는 [기관명] 유관 과업 N건으로 보고 체계 및 자료 접근 경로를 확보 | [기관명] 유관 실적 표 |

- 특장점은 WHAT의 절. 제안사의 보유 자산(방법론, 실적, 인력, 도구, 데이터)을 증거와 함께 서술. 추진전략 절과의 역할 구분은 SKILL.md 논증 절 구성 절

```
| 활용자료 | ◦ 시스템 구축 완료보고서 6건<br>◦ 데이터베이스 스키마 | ◦ 부서별 업무분장표<br>◦ 면담 질문지 3영역 24문항 |
| 산출물 | ◦ 시스템 현황표<br>◦ 데이터 항목 대응표 | 면담 결과 보고서 |
```

- Task는 밴드 아래에 라벨 ❍를 바로 둠. 라벨 세트는 methods.md 공통 표준 절의 유형별 세트. 채움본의 종류는 SKILL.md Task 서술 표준 절
- 채움본은 표가 뒷받침하는 라벨 아래에 배치. 표 앞에는 그 라벨 아래 하이픈 1개로 표의 결론을 먼저 서술. 이 결론 문장이 표를 읽는 관점을 제시
    + 예시로 `    + 사전조사 결과 데이터 유통 단계는 기관별 보유 수준의 편차가 가장 큼`
- 채움본이 뒷받침하는 라벨은 작성자가 Task의 읽는 흐름으로 정함
    + 대상을 특정하는 표(대상 실명 목록표)는 (분석 대상) 아래
    + 방법과 절차를 보여주는 표와 그림(문항 구조표, 진단 항목표, 기준표, 방법론 적용 예시)은 (분석 방법), 기준 라벨, (수행 절차) 아래
    + 결과의 모습을 미리 보여주는 표(사전조사 결과표, 비교 매트릭스, 산출물 시안)는 (산출물) 아래. 결론 하이픈의 첫머리는 "사전조사 결과", "시안 기준"처럼 표의 성격을 밝힘. 이 첫머리로 산출물의 구성 설명과 구별
    + 여러 라벨에 걸치는 표는 (산출물) 아래에 배치
- 비교 매트릭스의 열은 대상. 행은 단계나 항목. 셀은 ○ △ × 또는 ● ◐ ○ 중 한 세트로 채움. 범례를 표 아래 ※로 표기
- 기호 하나만 있는 셀은 셀 글머리 처리에서 제외. 해당 열은 가운데 정렬로 조판
- 사전조사 채움본은 웹검색 허용 시 공공 통계와 기관 공표 자료를 우선 기재. 값의 원천과 표 아래 부기는 SKILL.md Task 서술 표준 절
- 문헌과 자료 조사의 대상 실명 목록은 기관명, 자료명, 선정 사유의 3열. 대상 수는 실제 조사 가능한 범위로 특정

### Task 기본 서술 예시

```
Task 1-1. 시설 관리 시스템 실사

- (목적) 시스템별 기능과 데이터 항목의 중복과 공백을 확인하여 연계 대상 선정의 판단 자료를 확보
- (분석 대상) 시설 관리 업무에 쓰이는 시스템 6개와 각 시스템의 데이터베이스 스키마
- (분석 방법) 구축 완료보고서의 기능 목록과 운영 화면을 대조하여 현행 기능을 확정
- (산출물) 시스템 현황표, 데이터 항목 대응표
    + (시스템 현황표) 시스템별 구축 연도, 운영 부서, 기능 목록, 데이터 보유량으로 구성
    + (데이터 항목 대응표) 시설 식별자의 일치 여부를 판단 기준으로 작성
    + 두 산출물은 연계 과제 도출의 후보 목록 작성에 활용
```

- (산출물) 아래 첫 두 하이픈은 산출물별 구성의 나열. 괄호 소제목을 붙임. 셋째 하이픈은 두 산출물 전체의 활용처. 괄호 소제목 없이 묶음 끝에 둠
- (산출물) 줄의 서술 범위와 제출 시점의 기재 위치는 methods.md 공통 표준 절
