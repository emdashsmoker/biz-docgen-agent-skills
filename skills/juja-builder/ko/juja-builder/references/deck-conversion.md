# 발표자료 변환 경로

- 제안 발표자료(pptx, pdf)를 hwpx 정성제안서로 바꾸는 경로. 발표자료를 RFP와 같은 방식으로 다룸
    + 스크립트는 형식 변환만 담당. 추출과 판단은 원문 전문을 읽은 모델이 수행
    + 절차는 파싱, 원문 읽기, 제안전략서와 스토리라인으로 이관, RFP와 대조, 원고 작성. 일반 경로의 단계, 작성 규범, 점검, 조판은 그대로 적용
- 발표자료는 논지 중심의 문서. 제안서의 구성 단위(❍, 근거 줄, 표)는 원고 작성 단계에서 보강. 슬라이드 문장을 계위에 옮겨 적기만 한 원고는 `check volume`과 `check density`에서 FAIL

## 파싱

```bash
python3 <SKILL>/scripts/proposal.py init 작업폴더
python3 <SKILL>/scripts/proposal.py rfp RFP파일 작업폴더      # RFP 동반 제출 권장. 없으면 RFP 대조 절
python3 <SKILL>/scripts/proposal.py deck 발표자료 작업폴더
```

- 처리 경로는 PDF 하나. pptx는 LibreOffice에서 PDF 변환 후 처리. 본문과 표의 추출, 내장 이미지 추출, 도식 캡처는 전부 그 PDF에서 수행
- 산출은 작업폴더의 `발표자료/`. 원문.md(쪽별 본문과 표), sheets/(쪽 축소판 모음), pages/(쪽 PNG), img/(내장 이미지), 발표자료.pdf(기준본)
- pptx와 pdf를 둘 다 받으면 pptx를 입력으로 사용. pptx 변환본은 본문의 띄어쓰기가 유지됨. PowerPoint에서 저장한 PDF는 도식 캡처의 예비 원천으로 보관
- stdout 경고의 처리

| 경고 | 의미 | 처리 |
|---|---|---|
| 텍스트 레이어 불완전, 중단 | 용량 압축이나 재저장을 거친 PDF. 본문이 다른 음절로 추출됨 | 작업 중단 후 경고 문구를 유저에게 전달. pptx 원본이나 압축 전 PDF를 요청 |
| 공백 누락 쪽 | 띄어쓰기만 빠진 쪽(글자는 정상) | 띄어쓰기를 복원하여 이관 |
| 내용이 빈 쪽 | 내용 없이 서식만 있는 쪽. 작성 중인 자료 | 착수 질의에 쪽 번호를 묶어 확인 |
| 이 환경에 없는 글꼴 | 대체 글꼴로 변환됨. 본문 추출과 무관 | 도식 캡처 결과에서 글자 넘침만 확인 |

- `--allow-garbled`의 사용 조건은 유저의 원본 미보유 답변과 쪽 PNG 판독 진행 동의. 이 경우 기준 자료는 쪽 PNG. 원문.md는 보조 자료. OCR은 슬라이드 배치에서 품질이 낮음. 사용하지 않음

## 원문 읽기

- 발표자료/원문.md 전문을 01_RFP원문.md와 같은 방식으로 읽음. 도식이 많은 자료는 sheets/의 축소판 모음을 함께 확인
- 쪽 PNG는 필요한 쪽만 열람. 대상은 도식 후보, 문장이 끊긴 쪽, 표가 깨진 쪽, `이미지 쪽`(표를 그림으로 붙인 내용 쪽일 수 있음)
- 원문.md의 추정 유형은 참고값. 머리글, 바닥글, 쪽 번호는 제거된 상태

## 이관

- 착수 질의에서 발표자료로 확인되는 항목(컨소시엄, 인력, 자문위원회)은 값 제시 후 확정만 받음. 발표자료 작성 이후 바뀐 사항의 갱신 여부를 함께 질의
- 제안전략서, 모듈총괄표, 스토리라인의 내용은 발표자료에서 이관. 새로 작성하는 범위는 발표자료에 없는 필드

| 발표자료 요소 | 이관 파일 |
|---|---|
| 쪽 상단의 헤드라인 문장 | 02_스토리라인.md 논점 판단문 (명사형 종결로 전환) |
| 배경, 추진전략, 특장점 쪽 | 00_제안전략서.md의 발주처 니즈, 제안 전략, 차별화 포인트와 스토리라인의 해당 표 |
| 수행 절차도, 모듈별 세부활동과 산출물 표 | 02_모듈총괄표.md (명칭 유지, 번호 표기는 Module과 Task로 통일) |
| 제안사 현황, 실적, 인력, 자문위원 후보, 일정, 보고, 보안 쪽 | 회사자료.md와 공통 파트 치환값 |
| 예시와 시안 표기가 붙은 쪽 | 해당 Task의 채움본 표 |

- 발표자료에 없는 필드(이면 니즈 가설, 핵심 워딩 사전, 배경의 일부 단)는 모델이 기입한 안에 `[보강]`을 표시. 2단계 승인 요청에서 확인 항목으로 안내. 승인 뒤 표지를 지움
- 표지, 목차, 간지, 맺음 쪽은 옮기지 않음. 그 외 옮기지 않은 내용 쪽이 있으면 2단계 승인 요청에 쪽 번호와 사유를 1줄로 보고

## RFP 대조

- RFP 해부(1단계)는 일반 경로와 같이 RFP 원문에서 수행. 발표자료의 요구사항 대응 쪽은 배치 섹션 열의 참고 자료
- 장 구성은 RFP 지정 목차가 우선. 발표자료의 Module과 Task는 요구항목표와 대조. 빠진 요구항목이 있으면 Task를 보강. `check rfp`가 판정
- 발표자료 문장의 용어가 RFP 워딩과 다르면 RFP 표기로 통일
- RFP 동반 제출을 권장. 빠진 요구항목의 보강, 배점에 따른 분량 배분, 워딩 대조는 RFP가 있을 때 가능. RFP가 없으면 착수 질의에 묶어 제출을 1회 권함. 이후 진행은 유저 결정을 따름
- RFP 없이 진행하는 경우
    + `rfp 발표자료/원문.md 작업폴더`로 빈 표를 배치(01_RFP원문.md에는 발표자료 본문이 들어감)
    + 01_요구항목표.md는 발표자료의 과업 범위 쪽, 요구사항 대응 쪽, 모듈별 세부활동에서 이관. 비고 열에 `발표자료 기준`을 기입
    + 01_배점표.md는 발표자료에 표기된 평가항목에서 이관. 배점을 알 수 없는 항목은 배점 열에 0을 기입(빈칸은 집계에서 제외). 통제배점이 0이 됨. 심층 검토 강도는 수행부문과 논증 절을 10점 이상으로 간주
    + 핵심 워딩 사전은 발표자료의 과업명, 세부 과업 명칭, 산출물 명칭으로 작성
    + 장 구성은 발표자료의 목차를 따름. 유저가 나중에 RFP를 제출하면 1단계부터 다시 수행
    + 요구항목 누락 대조, 배점 비중 판단, RFP 워딩 대조를 수행하지 못한 한계를 최종 보고에 1줄 기재

## 원고 작성

- 헤드라인은 승인된 □ 판단문, 불릿은 ❍ 주장의 요지. 근거 줄과 표는 발표자료의 다른 쪽, RFP, 회사자료.md, 유저 제출 문헌, 웹검색(허용 시) 순으로 보강
- 발표자료의 표는 표로 재구성. 일정표는 추진일정표 규범으로, 조직도는 참여인력 표와 업무분장 표로 재구성
- 발표자료의 관용 표현은 원고 규범으로 전환. 대상은 경어체 종결, 숫자 선언, 화살표와 슬래시 연결, 방법론 명칭 나열, 대비 도식, 형용사 강점, 기호 불릿. `check tone`이 판정
- 발표자료의 수치는 출처 확인 후 이관. 출처 없는 효과 수치와 예시 표의 가상 값은 확인된 값으로 교체, 시안 부기, `[확인]` 표기 후 5단계 질의 중 1개로 처리
- 제안사 자체 수치(업력, 실적, 인력)는 회사자료.md와 대조. 값이 다르면 유저에게 질의

## 그림 선별

- 그림의 원천은 내장 이미지와 쪽 캡처. 사진, 로고, 지도, 차트 이미지는 `deck`이 추출한 내장 이미지(`발표자료/img/`와 manifest.json). 도형과 글상자로 그린 도식은 쪽 캡처(`figure`)
- 선별 기준과 유저 확인 절차는 SKILL.md 원본 이미지 재사용 절을 그대로 적용. 모델은 manifest와 축소판 모음을 근거로 후보 목록(파일 또는 쪽, 유형, 삽입 위치, 캡션안)을 작성. 이 목록은 2단계 승인 요청에 포함. 유저가 채택한 항목만 삽입
- 같은 그림이 내장 이미지와 쪽 캡처 양쪽에 있으면 내장 이미지를 우선. 원본 해상도가 유지됨. 내장 이미지가 조각으로 나뉘어 있으면 쪽 캡처를 사용

### 도식 캡처

```bash
python3 <SKILL>/scripts/proposal.py figure 작업폴더 쪽 --grid
python3 <SKILL>/scripts/proposal.py figure 작업폴더 쪽 --crop 좌,상,우,하 --name 이름
```

- 도형과 글상자로 그린 도식은 내장 이미지로 추출되지 않음. 기준본 PDF의 해당 영역을 캡처
- 그림 후보는 관계와 흐름이 핵심인 도식(절차도, 체계도, 개념도)과 차트, 지도, 사진. 단순 나열 도식과 타 기관 로고 모음은 표로 재구성
- `--crop` 값은 쪽 크기 기준 백분율. 쪽 전체 캡처에는 슬라이드 제목 띠와 바닥글이 포함됨. 도식 영역만 지정. 값은 `--grid`가 만든 눈금 PNG에서 읽음
- 삽입 전에 캡처 결과의 잘린 도형, 남은 헤드라인, 글자 넘침을 확인. pptx 변환본에서 글자가 넘치면 PowerPoint 저장 PDF로 같은 쪽을 캡처(`--pdf 경로`)
- 삽입은 `![캡션](../발표자료/figures/파일명.png)`. 도식 앞에는 도식의 요지를 담은 ❍ 1개를 배치. build stdout에 `WARN: 이미지 없음`이 나오면 경로 오류
- 도식 안의 문장은 `check wording`의 판정 대상 밖. 핵심 워딩은 ❍ 서술에도 포함
- 글자가 작은 도식은 렌더링 PNG에서 판독 가능 여부를 확인. 어려우면 표로 재구성하거나 두 영역으로 나눠 캡처

## 실패 패턴

- (슬라이드 전사) 슬라이드 문장만 계위에 옮겨 적음. 구성 단위가 빈 원고는 분량과 밀도 판정에서 FAIL. 근거 줄과 표를 보강
- (도식 남용) 쪽 전체를 통째로 삽입. 표로 재구성할 쪽까지 그림으로 삽입. 그림은 유저가 채택한 도식만 삽입. `--crop`으로 도식 영역만 캡처
- (압축 PDF 강행) 본문이 다른 음절로 추출되는 PDF를 유저 확인 없이 `--allow-garbled`로 진행. 중단 문구 전달 후 원본을 요청
- (예시 수치의 확정치화) 예시 쪽의 가상 값과 출처 없는 수치를 본문 근거로 사용. 확인된 값으로 교체하거나 시안 부기 또는 `[확인]` 표기로 전환
- (발표자료 구조 우선) RFP 지정 목차와 다른 발표자료 장 구성을 그대로 사용. RFP 지정 목차를 우선 적용
