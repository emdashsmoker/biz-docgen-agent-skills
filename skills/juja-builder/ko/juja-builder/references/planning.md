# 기획보고서 작성 경로

- RFP 없이 유저가 정한 주제와 자료로 기획보고서를 작성하는 경로
- (목적) 결과물을 이용할 사람의 필요에서 출발하여 무엇을 어떻게 할지 실행 전에 정하는 문서
- 간단한 형식 예시는 기획의 판단 재료나 결과를 보고 대상에게 전달하는 문서
- 모든 기획은 목표 설정 계통, 갭 분석 계통, 두 계통의 결합 중 하나로 설계. 판정과 적용은 설계 계통 절
- 문서 규격은 기획 유형 예시와 간단한 형식 예시를 참고하여 설계. 예시에 없는 유형도 같은 절차로 설계
    + (기획 유형 예시) 전략기획, 사업기획, 행사기획, 과제카드 등
    + (간단한 형식 예시) 요약보고서, 이슈리포트, 브리핑자료, 가이드라인과 매뉴얼 등
- 설계 순서는 기획 설계(결정 사항, 문제 진술, 계통, 경쟁 구도, 골격, 스토리라인), 목차, 원고
- 제안서 경로의 방법론(배경 골격, 과업 유형별 모듈 골격, 추진일정표, 회의체 설계)과 작성 규범, 조판을 그대로 사용
- 계위와 번호는 제안서와 같음(Ⅰ., 1., 가., 1), □, ○, -). 문서 첫 줄에 문서 제목을 둠
- 분량은 유저가 정함. 유저가 정하지 않으면 모델이 주제의 범위와 입력 자료의 양으로 분량을 설계하여 1단계 승인 요청에 제시

## SKILL.md 적용 범위

| 구분 | SKILL.md 절 |
|---|---|
| 그대로 적용 | 이용 안내, 대화 응답, 준비, 배경 골격, 원고 계위, □ 제목의 문체, 괄호 소제목, 회의체, 추진일정표, 독자 관점 서술, 자기완결 서술, 문장 규율, 원본 이미지 재사용, 조판, 렌더링 검수 |
| planning.md로 대체 | 절차, 제안전략서와 스토리라인 확정(기획 설계), 장 구성, 분량 구성 단위, 점검 대상 |
| 적용하지 않음 | RFP 해부, 섹션대장, 공통 파트, Task 서술 표준, 심층 검토의 통제배점 기준 |

- 독자 관점 서술 절의 발주처는 보고 대상으로 바꿔 적용. 보고 대상이 없으면 결과물 이용자로 바꿔 적용
- 과업 유형별 모듈 골격은 전략기획과 사업기획의 장 구성 참고로 사용. 분석 모듈의 결과는 현황 장, 전략 도출 모듈의 결과는 전략 장에 배치

## 설계 계통

- 두 계통의 사고 순서는 references/methods.md 서두의 계통 표를 따름
    + (목표 설정 계통) 전략기획 방법론. 도달할 상태의 정의에서 출발하여 과제와 실행 계획을 하향 전개
    + (갭 분석 계통) 문제해결 방법론. 현행 상태의 규명에서 출발하여 격차의 원인을 해소할 대안을 설계
    + (결합) 한 문서에서 두 계통을 이어 씀. 앞 계통의 결론이 뒤 계통의 전제. 장 순서는 references/report.md 장 순서 절의 사업기획형과 복합 과업
- 계통은 00_기획설계.md의 문제 진술로 판정
    + 기획이 도달 상태를 새로 정해야 하면 목표 설정 계통. 예시로 신규 사업, 비전 수립, 행사 등
    + 현행이 주어진 도달 상태에 미치지 못하는 원인을 찾아야 하면 갭 분석 계통. 예시로 운영 개선, 성과 부진 대응, 제도 보완 등
    + 두 판정이 함께 나오면 결합
- 장 구성은 판정한 계통의 사고 순서마다 장이나 절을 대응하여 설계. 단계의 통합과 생략은 분량과 입력 자료에 맞춰 모델이 판단
- 기획 유형 예시는 계통이 문서 규격으로 드러난 사례. 예시 밖의 요청은 계통으로 장을 설계. 설계한 장 구성의 누락은 가까운 예시의 장 구성과 핵심 표로 대조
- 간단한 형식이 제언, 과제, 계획을 담으면 그 장의 근거는 계통의 사고 순서로 세움

## 기획 유형 예시

- 기획 유형별 장 구성과 핵심 표의 예시. 장의 추가, 통합, 생략과 장 이름 조정은 주제와 스토리라인에 맞춰 모델이 설계

| 유형 | 계통 | 장 구성 | 핵심 표 |
|---|---|---|---|
| 전략기획 | 목표 설정 | 추진 배경 → 현황 진단 → 비전과 추진 전략 → 추진 과제 → 추진 체계와 일정 → 기대 효과 | 현황 진단표, 전략 체계표, 과제 목록표, 로드맵 |
| 사업기획 | 결합(갭 분석에 목표체계 추가) | 추진 배경 → 현황 분석 → 사업 추진 타당성 → 사업 내용 → 추진 체계와 절차 → 소요 예산 → 성과관리와 기대 효과 | 사업 개요표, 기존 사업 대비 차별성 비교표, 지원 분야표, 추진 체계도, 예산 산출표, 성과지표표 |
| 행사기획 | 목표 설정 | 행사 개요 → 추진 목적 → 세부 프로그램 → 운영 계획 → 소요 예산 → 향후 일정 | 행사 개요표, 프로그램표, 역할 분담표, 예산표 |
| 과제카드 | 두 계통의 마지막 단계(하향 전개, 대안 설계) | 과제 목록 → 과제별 카드 | 과제 목록표, 과제별 성과 지표표와 소요 예산표 |

- 추진 배경 장과 추진 필요성 장은 SKILL.md 배경 골격 절의 골격을 적용
- 사업기획의 구성
    + (현황 분석) 외부 환경과 내부 역량으로 나눔. 국외와 국내는 외부 환경 안의 하위 구분
    + (사업 추진 타당성) 공공 사업은 시급성, 정부지원 필요성, 기존 사업과의 차별성, 지원 근거와 추진 경위 등. 민간 사업은 시급성, 시장성, 수익성, 경쟁 우위 등
    + (성과관리와 기대 효과) 성과목표, 성과지표와 목표치, 성과지표 간 논리모형, 성과 관리와 확산 방안, 기대 효과
- 행사 개요표의 행은 일시, 장소, 대상, 규모, 주최, 주관 등. 프로그램표의 열은 시간, 내용, 담당, 비고
- 예산표는 비목, 산출 근거, 금액 열로 구성. 합계 행은 `check numbers`가 검산

## 간단한 형식 예시

- 보고 상황에 맞춘 문서 규격의 예시. 장 구성은 주제에 맞게 조정

| 형식 | 계통 | 장 구성 | 핵심 표 |
|---|---|---|---|
| 요약보고서 | 원 보고서의 계통을 따름 | 원 보고서의 장 순서를 유지. 장마다 첫 □에 그 장의 결론 | 원 보고서의 표 중 결론 도출에 쓰인 표 |
| 이슈리포트 | 목표 설정 계통의 앞 단계(환경 분석, 방향 제시) | 이슈 배경(작성 배경, 정의와 범위) → 동향(정책, 기술, 시장과 산업, 투자 등 주제에 맞는 항목) → 전망과 과제 → 시사점과 제언 → 참고문헌 | 주요국 비교표, 시장 전망표, 주요 기업 현황표 |
| 브리핑자료 | 추진 중인 기획의 계통을 따름 | 보고 요지 → 추진 경과 → 주요 내용 → 향후 계획 → 건의 사항 | 추진 경과표, 향후 일정표 |
| 가이드라인과 매뉴얼 | 두 계통의 마지막 단계(실행 방법) | 개요(배경, 목적과 적용 범위, 구성) → 기본 개념과 사례 → 원칙과 유의 사항 → 절차나 업무별 적용 방안 → 체크리스트 → 부록 | 용어 정의표, 절차표, 업무별 적용표, 체크리스트 |

- 요약보고서의 수치와 결론은 원 보고서의 값을 그대로 사용. 원 보고서는 입력 자료로 받음
- 이슈리포트의 동향 장은 항목마다 국외 뒤에 국내를 서술. 시사점과 제언 장은 동향 장에서 확인한 사실로 도출
- 브리핑자료의 건의 사항은 보고 대상이 결정할 사항을 □마다 1건씩 기재
- 가이드라인과 매뉴얼의 절차 장은 단계마다 □ 1개. □ 제목은 단계명
    + 절차표의 열은 단계, 담당, 처리 내용, 서식
    + 용어 정의표의 열은 용어, 정의, 근거 규정
    + 체크리스트의 열은 확인 항목, 확인 기준, 해당 단계

## 과제카드 형식

- 과제카드는 과제 1개의 추진 계획을 □ 단위로 서술하는 예시 양식. 모든 주제의 해법이 될 수 없음
- 적용 대상은 유저가 과제카드, 과제정의서, 과제별 추진계획을 요청한 문서
- 요청이 없는 문서에서 과제카드가 맞다고 판단되면 1단계 승인 요청에서 유저에게 사용 여부를 질의. 유저가 승인한 경우에만 사용
- 과제 제목의 계위는 문서 구조로 정함
    + 추진 과제 장에서 전략별로 과제를 묶으면 전략은 절(##), 과제는 항(###)
    + 과제카드 문서는 과제 1개를 절(##)로 둠
    + 과제 번호는 과제 목록표에 기재. 헤더 번호는 build가 부여
- 과제 제목 아래 □의 기본 구성과 순서. 과제 성격에 맞게 □를 추가, 통합, 생략
    + (과제 개요) 과제 목표와 추진 기간. (목표)와 (기간) 괄호 소제목으로 구분
    + (추진 근거) 상위 계획, 법령, 조례의 해당 조항
    + (추진 배경) 현행 상태와 과제가 해소할 문제. 수치는 근거 줄에 출처와 함께 기재
    + (주요 내용) 과제의 세부 활동. ❍마다 활동명을 괄호 소제목으로 붙임. 세부 항목은 근거 줄로 기재
    + (추진 체계) 주관 기관과 참여 기관의 기관명. (주관)과 (참여) 괄호 소제목 뒤에 기관명을 쉼표로 구분하여 나열
    + (기대 효과) 과제 수혜자에게 일어나는 변화. 서술 규칙은 독자 관점 서술 절의 (성과 서술)
    + (성과 지표) 성과지표와 연도별 목표치의 표
    + (소요 예산) 재원별 연도별 예산의 표. 표 앞 요지 ❍는 총액 뒤 괄호에 재원별 금액을 쉼표로 구분하여 나열
- □ 제목은 구성 항목의 괄호 안 명칭인 키워드형 명사구. 과제카드가 여러 개면 □의 구성과 순서를 과제 간 통일
- 과제 1개의 □ 수는 구성 항목 수를 따름. 과제카드 절과 항에서 나오는 `check volume`의 □ 개수 경고(상한 4)는 해소 대상 밖
- 주요 내용의 활동이 5개 이상이면 활동 묶음마다 □ 1개를 두고 묶음명을 □ 제목으로 씀
- 표는 □ 아래 요지 ❍ 뒤에 배치. 규칙은 SKILL.md □ 제목의 문체 절
    + 성과 지표 표의 열은 성과지표, 단위, 연도별 목표치
    + 소요 예산 표는 재원(국비, 지방비, 민자 등)을 행, 연도와 합계를 열로 둠. 합계는 `check numbers`가 검산
- 과제카드 앞에는 과제 목록표(과제 번호, 과제명, 추진 주체, 추진 기간 등)를 둠

```markdown
### 해외 공동 전시관 운영

□ 과제 개요
- (목표) 지역 수출 기업의 해외 판로 확대를 위한 연 2회 공동 전시관 운영
- (기간) 2027년부터 2029년까지 3년간 추진

□ 추진 배경
- 지역 수출 기업은 해외 전시 참가비를 기업마다 개별 부담
    + 참가비는 부스 임차비, 장치비, 현지 홍보비로 구성
- 공동 참가 방식은 부스 임차비, 장치비, 현지 홍보비를 참가 기업 간에 분담

□ 주요 내용
- (참가 기업 선정) 수출 실적과 제품 경쟁력을 기준으로 참가 기업 선정
- (전시관 운영) 공동 부스 설계와 현지 바이어 초청 상담회 운영
    + 상담회는 전시 기간 중 1일 이상 편성
- (사후 관리) 상담 건의 계약 전환 여부를 전시 종료 후 6개월간 추적

□ 추진 체계
- (주관) 지역 수출지원센터
- (참여) 현지 협력 기관, 무역 통역 지원 기관

□ 소요 예산
- 총 6억 원(국비 4억 원, 지방비 2억 원)

<표> 연도별 소요 예산
(단위: 억 원)

| 구분 | 2027년 | 2028년 | 2029년 | 합계 |
|---|---|---|---|---|
| 국비 | 1.0 | 1.5 | 1.5 | 4.0 |
| 지방비 | 0.5 | 0.5 | 1.0 | 2.0 |
| 합계 | 1.5 | 2.0 | 2.5 | 6.0 |
```

## 기획 설계

- 00_기획설계.md는 제안서 경로의 제안전략서와 스토리라인, 사전진단보고서 경로의 진단서와 스토리라인에 대응
- 작성 순서는 결정 사항, 문제 진술, 계통, 경쟁 구도, 골격, 스토리라인, 목차
- (결정 사항) 보고 대상이 문서를 읽고 내릴 결정과 그 결정에 필요한 근거. 이 근거가 장 구성과 핵심 표를 정함
- (문제 진술) references/report.md 진단 설계 절의 문제 진술 규칙을 적용
- (계통) 설계 계통 절의 판정 기준으로 목표 설정, 갭 분석, 결합 중 1개를 정함. 판정 근거 1줄을 병기
- (경쟁 구도) 문서 주체나 대상 사업이 한정된 재원을 두고 다른 주체와 겨루면 작성. 민간기업의 사업 계획, 기술사업화 계획, 국비 공모 대응 계획 등이 해당. 작성 규칙은 references/report.md 진단 설계 절의 경쟁 구도 항목. 경쟁 우위와 열위는 장별 메시지와 □ 판단문으로 세움
- (골격) 문서 1개에 골격 1개
    + 판정 기준은 문서가 끝나는 자리. 결정 사항 절에 보고 대상의 결정(승인, 선택, 투자)이 있으면 상황, 문제, 질문, 답(SCQA)
    + 결정 없이 실행 방법으로 끝나는 문서는 필요성, 권고 내용, 실행 방법(WWH). 예시로 가이드라인과 매뉴얼
    + 동향과 시사점, 진단과 개선으로 끝나는 문서는 상황, 문제, 해소(SCR). 예시로 이슈리포트, 요약보고서
    + 전략기획과 사업기획은 결정 사항 절에 따라 SCQA 또는 WWH. 브리핑자료는 SCQA
- (1줄 스토리라인) 핵심 질문의 답 1문장
- (장별 메시지) 장마다 1줄. 장 메시지는 1줄 스토리라인의 근거. 형제 장의 배열은 시간 순서, 구조 순서, 중요도 순서 중 1개
- (목차) 장 순서는 판정한 계통의 사고 순서를 따름. 기획 유형 예시에 같은 유형이 있으면 그 장 구성을 초안으로 사용. 계통별 장 순서는 references/report.md 장 순서 절
    + 목차 표는 절마다 1행. 행마다 대표 □ 판단문 1개, 핵심 표, 예상 쪽수를 기입
    + 과제카드 형식으로 쓰는 절이나 항은 □ 판단문 열에 과제 목표 1문장을 기입. 승인 후 이 문장은 과제 개요 □의 (목표) ❍로 사용
- 판단문은 원고의 □ 제목으로 그대로 옮겨짐. SKILL.md 스토리라인 확정 절의 작성 규범(□ 제목의 문체, 단문과 명사형 종결, 줄 상한)을 적용
- 제시 전에 아래 항목을 자체 점검. 어긋난 행은 수정 후 제시
    + 장 순서가 판정한 계통의 사고 순서와 일치
    + 장 메시지마다 1줄 스토리라인의 근거 역할이 확인됨
    + 결정 사항의 설득 근거마다 담는 장이나 핵심 표가 존재
    + 역순 점검에서 근거가 끊기는 장이 없음
- 00_기획설계.md를 파일 전달 기능으로 전달. 확인 요청 항목은 3개 이내
- 유저가 승인하면 00_기획설계.md 상단 (승인) 줄에 일자와 범위를 기입. 승인된 판단문은 해당 절의 첫 □ 제목으로 사용. 같은 절의 나머지 □는 원고 작성 중에 판단문의 논지 안에서 작성. 판단문의 의미 변경과 절 추가는 유저 재확인

## 원고 작성

- 원고는 장 1개당 파일 1개. 파일명은 `NN_장이름.md`. 과제카드, 이슈리포트, 브리핑자료 등 짧은 문서는 파일 1개로 작성할 수 있음
- 입력 자료의 수치와 사실을 우선 사용. 자료 밖의 수치는 웹검색 출처(허용 시)나 `[확인]` 표지
- 자료 원천과 출처 품질은 references/report.md 자료 조사 절을 적용. 수치와 사실은 03_자료대장.md에 한 행씩 기록. 기획보고서의 자료대장은 가설 열과 판정 열을 비움. 반영 절 열은 채움
- 보고 대상이 판단할 사항(예산, 일정, 역할, 성과 지표)은 표로 제시
- 추진일정표와 회의체 운영(안) 표는 SKILL.md 추진일정표 절과 회의체 절의 규범을 적용
- 분량은 □ 1개에 ❍ 1개 이상. `check volume`이 □ 단독과 □ 직후 표를 판정. □ 제목 줄 상한과 계위 개수 초과는 경고

## 독자 관점 서술

- SKILL.md 독자 관점 서술 절을 적용. 아래 규칙은 기획보고서 독자에 맞춘 보완
- (독자) 독자는 00_기획설계.md의 보고 대상. 보고 대상은 결정 사항 절의 결정을 내리는 주체. 보고 대상이 따로 없는 기획(개인 홈페이지, 오픈소스 프로젝트 등)은 결과물 이용자(방문자, 사용자, 기여자 등)를 독자로 둠
    + 예산, 일정, 성과 지표는 보고 대상이 쓰는 단위와 명칭으로 표기. 예시로 회계연도, 예산 단위, 기관 성과지표 명칭 등
- (대안 제시) 결정을 요청하는 문서는 결정 사항마다 비교 대안과 선택 기준을 제시. 권고안은 비교 결과에서 고름
- (현황 서술) 보고 대상의 현황과 부족한 부분은 references/report.md 독자 관점 서술 절의 어조 규칙과 격차 서술 규칙을 적용
- (성과 서술) 성과는 사업 수혜자에게 일어나는 변화로 서술. 지원 건수, 행사 개최 횟수 등의 활동량은 그 변화에 이르는 수단으로 서술
- (시사점) 이슈리포트의 시사점과 제언은 보고 대상이 대응할 사항으로 씀

## 점검

- `check all`의 기획보고서 대상은 분량 구성, 어조와 어휘, 수치 검산, 확인 표지 잔여(경고만)
- `[확인]` 잔여는 3단계에 위치 목록을 한 턴에 묶어 유저에게 질의. 값을 받으면 기입. 받지 못한 자리는 유저 승인 후 문장이나 행을 삭제
- 자체 검토와 렌더링 검수 기록은 05_점검기록.md의 `## 수동 기록` 절 아래에 둠
- 자체 검토는 1회. 항목은 SKILL.md 심층 검토 절의 수치 무결성, 논리 비약, 독자 관점과 아래 항목
    + (내부 어휘) 00_기획설계.md의 설계 언어가 원고에 남지 않음. 대상은 골격의 단 이름, SCQA와 WWH 같은 골격 약칭, 계통 명칭 등. 남은 자리에는 그 뜻을 실제 내용으로 서술. `check all`의 어조 판정은 이 어휘를 판정하지 않음

## 조판

- 명령은 `build 작업폴더 --title "문서 제목" --format 형식 --page-break 방식`
- 장 대부분이 반 쪽 이하인 문서는 `--page-break none`. 장마다 새 쪽을 쓰면 빈 공간이 커짐
- 목차, 쪽번호, 표지, 간지는 기본 OFF. 착수 질의 답변으로 켬
- 목차 쪽번호에 누락이 있으면 references/report.md 조판 절의 처리를 따름. 목차는 유지하고 누락 항목과 새로 고침 안내를 최종 보고에 기재
- 간지는 `--divider on`으로 켬. 장마다 장 번호와 장 제목만 둔 쪽이 앞에 들어감. 조판 방식은 SKILL.md 조판 절
    + 간지를 켜면 문서 제목은 첫 쪽에 단독으로 배치
- 산출 파일은 납품/기획보고서.hwpx와 .docx
