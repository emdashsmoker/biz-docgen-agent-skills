# Planning Report Path

- The path that writes a planning report from a topic and materials the user sets, without an RFP
- (Purpose) A document that starts from the needs of the people who will use the result and decides what to do and how before execution
- Short-form examples are documents that deliver the inputs to a planning judgment or its results to the report recipients
- Every plan is designed in one of the goal-setting stream, the gap-analysis stream, or a combination of the two. Judgment and application are in the Design Streams section
- Design the document specification with reference to the planning type examples and short-form examples. Types absent from the examples are designed with the same procedure
    + (Planning type examples) Strategic planning, business planning, event planning, initiative cards, and so on
    + (Short-form examples) Summary reports, issue reports, briefing materials, guidelines and manuals, and so on
- The design order is planning design (decisions, problem statement, stream, competitive landscape, framework, storyline), table of contents, manuscripts
- Use the methods of the proposal path (background framework, module frameworks by engagement type, schedule chart, committee design), its writing norms, and its typesetting as is
- Hierarchy and numbering are the same as the proposal (Ⅰ., 1., 가., 1), □, ○, -). The document title goes on the first line of the document
- The user sets the volume. If the user does not, the model designs the volume from the scope of the topic and the amount of input material and presents it in the step 1 approval request

## Design Streams

- The thinking order of the two streams follows the stream table at the opening of references/methods.md
    + (Goal-setting stream) Strategic planning methodology. Starts from defining the state to reach and cascades initiatives and action plans downward
    + (Gap-analysis stream) Problem-solving methodology. Starts from establishing the current state and designs alternatives that remove the causes of the gap
    + (Combination) Writes the two streams in sequence in one document. The conclusion of the first stream is the premise of the second. The chapter order is the business planning type and composite engagements in the references/report.md Chapter Order section
- Judge the stream by the problem statement of 00_기획설계.md
    + If the plan must newly set a state to reach, it is the goal-setting stream. For example new programs, vision development, events
    + If it must find the causes why the current state falls short of a given target state, it is the gap-analysis stream. For example operational improvement, response to poor performance, institutional supplementation
    + If both verdicts come out, it is a combination
- Design the chapter structure by mapping a chapter or section to each step of the thinking order of the judged stream. The model decides on merging and omitting steps to fit the volume and input material
- Planning type examples are cases where a stream shows up as a document specification. For requests outside the examples, design chapters by the stream. Check the designed chapter structure for omissions against the chapter structure and key tables of the closest example
- If a short form holds recommendations, initiatives, or plans, set the grounds of that chapter by the thinking order of the stream

## Planning Type Examples

- Examples of chapter structure and key tables per planning type. The model designs added, merged, or omitted chapters and adjusted chapter names to fit the topic and storyline

| Type | Stream | Chapter structure | Key tables |
|---|---|---|---|
| Strategic planning | Goal-setting | 추진 배경 → 현황 진단 → 비전과 추진 전략 → 추진 과제 → 추진 체계와 일정 → 기대 효과 (background → current state diagnosis → vision and strategies → initiatives → implementation structure and schedule → expected effects) | Current state diagnosis table, strategy system table, initiative list table, roadmap |
| Business planning | Combination (a goal system added to gap analysis) | 추진 배경 → 현황 분석 → 사업 추진 타당성 → 사업 내용 → 추진 체계와 절차 → 소요 예산 → 성과관리와 기대 효과 (background → current state analysis → program feasibility → program content → implementation structure and procedure → required budget → performance management and expected effects) | Program overview table, table comparing distinctiveness against existing programs, support field table, implementation structure diagram, budget calculation table, performance indicator table |
| Event planning | Goal-setting | 행사 개요 → 추진 목적 → 세부 프로그램 → 운영 계획 → 소요 예산 → 향후 일정 (event overview → purpose → detailed program → operation plan → required budget → next schedule) | Event overview table, program table, role assignment table, budget table |
| Initiative card | Last step of both streams (downward cascade, alternative design) | 과제 목록 → 과제별 카드 (initiative list → card per initiative) | Initiative list table, performance indicator table and required budget table per initiative |

- Background and necessity chapters apply the framework of the SKILL.md Background Framework section
- Composition of business planning
    + (Current state analysis) Divided into external environment and internal capability. International and domestic are sub-divisions within the external environment
    + (Program feasibility) For public programs, urgency, need for government support, distinctiveness from existing programs, support grounds and history, and so on. For private programs, urgency, marketability, profitability, competitive advantage, and so on
    + (Performance management and expected effects) Performance goals, performance indicators and target values, a logic model among performance indicators, performance management and diffusion measures, expected effects
- Rows of the event overview table are date and time, venue, audience, scale, host, organizer, and so on. Columns of the program table are time, content, owner, and remarks
- A budget table consists of the columns expense item, calculation basis, and amount. `check numbers` rechecks the total row

## Short-Form Examples

- Examples of document specifications fitted to reporting situations. Adjust the chapter structure to the topic

| Form | Stream | Chapter structure | Key tables |
|---|---|---|---|
| Summary report | Follows the stream of the original report | Keep the chapter order of the original report. The first □ of each chapter holds that chapter's conclusion | Tables from the original report used to derive conclusions |
| Issue report | Early steps of the goal-setting stream (environment analysis, direction) | 이슈 배경(작성 배경, 정의와 범위) → 동향(정책, 기술, 시장과 산업, 투자 등 주제에 맞는 항목) → 전망과 과제 → 시사점과 제언 → 참고문헌 (issue background (context, definition and scope) → trends (policy, technology, market and industry, investment, and other items fitting the topic) → outlook and challenges → implications and recommendations → references) | Comparison table of major countries, market outlook table, major company status table |
| Briefing material | Follows the stream of the ongoing plan | 보고 요지 → 추진 경과 → 주요 내용 → 향후 계획 → 건의 사항 (gist → progress → main content → next plans → requests) | Progress table, upcoming schedule table |
| Guidelines and manuals | Last step of both streams (execution method) | 개요(배경, 목적과 적용 범위, 구성) → 기본 개념과 사례 → 원칙과 유의 사항 → 절차나 업무별 적용 방안 → 체크리스트 → 부록 (overview (background, purpose and scope, composition) → basic concepts and cases → principles and cautions → application by procedure or task → checklist → appendix) | Term definition table, procedure table, application table by task, checklist |

- Use the figures and conclusions of the original report as they are in a summary report. The original report is received as input material
- In the trend chapter of an issue report, describe domestic after international for each item. Derive the implications and recommendations chapter from facts confirmed in the trend chapter
- The requests of briefing material list one matter for the report recipient to decide per □
- The procedure chapter of guidelines and manuals has one □ per step. The □ heading is the step name
    + The columns of the procedure table are step, owner, processing content, and form
    + The columns of the term definition table are term, definition, and governing rule
    + The columns of the checklist are check item, check criterion, and applicable step

## Initiative Card Format

- An initiative card is an example format that describes the implementation plan of one initiative in □ units. It cannot be the answer for every topic
- It applies to documents for which the user asked for initiative cards, initiative definitions, or implementation plans per initiative
- If the model judges initiative cards fit a document where they were not requested, ask the user whether to use them in the step 1 approval request. Use them only if the user approves
- The level of initiative titles is set by the document structure
    + If the initiatives chapter groups initiatives by strategy, strategies are sections (##) and initiatives are subsections (###)
    + An initiative card document makes each initiative a section (##)
    + Initiative numbers go in the initiative list table. build assigns heading numbers
- The default composition and order of □ under an initiative title. Add, merge, or omit □ to fit the character of the initiative
    + (과제 개요, initiative overview) The initiative goal and implementation period, divided by the bracketed subheadings (목표) and (기간)
    + (추진 근거, grounds) The relevant clauses of higher-level plans, laws, and ordinances
    + (추진 배경, background) The current state and the problem the initiative resolves. Figures go on evidence lines with sources
    + (주요 내용, main content) The detailed activities of the initiative. Each ❍ carries the activity name as a bracketed subheading. Detailed items go on evidence lines
    + (추진 체계, implementation structure) The names of the lead organization and participating organizations. List organization names separated by commas after the bracketed subheadings (주관) and (참여)
    + (기대 효과, expected effects) The change that happens to the initiative's beneficiaries. The writing rule is (Outcome description) of the Reader-Perspective Writing section
    + (성과 지표, performance indicators) A table of performance indicators and annual target values
    + (소요 예산, required budget) A table of budget by funding source and year. The gist ❍ before the table lists the amount per funding source separated by commas in parentheses after the total
- □ headings are keyword noun phrases, the names in parentheses of the composition items. With several initiative cards, keep the composition and order of □ uniform across initiatives
- The number of □ for one initiative follows the number of composition items. The □ count warning of `check volume` (cap 4) arising in initiative card sections and subsections is not to be resolved
- If the main content has five or more activities, place one □ per group of activities and use the group name as the □ heading
- Place tables after the gist ❍ under □. The rule is in the SKILL.md Style of □ Headings section
    + The columns of the performance indicator table are performance indicator, unit, and annual target values
    + The required budget table has funding sources (national, local, private, and so on) as rows and years and total as columns. `check numbers` rechecks the total
- Put an initiative list table (initiative number, initiative name, implementing body, implementation period, and so on) before the initiative cards

## Planning Design

- 00_기획설계.md corresponds to the proposal strategy file and storyline of the proposal path and to the diagnosis file and storyline of the pre-diagnosis report path
- The writing order is decisions, problem statement, stream, competitive landscape, framework, storyline, table of contents
- (Decisions) The decisions the report recipient will make after reading the document and the grounds those decisions need. These grounds set the chapter structure and key tables
- (Problem statement) Apply the problem statement rule of the references/report.md Diagnosis Design section
- (Stream) Choose one of goal-setting, gap analysis, and combination by the criteria of the Design Streams section. Give one line of grounds for the verdict alongside
- (Competitive landscape) Write it if the document's actor or the target program competes with other actors for limited resources. Private companies' business plans, technology commercialization plans, plans responding to national funding calls, and so on. The writing rule is the competitive landscape item of the references/report.md Diagnosis Design section. Competitive advantages and disadvantages are set up as chapter messages and □ judgment statements
- (Framework) One framework per document
    + The criterion is where the document ends. If the decisions section has a decision of the report recipient (approval, choice, investment), situation, complication, question, answer (SCQA)
    + A document that ends with execution methods without a decision is necessity, recommendations, execution method (WWH). For example guidelines and manuals
    + A document that ends with trends and implications or diagnosis and improvement is situation, complication, resolution (SCR). For example issue reports and summary reports
    + Strategic planning and business planning are SCQA or WWH according to the decisions section. Briefing material is SCQA
- (One-line storyline) One sentence answering the key question
- (Chapter messages) One line per chapter. A chapter message is a ground of the one-line storyline. Sibling chapters are arranged in one of time order, structural order, or order of importance
- (Table of contents) The chapter order follows the thinking order of the judged stream. If the planning type examples include the same type, use its chapter structure as the draft. The chapter order per stream is in the references/report.md Chapter Order section
    + The table of contents table has one row per section. Each row holds one representative □ judgment statement, key tables, and expected pages
    + For a section or subsection written in the initiative card format, write one sentence of the initiative goal in the □ judgment statement column. After approval this sentence is used as the (목표) ❍ of the initiative overview □
- Judgment statements carry over unchanged as □ headings of the manuscripts. Apply the writing norms of the SKILL.md Storyline Finalization section (style of □ headings, short sentences with nominal endings, line limits)
- Before presenting, self-check the items below. Fix rows that deviate before presenting
    + The chapter order matches the thinking order of the judged stream
    + Each chapter message is confirmed to serve as a ground of the one-line storyline
    + For each persuasion ground in the decisions, a chapter or key table that holds it exists
    + No chapter breaks the grounds in the reverse-order check
- Deliver 00_기획설계.md through the file delivery feature. At most three items for confirmation
- When the user approves, write the date and scope on the `(Approval)` line at the top of 00_기획설계.md. Approved judgment statements are used as the first □ heading of their sections. The other □ of the same section are written while writing manuscripts within the argument of the judgment statement. Changing the meaning of a judgment statement or adding sections needs user reconfirmation

## Manuscript Writing

- One manuscript file per chapter. The file name is `NN_장이름.md`. Short documents such as initiative cards, issue reports, and briefing material may be written as one file
- Use the figures and facts of the input materials first. Figures outside the materials get a web search source (if allowed) or the `[확인]` marker
- Apply the references/report.md Source Research section for data sources and source quality. Record figures and facts in 03_자료대장.md one row at a time. The source ledger of a planning report leaves the hypothesis and verdict columns empty. The reflecting section column is filled
- Present matters for the report recipient to judge (budget, schedule, roles, performance indicators) as tables
- Apply the norms of the SKILL.md Schedule Chart and Committees sections to the schedule chart and the committee operation (draft) table
- Volume is one or more ❍ per □. `check volume` judges a lone □ and a table right after □. The □ heading line cap and level counts over the cap are warnings

## Reader-Perspective Writing

- Apply the SKILL.md Reader-Perspective Writing section. The rules below supplement it for the readers of a planning report
- (Readers) The reader is the report recipient of 00_기획설계.md. The report recipient is the actor who makes the decisions in the decisions section. For a plan without a separate report recipient (a personal homepage, an open source project, and so on), the users of the result (visitors, users, contributors, and so on) are the readers
    + Write budget, schedule, and performance indicators in the units and names the report recipient uses. For example fiscal years, budget units, institutional performance indicator names
- (Presenting alternatives) A document that asks for a decision presents comparison alternatives and selection criteria for each decision. Choose the recommendation from the comparison results
- (Current state description) For the report recipient's current state and shortfalls, apply the tone rule and gap description rule of the references/report.md Reader-Perspective Writing section
- (Outcome description) Describe outcomes as changes that happen to the program's beneficiaries. Describe activity volumes such as the number of support cases or events held as means to reach that change
- (Implications) Write the implications and recommendations of an issue report as matters for the report recipient to respond to

## Checks

- The planning report targets of `check all` are volume composition, tone and vocabulary, figure checks, and leftover confirmation markers (warning only)
- For leftover `[확인]`, bundle the list of locations into one turn at step 3 and ask the user. Fill in values received. For places without values, delete the sentence or row after user approval
- Records of the self-review and render review go under the `## 수동 기록` section of 05_점검기록.md
- One self-review. The items are figure integrity, logical leaps, and reader perspective from the SKILL.md In-Depth Review section, plus the item below
    + (Internal vocabulary) Design language from 00_기획설계.md does not remain in the manuscripts. Targets are framework stage names, framework abbreviations such as SCQA and WWH, stream names, and so on. Where they remain, describe their meaning as actual content. The tone verdict of `check all` does not judge this vocabulary

## Typesetting

- The command is `build workspace --title "document title" --format format --page-break handling`
- For a document whose chapters are mostly half a page or less, use `--page-break none`. A new page per chapter makes large empty spaces
- Table of contents, page numbers, cover, and divider pages are OFF by default. Turn them on by the kickoff answers
- If table of contents page numbers are missing, follow the handling in the references/report.md Typesetting section. Keep the table of contents and state the missing entries and the refresh guidance in the final report
- Turn on divider pages with `--divider on`. A page holding only the chapter number and title goes before each chapter. The typesetting method is in the SKILL.md Typesetting section
    + With divider pages on, the document title is placed alone on the first page
- Output files are 납품/기획보고서.hwpx and .docx
