# 조판 규범

양식 모양은 scripts/form.py, 조판 수치는 scripts/config.py에서만 바꾼다. 길이 단위 HWPUNIT은 1/7200인치(1mm는 약 283 HWPUNIT)다.

## 내장 양식

두 양식 모두 A4(210 x 297mm), 좌우 여백 20mm, 본문 폭 170mm다. chapter는 위아래 여백 15mm, 머리말과 꼬리말 영역 각 10mm이며 flat은 위 여백 15mm, 아래 여백 10mm, 머리말 영역 10mm, 꼬리말 영역 15mm다.

| 역할 | chapter 스타일 | flat 스타일 |
|------|------|------|
| 장 | 장 제목 (나눔고딕 20pt 굵게) | 문서 제목 (나눔바른고딕 20pt 굵게, 가운데) |
| 절 | 절 제목 (나눔고딕 15pt 굵게) | 절 제목 (나눔바른고딕 15pt 굵게) |
| 소절 | 소절 제목 (나눔고딕 14pt 굵게) | 소절 제목 (나눔바른고딕 14pt 굵게) |
| 가나다 | 가나다 제목 (나눔고딕 13pt 굵게) | 가나다 제목 (나눔고딕 13pt 굵게) |
| 논점 | □ 내용 (나눔고딕 13pt 굵게) | □ 내용 (나눔고딕 12pt 굵게) |
| 주장 | ○ 내용 (나눔고딕 12pt) | ○ 내용 (나눔고딕 12pt) |
| 근거 | - 내용 (나눔고딕 12pt) | - 내용 (나눔고딕 12pt 자간 3%) |

| 셀 글머리 | 표 내용 ○, 표 내용 - (나눔고딕 10pt 왼쪽 정렬, 기호 ◦와 -) | 표 내용 ○, 표 내용 - (나눔고딕 10pt 자간 -7% 왼쪽 정렬, 기호 ◦와 -) |
| 표 캡션 | 표 제목 (나눔고딕 11pt 굵게) | 표 제목 (나눔고딕 11pt) |
| 단위 행 | 단위 (나눔고딕 9pt) | 단위 (나눔고딕 9pt 자간 -7%) |
| 출처 행 | 출처 (나눔고딕 9pt) | 출처 (나눔고딕 9pt 자간 -7%) |
| 그림 캡션 | 그림 제목 (나눔고딕 11pt 굵게 자간 -6%) | 그림 제목 (나눔고딕 11pt 자간 -6%) |
| 각주 | 각주 (나눔고딕 10pt 왼쪽 정렬) | 각주 (나눔고딕 9pt 왼쪽 정렬) |
| 목차 | 목차 장 (나눔고딕 14pt 굵게), 목차 절 (나눔고딕 12pt) | 없음 (목차 생략) |
| 바탕글 | 바탕글 (나눔고딕 10pt) | 바탕글 (나눔고딕 10pt) |

- 글꼴은 모두 나눔고딕이며 flat 제목만 나눔바른고딕. 한 스타일 안의 모든 언어 칸에 같은 글꼴을 씀. 확보 경로와 한자 표시는 references/renderers.md의 글꼴 절
- (번호 체계) chapter는 제N장, N.N, N.N.N, 가. 순이며 캡션 번호가 장마다 1부터 다시 시작(표 1-1, 그림 1-1). flat은 문서 제목, N., N.N, 가. 순이며 캡션 번호가 문서 전체에 이어짐(표 1, 그림 1)
- (글머리 출력) 스타일의 글머리 설정이 BULLET이면 한/글과 Word가 기호를 그림. 글머리가 없는 스타일은 build가 기호 문자를 본문에 기입
- (쪽 끝 고립 방지) 장, 절, 소절, 가나다 제목과 □ 스타일은 다음 문단과 같은 쪽에 두는 설정을 가짐
- 줄 간격, 문단 여백, 글머리 기호 뒤 간격 등 나머지 수치는 scripts/form.py의 정의가 기준

## 개체 배치

표 폭 산정

- 표는 ○ 서술의 하위 정보이므로 열 폭을 글자에 맞춰 ○ 계위 안쪽에 둠. 정보가 많아 글자에 맞춘 폭이 ○ 계위를 넘는 표만 상한까지 넓어짐
- 표 폭 상한은 본문 폭에서 계위 들여쓰기 1500 HWPUNIT(약 5.3mm, TABLE_INDENT_MARGIN)을 제외한 값. 하한은 상한의 50%(TABLE_MIN_RATIO). 실폭은 열 필요폭의 합계
- 가중 길이는 글자 폭을 한글 반 자 단위로 센 합의 올림값. 한글과 한자 등 전각 문자는 2, 영문과 숫자와 기호는 나눔고딕 글자별 폭(GLYPH_EM), 빈칸은 HWPX 0.5em과 DOCX 0.28em(SPACE_EM_HWPX, SPACE_EM_DOCX)을 한글 반 자 폭으로 나눈 값, 폭 표에 없는 글자는 1
- 줄의 폭은 가중 길이에 가중 1단위 폭을 곱하고 셀 안 문단의 좌우 여백과 셀 글머리 기호 폭(기호 폭, 기호 뒤 간격, 폭 조정의 합)을 더한 값. 글자 크기, 장평, 자간과 여백은 그 줄에 쓰는 스타일(표 내용, 표 내용 왼쪽, 셀 글머리)의 값이며 일반 줄은 표 내용과 표 내용 왼쪽 중 넓은 쪽
- 열 필요폭은 열에서 가장 긴 줄의 폭에 1800(COL_PAD_W)을 더한 값. 최소 3000(COL_MIN_W)
- `<` 지시로 여러 열에 걸친 셀은 줄의 폭을 걸친 열 수로 나누어 각 열에 반영. 병합 지시 셀(`^`, `<`)은 길이 계산에서 제외
- 가장 긴 줄의 폭이 12000 HWPUNIT(약 42mm, 12pt 한글 10자, COL_ONE_LINE_W)을 넘는 열은 2줄 접힘을 전제로 폭을 60%(COL_WRAP_RATIO)로 줄여 계산. 줄인 폭도 12000 이상 유지하여 이 폭 안의 이름과 짧은 문구는 접지 않음
- 합계가 상한을 넘으면 필요폭이 균등 몫(상한을 열 수로 나눈 값) 이하인 짧은 열은 필요폭을 보장하고 남은 폭을 나머지 열에 필요폭 비율로 나눔. 나머지 열의 접힘 비율이 비슷해져 행 높이가 고르게 됨
- 합계가 하한보다 작으면 하한까지 열 폭 비율로 늘림
- 원고에 열 폭 줄이 있는 표는 위 산정 대신 열 폭 줄의 값으로 열 폭을 정함. 열 하나의 폭은 표 폭 상한(○ 계위 폭)에 값/100을 곱한 값. 하한 보정은 적용하지 않으므로 값의 합계가 표 폭(합계 60이면 상한의 60%). 사용 조건과 값을 정하는 순서는 references/manuscript.md의 표 절

셀 서식

- 열 정렬은 열 단위로 결정. 우선순위는 원고 정렬 표기, 글머리로 시작하는 셀이 있는 열 왼쪽, 그 외 가운데 순. 표기가 없는 숫자 열과 서술형 설명 열은 가운데
- 수량 열의 오른쪽 정렬과 서술형 설명 열의 왼쪽 정렬은 원고 정렬 표기(`---:`, `:---`)로 지정. 표기 기준은 references/manuscript.md의 표 절
- 정렬 판정에는 머리글 행(다단 머리글 포함)과 병합 지시 셀을 제외한 본문 셀만 사용
- 머리글 행은 열 정렬과 관계없이 표 내용 스타일의 가운데 정렬
- 셀 선은 0.15mm 검정. 좌측 끝 셀의 왼선과 우측 끝 셀의 오른선은 비움(EDGE_OPEN_SIDES)
- 병합 뒤 셀의 실제 스팬 기준으로 좌우 바깥선을 다시 지정. 표 끝에 닿는 병합 셀도 바깥선을 비움
- 머리글 행은 표 내용과 같은 글꼴, 크기, 장평, 자간에 굵게와 배경 `#D9D9D9`만 더함. 다단 머리글은 머리글 행 전체에 같은 서식 적용

표 부속 요소

- 단위 행은 머리글 위의 투명 병합 행이며 오른쪽 정렬. 출처 행은 표 아래의 투명 병합 행이며 왼쪽 정렬. 둘 다 표 안에 있어 표와 함께 이동
- 단위 행과 출처 행은 글머리 없는 9pt 전용 스타일(단위, 출처)로 출력. 출처 행에 붙은 ※ 주석 줄은 ※, * 기호를 유지한 채 출처 스타일로 출력
- 표 캡션은 표 위, 그림 캡션은 그림 아래. 캡션과 표 사이 간격 850 HWPUNIT(약 3mm, CAPTION_GAP)
- 캡션 폭은 딸린 표나 그림 표의 폭. 긴 캡션은 이 폭 안에서 줄을 바꿈
- HWPX 캡션은 표에 부착된 캡션 개체이고 번호는 자동번호 필드. chapter는 장 시작 문단의 번호 재시작으로 장마다 1부터 부여

병합

- 세로 병합(auto)은 선행 라벨 열(첫 숫자 열 앞, 최대 2열, MERGE_LABEL_COLS)의 연속 동일값을 병합. 숫자 여부는 굵게 등 인라인 서식 표기를 뺀 출력 글자로 판정
- 라벨 열은 상위 라벨 열의 병합 구간 안에서만 병합하여 구간이 겹치거나 빠지지 않게 유지
- `^` 지시는 모든 열에서 유효. `<` 지시로만 가로 병합. 가로 병합이 세로 병합과 겹치면 가로 병합을 생략하고 경고
- `--merge explicit`은 지시만 적용, `--merge none`은 병합 없음

행 배치

- 행 높이는 2000 HWPUNIT(ROW_BASE_H)에 예상 줄 수가 1줄 늘 때마다 1400(ROW_LINE_H)을 더한 최소 높이. 내용이 넘치면 한/글과 Word가 행을 늘림
- 행의 예상 줄 수는 세로 병합에 속하지 않은 셀 가운데 줄 수가 가장 많은 셀의 줄 수. 셀의 줄 수는 셀 안의 개행 단위 줄마다 줄의 폭(표 폭 산정 항목)을 가중 1단위로 나타낸 값을 한 줄 용량으로 나눈 올림값의 합
- 한 줄 용량은 셀 안 폭을 가중 1단위 폭으로 나눈 값. 셀 안 폭은 셀이 걸친 열 폭의 합에서 좌우 셀 여백을 제외한 값
- 줄의 가중 길이는 줄 스타일의 장평과 자간을 반영. 글자 폭은 글꼴 폭 x 장평 + 자간이므로 음수 자간에서 영문처럼 좁은 글자는 한글 반 자 대비 폭이 더 줄어듦
- 가중 1단위 폭은 한글 1자 폭의 절반. 한글 1자 폭은 글자 크기 x (한글 폭 비율 x 장평 + 자간)이며 글자 크기, 장평, 자간은 표 내용 스타일의 값. 한글 폭 비율 0.94(CELL_HANGUL_EM)는 나눔고딕 실측값
- 세로 병합 셀은 병합 구간 행 높이의 합으로 줄 수를 담음. 모자라는 줄만 구간 행에 번갈아 더하여 행 높이를 고르게 유지
- 셀 안 여백은 좌우 510, 위아래 141 HWPUNIT(CELL_MARGIN_LR, CELL_MARGIN_TB)
- 머리글 행을 포함한 표 행 수가 25행(LONG_TABLE_ROWS)을 넘으면 장표. 단위 행과 출처 행은 행 수에서 제외
    - (engine) 쪽 경계에서 행 단위로 나누고 단위 행과 머리글 행을 제목 행(쪽이 바뀌면 표 위에 다시 나오는 행)으로 지정. 한/글과 Word는 표 맨 위부터 이어진 제목 행만 반복하므로 머리글 위의 단위 행도 제목 행에 포함
    - (split) 첫 행(머리글)을 제외한 행을 24행씩 나누어 별도 표로 만들고 각 표 맨 위에 첫 행을 반복. 캡션 뒤에는 (1), (2) 순번을 붙임

그림 배치

- 그림은 투명 1열 표 안에 배치하여 그림과 출처 행이 함께 이동(FIGURE_IN_TABLE)
    - (HWPX 캡션) 표에 부착된 캡션 개체로 표와 함께 이동. 표의 번호 유형을 그림으로 지정하고 내부 그림은 번호 집계에서 제외
    - (DOCX 캡션) 그림 표 바로 뒤의 캡션 문단. 표 안 문단마다 다음 문단과 같은 쪽에 두는 설정을 걸어 캡션과 같은 쪽에 배치
- 그림 표의 폭은 그림 폭에 좌우 셀 여백(CELL_MARGIN_LR x 2)을 더한 값. 그림이 셀 안 폭에 그대로 들어감
- 그림 크기는 폭을 높이로 나눈 비율로 결정. 1.4 이상인 가로형은 폭 140mm, 0.8 이하인 세로형은 높이 110mm, 그 사이는 폭 90mm. 해상도 정보가 없으면 96dpi로 간주
- 표와 그림은 본문 가운데 배치. 앞뒤 간격은 표 위치와 그림 위치 스타일의 문단 여백이 담당

HWPX 패키지

- (이미지 매니페스트) build 직후 header.xml의 이미지 항목과 BinData 파일을 content.hpf 목록과 대조하여 누락분을 등록하고 `이미지 매니페스트 누락 N건 등록` 줄로 알림. python-hwpx 6.5.0은 목차나 표지를 넣은 문서에서 이미지 여러 개 중 첫 항목만 등록하며 등록하지 않으면 한/글이 나머지 그림을 열지 못함. 이 안내 줄은 보정 결과 보고
- check가 같은 대조와 본문 참조 대응을 다시 확인

## DOCX 대응 규칙

DOCX는 form.py의 같은 정의를 Word 단위로 옮긴다.

- (단위) twip = HWPUNIT / 5, EMU = HWPUNIT x 127
- (글꼴) 한글 칸 글꼴은 Word 동아시아 글꼴과 복합 문자 글꼴에, 영문 칸 글꼴은 라틴 글꼴에 기록. 장평은 문자 폭 비율로, 자간은 글자 크기에 자간 비율을 곱한 문자 간격으로 옮김
- (자동 간격) 한글과 영문, 한글과 숫자 사이 자동 간격을 끔. HWPX 문단 모양의 자동 간격 설정과 같음
- (언어) 문서 기본 언어는 라틴 en-US, 동아시아 ko-KR로 기록. Word 한국어판 기본 문서와 같은 조합. 라벨 파일로 변경 가능(language.latin, language.east_asia)
- (줄 간격) 한/글의 글자 크기 대비 비율을 Word의 최소 줄 높이(글자 크기 x 비율)로 옮김. 줄 높이 계산 방식이 달라 세로 위치가 조금 다를 수 있음
- (문단 여백) 그대로 옮기고 음수 내어쓰기는 Word 내어쓰기로 옮김
- (글머리) Word 글머리 목록(단일 수준)으로 출력. 둘째 줄이 본문 시작선에 맞도록 내어쓰기 폭을 기호 폭, 기호 뒤 간격, 폭 조정값의 합으로 설정. 기호 폭은 유니코드 동아시아 폭이 반각(Na, H)인 기호(내장 양식에서는 하이픈)가 0.5글자, 그 외 기호가 1글자
- (제목 스타일) chapter는 장, 절, 소절, 가나다를 Word 제목 1-4에 입히고 flat은 문서 제목을 Word 제목(Title)에, 절, 소절, 가나다를 제목 1-3에 입힘. 탐색 창과 목차 필드가 이 스타일을 인식
- (그 외 역할) 양식 스타일 이름을 그대로 쓴 사용자 스타일로 출력
- (캡션 번호) Word 번호 필드(SEQ 표, SEQ 그림. 라벨 파일을 쓰면 캡션 라벨을 따름)이며 결과값을 미리 채움. chapter는 장 번호를 글자로 붙이고 필드가 제목 1마다 1부터 다시 셈. flat은 문서 전체에 이어지는 번호
- (캡션 폭) 캡션 문단의 좌우를 본문 폭과 표 폭 차이의 절반씩 들여씀. HWPX 캡션 개체와 같은 폭에서 줄을 바꿈
- (각주) Word 각주로 출력하고 각주 번호 뒤에 `)`를 붙임
- (표) 행 하나는 두 쪽에 나뉘지 않음. 25행 이하 표는 모든 행을 다음 행과 묶어 한 쪽에 둠. 장표(engine)는 단위 행과 머리글 행을 제목 행으로 반복
- (쪽 설정) 한/글은 위쪽 여백과 본문 사이에 머리말 영역을 따로 둠. Word 위쪽 여백은 한/글 위쪽 여백과 머리말 영역의 합이고 머리말 위치는 한/글 위쪽 여백. 아래쪽도 같은 방식
- (앞부분 구역) 표지와 목차는 다음 쪽에서 시작하는 앞 구역에 두고 본문 구역 쪽번호를 1부터 시작. 머리말과 쪽번호는 본문 구역에만 표시. 쪽번호는 꼬리말 가운데 `- N -`
- (글꼴 표) 양식 글꼴마다 영문 이름(나눔고딕은 NanumGothic, 나눔바른고딕은 NanumBarunGothic), 한글 문자 집합, 계열을 기록. 계열은 영문 이름에 Myeongjo가 있으면 명조 계열(roman), 그 외 고딕 계열(swiss). Word는 해당 글꼴이 없을 때 이 정보로 같은 계열의 글꼴을 고름
- (문서 속성) 작성자, 수정자, 설명은 비우고 제목은 표지 제목으로 기록. 서식 파일에 딸린 미리보기 그림은 제거

## 목차

- 목차 항목은 깊이 1이면 장, 2면 절까지, 3이면 소절까지. 항목은 제목, 점선 탭, 쪽번호
- 목차는 목차 스타일(toc_chapter, toc_section)이 있는 양식에서만 생성. flat은 목차 스타일이 없어 생략
- HWPX 목차는 정적 문단. 납품용 목차는 한/글의 차례 기능으로 다시 생성 권장
- DOCX 목차는 Word 목차 필드(`TOC \o "1-깊이" \h \z`)이며 항목과 쪽번호를 결과값으로 미리 채움. 쪽번호가 없으면 `\n` 스위치로 쪽번호를 숨김
- DOCX 목차는 Word가 만드는 목차와 같은 구조로 생성. 제목마다 숨은 책갈피(`_Toc` 뒤에 9자리 번호를 붙인 이름)를 두고, 목차 항목마다 그 책갈피로 가는 하이퍼링크와 `PAGEREF` 쪽번호 필드를 두며, 전체를 Word 목차 콘텐츠 컨트롤로 감쌈
- DOCX에 쪽번호 있는 목차를 삽입하면 Word가 열 때 필드 갱신을 묻도록 설정. "예"를 누르면 Word 기준으로 다시 계산. 쪽번호 없는 목차는 묻지 않음
- DOCX 목차는 Word 제목 스타일을 기준으로 항목을 모음. 문서를 손으로 고칠 때 제목의 스타일을 바꾸면 목차에서 빠짐. 고친 뒤에는 목차를 선택하고 F9로 갱신
- Word에서 목차를 갱신하면 '쪽 번호만 업데이트'와 '목차 전체 업데이트' 중 하나를 고름. '쪽 번호만 업데이트'는 `PAGEREF`가 책갈피 위치로 쪽번호를 다시 계산하고 '목차 전체 업데이트'는 Word가 항목을 새로 만듦

쪽번호 산정 (`--toc`와 `--page-number`를 함께 지정한 경우)

1. 목차 항목만 담은 1회차 문서를 조판
2. 1회차 문서를 글자 추출이 가능한 PDF로 렌더링하고 쪽별 텍스트를 그린 순서대로 얻음. HWPX는 rhwp, 없으면 LibreOffice와 H2Orestart. DOCX는 LibreOffice이며 목차 필드를 갱신한 뒤 저장. 렌더링 사본과 PDF는 임시 폴더에서 만들고 지우므로 산출 폴더에는 문서만 남음
3. 목차 제목(`목  차` 또는 라벨 파일의 toc.title)이 처음 나오는 쪽부터 목차 항목을 차례로 찾아 마지막 항목이 있는 쪽까지를 목차로 보고 그다음 쪽을 본문 1쪽으로 둠. 목차가 여러 쪽이어도 같은 방식
4. 본문에서 목차 항목을 차례로 찾아 처음 나오는 쪽을 쪽번호로 삼음. 앞 항목보다 앞쪽에서는 찾지 않음
5. 쪽번호를 기입한 최종 문서를 다시 렌더링하여 같은 방식으로 대조. 불일치가 있으면 새 값으로 다시 조판(TOC_MAX_PASSES, 기본 2회)
6. build가 `목차 쪽번호 대조: ... 일치 N/M건`(M은 목차 항목 수) 또는 불일치 항목 목록을 출력. 본문에서 찾지 못한 항목은 쪽번호를 비우고 `WARN:` 줄로 알림
7. HWPX는 최종 렌더에서 목차 제목이 쪽 끝에 있고 뒤따르는 첫 본문 줄(사이의 하위 제목과 □는 건너뜀, 표와 그림은 캡션)이 다음 쪽에서 시작하면 `[목차 제목 고립]` WARN으로 제목과 본문 쪽번호를 알림. WARN 안내대로 원고의 해당 제목 앞에 `---`를 두어 맞춤

- 목차 항목과 쪽번호는 항목 순번으로 대응하므로 같은 문구의 제목이 여럿이어도 섞이지 않음
- 본문 구역이 1쪽부터 시작하므로 목차 길이가 바뀌어도 본문 쪽번호는 변하지 않음
- 산정값은 검수 렌더러 기준의 근사값. 렌더러의 줄바꿈과 쪽 나눔이 한/글이나 Word와 다르면 값이 달라질 수 있음

## 유저 양식 (HWPX 전용)

- skeleton 명령(`skeleton 양식.hwpx 스켈레톤.hwpx [--section N]`)은 유저 양식에서 header.xml과 본문 구역의 쪽 설정(첫 문단)만 남긴 빈 양식과 프로파일 초안(스켈레톤.profile.json)을 산출. 본문 구역 기본값은 마지막 구역
- 스켈레톤에서는 다른 구역, 이미지, 미리보기, 작성자와 일시 메타데이터를 제거
- 초안은 역할별 후보 이름(내장 양식 이름과 보고서 양식에 흔한 짧은 이름)으로 스타일을 추정. 찾지 못한 역할은 null이며 출력된 스타일 목록에서 골라 기입
- 표지, 제출문, 연구진, 표 목차는 스켈레톤에 없음. 유저 양식 원본에 fill로 채우거나 한/글에서 붙임

프로파일 키

- (numbering) manual은 절과 소절 번호를 제목 문구에 기입. auto는 절과 소절 번호를 한/글 개요 번호에 맡기고 제목 문구에는 기입하지 않음. 장 번호와 가나다는 두 방식 모두 제목 문구에 기입
- (chapter_format, section_format, subsection_format) 제목 형식. chapter_format은 `{n}`(장 번호)과 `{t}`(제목)를 쓰고 section_format과 subsection_format은 `{c}`(속한 장 번호, 장이 없으면 1), `{s}`(절 번호), `{ss}`(소절 번호), `{t}`를 씀. 예시는 `"제{n}장 {t}"`, `"{c}.{s} {t}"`, `"{s}. {t}"`. 라벨 파일의 formats.* 키가 이 값을 덮어씀
- (caption_prefix) 캡션 번호 앞 문자. `"{c}-"`이면 장별 번호, `""`이면 문서 전체에 이어지는 번호
- (역할 키) 값은 스타일 이름. body, chapter, section, subsection, ganada, square, circle, dash, dot, note, table_pos, table_cell, table_cell_left, table_title, unit, source, fig_pos, fig_title
- (선택 역할 키) toc_chapter, toc_section, table_cell_bullet, table_cell_dash
- null이거나 빠진 역할은 바탕글로 출력하고 WARN. 스켈레톤에 없는 스타일 이름을 적으면 build가 오류로 중단

스켈레톤 편집 규칙

- 렌더러가 글머리 정의를 목록 위치로 참조하므로 새 글머리 정의는 목록 끝에 id 순서로 추가
- H2Orestart 변환에 필요하므로 스타일을 추가할 때 engName, langID, lockForm 속성을 기입
- 여백과 용지 크기는 머리말과 꼬리말을 추가하기 전에 확정. python-hwpx는 머리말과 꼬리말의 영역 폭을 생성 시점의 여백으로 한 번만 계산하므로 나중에 여백을 바꾸면 영역 폭이 본문 폭과 어긋남
- 머리말은 secPr 밖의 ctrl 사본이 유효. python-hwpx의 머리말 설정이 만드는 secPr 안 사본은 제거하고 ctrl 사본의 문단 정렬을 지정 (`--header`가 자동 처리)

## 라벨

build가 문서에 찍는 고정 문구와 파일에 기록하는 언어 태그를 라벨로 둔다. 기본값이 한국어이므로 `--labels` 없이 조판하면 한국어 문서가 나온다. `build ... --labels 라벨.json`은 아래 키의 중첩 JSON 객체를 읽으며 HWPX, DOCX와 두 내장 양식에 모두 적용된다. 기본값은 scripts/config.py의 LABEL_DEFAULTS에 있다.

| 키 | 의미 | 기본값 |
|------|------|------|
| formats.chapter | 장 제목 형식. `{n}` 장 번호, `{t}` 제목 | 현재 프로파일의 값. chapter `제{n}장 {t}`, flat `{t}` |
| formats.section | 절 제목 형식. `{c}` 장 번호, `{s}` 절 번호, `{t}` | chapter `{c}.{s} {t}`, flat `{s}. {t}` |
| formats.subsection | 소절 제목 형식. `{c}`, `{s}`, `{ss}` 소절 번호, `{t}` | chapter `{c}.{s}.{ss} {t}`, flat `{s}.{ss} {t}` |
| letters.items | 가나다 계위의 글자 순서. 제목 하나에 한 글자이며 끝 글자 다음은 처음부터 다시 | `가나다라마바사아자차카타파하` |
| letters.format | 가나다 계위의 번호 형식. `{x}` 글자. 제목은 빈칸 하나 뒤에 붙음 | `{x}.` |
| toc.title | 목차 제목. 목차 쪽번호 대조도 이 제목이 있는 쪽에서 시작 | `목  차` |
| caption.table.label, caption.figure.label | 캡션 라벨 단어 | `표`, `그림` |
| caption.table.open, caption.table.close | 표 캡션 라벨과 번호를 감싸는 기호 | `<`, `>` |
| caption.figure.open, caption.figure.close | 그림 캡션 라벨과 번호를 감싸는 기호 | `[`, `]` |
| caption.table.seq, caption.figure.seq | 캡션 번호의 Word SEQ 필드 이름(DOCX). 공백 불가 | 캡션 라벨 |
| notation.source | 출처 줄 토큰(`토큰:`). 추가한 토큰은 `(토큰)`으로도 인식 | `출처`, `자료`, `주` (`(출처)`, `(자료)` 포함) |
| notation.unit | 단위 줄 토큰(`(토큰: )`) | `단위` |
| notation.table | 표 캡션 줄 토큰(`<토큰> 제목`) | `표` |
| notation.figure | 그림 캡션 줄 토큰(`[토큰] 캡션`) | `그림` |
| notation.colwidth | 열 폭 줄 토큰(`(토큰: 15, 20, 25)`) | `열 폭` |
| language.latin, language.east_asia | DOCX 문서 기본 언어(w:lang)의 라틴, 동아시아 값 | `en-US`, `ko-KR` |
| language.hwpx_package | HWPX 문서 언어(content.hpf의 opf:language) | `ko` |
| language.hwpx_style_lcid | HWPX 스타일 언어(langID, Windows LCID 정수) | `1042` |

- (부분 지정) 빠진 키는 기본값 유지. 알 수 없는 키, 자료형이 틀린 값, 알 수 없는 자리표시를 쓰거나 `{t}`(letters.format은 `{x}`)가 없는 형식, 공백이 든 SEQ 이름은 문제 목록 전체를 출력하고 build를 중단
- (프로파일) formats.*는 현재 프로파일(chapter, flat, 유저 프로파일 JSON)의 형식을 덮어씀. flat용 라벨 파일은 flat 형식을 지정하며 flat 문서 제목에는 번호가 없으므로 formats.chapter를 빼고 씀
- (캡션) 캡션은 open, label, 빈칸, 번호, close, 빈칸, 제목 순으로 출력(`<표 1-1> 제목`, `[그림 1-1] 캡션`)
- (원고 표기 토큰) notation.*는 토큰을 추가만 함. 한국어 토큰은 계속 인식하므로 한 원고에 섞어 써도 됨. 토큰은 적은 그대로(대소문자 구분) 대조하고 토큰 안의 빈칸은 빈칸 유무와 관계없이 일치
- (헤더 번호) 원고에 라벨 파일의 번호 형식으로 쓴 번호(예 `# Chapter 2. Status`, `#### (b) Overview`)는 `제2장`, `가.`와 같이 제거한 뒤 양식 번호 체계로 다시 부여
- (HWPX 언어) language.hwpx_package와 language.hwpx_style_lcid는 내장 양식에 적용. 유저 양식(`--skeleton`)은 양식의 값을 유지
- (라벨 밖) 스타일 이름(장 제목, □ 내용 등 양식에 저장된 이름), 글꼴 이름, 계위 기호 □ ○ - ㆍ ※, 쪽번호 `- N -`, 각주 번호 뒤 `)`는 그대로 둠. 표지와 머리말 문구는 `--cover`, `--header`로 지정

영어 예시 (chapter 문서. 가나다 계위는 (a), (b), (c))

```json
{
  "formats": {"chapter": "Chapter {n}. {t}"},
  "letters": {"items": "abcdefghijklmnopqrstuvwxyz", "format": "({x})"},
  "toc": {"title": "Contents"},
  "caption": {"table": {"label": "Table"}, "figure": {"label": "Figure"}},
```

- 항목 점검 뒤 목록을 덮고 자유 검수 1회 수행. 문서를 처음 받은 실무자가 이상하게 볼 지점은 규칙에 없어도 재량으로 고침

## 규범의 근거

- (기호 계위) 「행정업무의 운영 및 혁신에 관한 규정 시행규칙」 제2조제1항은 공문서의 항목을 1., 가., 1), 가) 순으로 표시하되 필요하면 □, ○, -, ㆍ 등 특수한 기호로 표시할 수 있다고 정함. 양식은 이 기호 계위를 보고서 본문 계위로 사용
- (기호 문자) 계위 기호는 □(U+25A1), ○(U+25CB), -(U+002D), ㆍ(U+318D), ※(U+203B). 나눔고딕(네이버, Google 배포본)과 나눔바른고딕의 모든 굵기 파일에 글자 모양이 있어 글꼴, 굵기, 배포본이 달라도 기호가 빠지지 않음. □, ○, ㆍ, ※는 한 글꼴 안에서 폭이 같아(나눔고딕은 글자 크기의 0.94배, 나눔바른고딕은 0.89배) 글머리 뒤 본문 시작선이 계위마다 흔들리지 않음
- (셀 글머리 기호) 10pt 셀 글자 옆에서 ○(지름이 글자 크기의 0.75배)는 커 보이므로 셀 글머리는 지름 0.53배인 ◦(U+25E6)를 씀. 글자 폭은 ○와 같아 본문 시작선은 바뀌지 않음
- (나눔고딕과 나눔바른고딕) 한자가 많은 보고서에서 한자가 빈칸이나 다른 글꼴로 찍히지 않게 하기 위해 선택. 두 글꼴의 네이버 배포본은 모든 굵기에 KS X 1001 한자 4,620자와 호환 한자 268자의 글자 모양을 담음. 나눔명조는 한자가 없고 나눔스퀘어는 한자 코드만 있고 글자 모양이 비어 있어 쓰지 않음. flat 제목은 서체를 달리하여 chapter 제목과 구분
- (나눔글꼴) SIL Open Font License 1.1 무료 글꼴이라 한/글과 Word 어느 환경에서나 라이선스 비용 없이 설치하여 문서를 같은 모양으로 열 수 있음. 나눔고딕과 나눔바른고딕 모두 한국저작권위원회 공유마당이 안심글꼴로 제공
- (표 폭 상한) 가용 폭 전체를 쓰면 표 좌측이 본문 시작선 밖으로 돌출하므로 계위 들여쓰기만큼 줄임
- (열 단위 정렬) 셀 단위로 판정하면 같은 열 안에서 숫자 셀, 서술 셀, 짧은 셀의 정렬이 갈리므로 열 단위로 정함
- (원고 정렬 표기) 열 정렬은 표 안에서 열이 하는 역할로 정해짐. 연도 2005와 금액 2,005처럼 셀 글자의 숫자 모양이 같아도 역할은 다를 수 있음. 표 전체를 보는 원고 작성자가 표기로 정렬을 정함
- (기본 정렬) 사람이 작성한 보고서 표에서 글머리 외 텍스트 열은 대부분 가운데 정렬. 좌측 정렬은 내용, 세부 내용 같은 서술형 설명 열에 주로 나타남. 글자 수로는 이 열을 가려낼 수 없음. 표기가 없는 열은 글머리 열만 좌측에 둠
- (캡션 개체와 자동번호) 한/글에서 표를 옮기면 캡션이 따라가고 번호가 갱신됨. DOCX의 번호 필드도 같은 목적
- (표 안 부속 행) 단위 행과 출처 행을 표 안 투명 셀로 두어 손으로 편집할 때 표와 함께 이동
- (표 바깥선) 본문과 표의 경계를 부드럽게 보이게 하려고 좌우 바깥선을 비움. 바깥선이 필요하면 EDGE_OPEN_SIDES를 False로 변경
- (코드 생성 양식) 스타일, 글꼴, 글머리, 개요 번호의 참조 관계를 한 정의(form.py)에서 만들어 참조 누락을 막음. 글머리 정의의 참조 하나가 빠져도 한/글이 기호를 생략하며 이런 결손은 본문 텍스트 검증으로 드러나지 않음
- (원고 해석 모듈) 원고 해석과 표, 그림 계산을 manuscript.py 한 모듈에 둠. HWPX와 DOCX 조판 모듈이 같은 병합, 정렬, 폭 계산을 쓰므로 규범 수정이 한곳에서 끝남
- (목차 쪽번호 재대조) 쪽번호 기입으로 목차나 본문 배치가 바뀌는 경우를 잡아냄
- (DOCX 언어 태그) 라틴 언어를 ko-KR로 두면 LibreOffice가 `3,456,789` 같은 숫자 중간에서 줄을 바꿈
- (DOCX 목차 책갈피) 결과 문자열만 미리 채운 목차는 Word에서 필드를 갱신할 때 쪽번호가 모두 1로 바뀌는 사례가 있었음. Word가 만드는 목차와 같은 구조로 두어 갱신 방식과 관계없이 제목 위치로 쪽번호를 다시 계산하게 함
