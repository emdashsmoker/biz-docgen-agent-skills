# 과업 유형별 모듈 골격

## 적용 규칙

- 읽는 시점은 3단계 구성 확정 전의 수행계획 설계 단계
- 읽는 범위는 과업 유형에 해당하는 절
- RFP 과업 세부내용이 골격보다 우선
- RFP 가 요구하지 않는 단계는 생략 가능
- 환경분석 모듈은 전략 수립 모듈보다 앞에 배치
- 복합 과업은 모듈 단위로 유형을 섞어 구성
- 절마다 기재한 대응 구성은 `references/recipes.md` 의 레시피 이름과 `references/templates.md` 의 템플릿 이름
- 골격의 적용 방식은 과업의 제도 적용 수준에 따라 다름
    + (제도 기반) 국가연구개발 성과평가 대응, 사업기획점검 대응, R&D 사업기획은 유형별 골격을 기본값으로 적용 (제도가 골격과 워딩을 정함)
    + (조건부 제도) 정보화는 법정 ISP 대상이면 제도 절차를 적용
    + (재량) 경영전략, 조직진단, 신사업 발굴, 시설 타당성, 지원사업 성과분석, 문제해결은 유형별 골격을 참고 예시로 사용 (발주기관과 과업마다 구조가 다름)
- 법정 ISP 대상은 일정 금액 이상 정보시스템 구축의 사전 ISP
- 법정 ISP 대상 여부는 근거 법령, 사업비 규모, 산출물 목록으로 판별
- 법정 ISP 대상은 한국지능정보사회진흥원(NIA)의 ISP·ISMP 수립 공통가이드 절차와 산출물 명칭을 그대로 사용 (착수 시 최신판 확인)
- 법정 대상 밖 IT 기획은 발주기관 요구에 맞춰 모듈을 구성
- 재량 과업의 모듈과 Task 는 RFP 과업 세부내용과 핵심이슈에서 도출
- 재량 과업에서 예시 골격의 모듈명을 그대로 쓰면 변별력 결함
    + 워딩 트랙 mgmt 와 general 에서 `meta.rfp.moduleTasks` 의 title 이 예시 모듈명과 같으면 lint WARN
    + RFP 가 정한 명칭이면 해당 항목에 `rfpNamed: true` 를 지정

## 유형 판별

| 유형 | RFP 신호 | 대표 산출물 |
|---|---|---|
| 전략기획 | 중장기 계획, 기본계획, 발전전략, 육성계획, 비전, 로드맵 | 비전체계도, 전략과제, 로드맵 |
| 사업기획 | 신규사업 기획, 사전기획, 상세기획, 타당성, 사업기획점검 대응, 기획보고서, R&D 예산의 기획연구 과제 | 기획보고서, 논리모형, 목표와 지표 체계 |
| 성과분석과 평가 | 성과분석, 성과평가 대응, 자체평가, 경영평가, 지표 개발, 평가 제도 개선 | 성과분석보고서, 자체평가보고서, 지표 체계 |
| 문제해결 | 실태조사, 동향조사, 수요조사, 과제 발굴, 개선방안, 제도 개선, 프로세스 개선, 서비스 개선 | 현황 진단 결과, 개선안, 과제 후보군 |
| 정보화 | ISP, ISMP, 지능정보사회 기본계획, 정보화전략계획, 시스템 구축 기획 | 목표 시스템 구성도, 이행계획, 예산 산정 |
| 지원사업 운영 | 기업지원 프로그램 운영, 사업화 지원, 창업지원, 인력양성 운영기관 공모 | 프로그램 설계서, 성과지표와 증빙, 사업비 집행계획 |
| 연구개발계획 발표 | 국가연구개발 신규과제 공모(지정공모, 품목지정, 자유공모), 연구개발계획서 발표평가 | 연구개발계획서, 연차별 목표와 평가지표, 추진체계, 연구개발비 |
| 비R&D 공모 발표 | 실증 사업, 컨설팅 사업, 바우처 사업, 수요기반 지원사업, 컨소시엄 공모 | 사업계획서, 수행부문별 계획, 성과지표, 사업비 |

- 민간 사업기획, 서비스 기획, 사내 보고도 같은 표로 유형을 판별
- 신규 사업, 서비스, 제품 기획은 사업기획 골격을 적용
- 사업기획 골격의 모듈명은 대상에 맞게 조정
- 서비스 기획은 M1 시장과 사용자 조사, M2 경쟁과 사례 분석, M3 서비스 모델과 기능 정의, M4 사업성과 실행계획 순서로 변형
- IT 기획은 정보화 골격에서 법정 ISP 절차를 제외한 M1 현황과 요구 분석, M2 목표 시스템 설계, M3 구축과 운영 계획으로 변형
- RFP 신호에 해당하지 않는 과업은 과업이 요구하는 사고의 출발점으로 판정
    + 목표 상태의 정의를 요구하는 과업은 전략기획 골격이 기본값
    + 현행 문제의 원인 규명을 요구하는 과업은 문제해결 골격이 기본값
    + 기본값 적용 후 모듈은 RFP 과업 세부내용에 맞춰 교체

## 공통 규범

- 모듈 도입부는 모듈 개요 슬라이드
- 모듈 개요의 열은 Task, 행은 추진과정, 활용 자료, 산출물
- 산출물 행에는 산출물의 정식 명칭을 기재
- Task 마다 활용 자료, 조사 규모, 산출물을 특정
- Task 마다 실측 표본을 1개 이상 배치
- 표본 유형은 실제 데이터 표, 실제 도구 화면(NTIS, KOSIS, 특허 DB, 기업정보시스템), 사례 요약 중 1개
- 표본에는 시안임을 ※ 로 표기
- 과제와 수요의 입력 경로는 RFP 에 맞춰 확정
- 입력 경로는 수요조사(기획서형 설문), 인식조사(척도 설문), 전문가 참여(FGI, 델파이, 자문위원회), 직접 도출(문헌) 중 1개
- 직접 도출을 단독으로 쓰면 검증 절차를 병행
- 방법론명은 RFP 가 요구한 기법(SWOT, AHP, 델파이, 논리모형 등)만 표기
- RFP 가 요구하지 않은 기법은 방법론명 없이 수행 내용으로 서술
- 자문위원회 후보(안) 표에는 발주기관 협의 후 확정 부기를 붙임 (관행)

## 전략기획

```
M1 대내외 환경분석      정책, 시장, 기술 동향. 사실만 서술. 전망과 대안은 M3 이후에 배치
M2 내부현황과 사례분석  대상 지역과 조직의 여건 진단, 국내외 선진사례. 기관 소개성 현황과 역량 진단을 분리
M3 시사점과 전략체계     시사점 종합, SWOT 또는 갭 분석, 비전과 목표와 전략
M4 실행계획              실행과제 발굴, 우선순위(필요성, 시급성, 실현가능성), 단기와 중장기 로드맵, 파급효과
```

- (SWOT 요인 출처) 내부현황 시사점은 강점과 약점에만 배치
- (SWOT 요인 출처) 외부환경 시사점은 기회와 위협에만 배치
- (SWOT 요인 출처) 사례분석 시사점은 강점, 약점, 기회, 위협 모두에 배치 가능
- (SWOT 조합) SO 전략은 S 요인과 O 요인만 결합
- (수직 정렬) 비전, 목표, 전략, 전략과제, 실행과제, 성과지표는 번호 계승(1. 전략, 1-1. 전략과제, 1-1-1. 실행과제)으로 연결
- (상하위 연결) 비전부터 성과지표까지 각 항목은 인접 계층의 항목과 1개 이상 연결
- (시사점 연결) 모든 시사점은 1개 이상의 과제로 이어지게 배치
- (분석 구성) M1 은 정치, 경제, 사회, 기술 영역의 동향과 기회, 위협을 핵심 아젠다 1문장으로 종합 (pest_scan)
- (경과 구성) M1 은 정책 추진 경과를 시간순으로 정리 (history_timeline)
- (사례 구성) M2 사례분석은 사례를 같은 비교 항목(개요, 추진 방식, 성과 수치, 성과 요인)으로 대조 (benchmark_cases)
- (사례 종합) 사례별 성과 요인은 적용 방향 1문장과 방향별 적용 과제로 종합
- (종합 구성) M3 도입부에 영역별 시사점을 전략 이슈로 모으는 분석 종합 1장을 배치 (findings_synthesis)
- (과제 선별) M4 과제 발굴은 수집 경로별 후보 건수에서 최종 과제 수까지 단계별 대상 수, 선별 기준, 방법과 참여 주체를 제시 (task_funnel)
- (예산 전개) 종합 시행계획은 실행과제별 단기, 중기, 장기 예산과 합계, 재원별 분담 비율을 표로 제시
- 지역 산업 육성 과업은 산업 특화도(입지계수), 기업 수요조사, 앵커 기관과 수요처 접근성, 인력 공급 기반을 M2 에서 다룸
- 파급효과는 산업연관분석(생산유발, 부가가치유발, 취업유발)이 관행
- 산업연관분석은 계수 출처와 상품군 배분 근거를 병기
- (경영전략과 조직진단 복합 과업의 관행) 공공기관 중장기 경영전략 과업은 경영전략, 조직진단, 경영효율화를 함께 다룸
    + 미션과 비전 재설정 앞에 현행 전략체계를 진단 기준(적합성, 연계성, 타당성, 현실성)으로 평가 (strategy_review)
    + 중장기 경영전략은 환경분석, 미션과 비전과 핵심가치 재설정, 발전전략, 전략과제와 실행과제의 부서 단위 전개, 우선순위와 추진시기, 연도별 성과지표로 구성
    + 조직진단과 재설계는 직무분석, 업무량 조사(양적 분석, 질적 분석), 적정 정원 산정과 배분, 조직구조 개편안, 위임전결 개선으로 구성
    + 조직진단의 진행 순서는 직무분석, 통솔범위 분석, 유사기관 벤치마킹, 재설계안, 단계별 이행안
    + 직무분석과 인력 산정 슬라이드는 구성원 참여(설명회, 면담, 워크숍)와 검증 절차(담당자 확인, 관리자 검토, 내용전문가 검증)를 함께 제시
    + 부서별 인력 규모는 부서 검증과 협의를 거친 결과로 제시
    + 제안 단계의 인력 산정표는 부서 A, 부서 B 같은 일반 명칭과 양식 예시 표기로 작성
    + 경영효율화는 사업 포트폴리오, 경영평가 지표 개선, ESG, 정부의 공공기관 혁신 방향 반영으로 구성
    + 경영평가 지표 개선에는 `references/wording.md` 의 경영평가 열 워딩을 사용
- (비R&D 신사업 발굴 관행) 과업의 이해에서 도출한 핵심이슈와 해결방향을 과업별 접근의 근거로 제시
    + 과업의 이해는 발주기관 개요, 대상 사업 현황, 상위계획, 대상지 현황, 여건의 불확실성으로 구성
    + 신사업 발굴은 업의 재정의, Long List, 1차 스크린(시장매력성, 발주기관 적합성, 재무 타당성), 2차 스크린 지표, 신규사업 평가, 세부 사업추진계획서로 좁혀 가는 깔때기 구조
    + 활성화 방안은 개발 전 시나리오와 개발 후 시나리오로 분리
- (대응 구성) module_overview, pest_scan, history_timeline, benchmark_cases, findings_synthesis, strategy_derivation, strategy_review, env_to_strategy, swot, vision_system, goal_hierarchy, task_funnel, priority_matrix, option_evaluation, roadmap, task_definition, pdca_cycle, impact_io
- (조직진단 대응 구성) job_analysis, workforce_estimation, raci_matrix, gap_analysis, org_redesign, option_evaluation, financial_feasibility, compare
- 조직 개편안과 운영 방식 대안은 대안별 개요와 같은 평가 기준의 비교 결과로 선정 (option_evaluation)

## 사업기획

```
M1 정책과 환경 분석      상위계획 부합성, 정책과 기술 동향, 문제와 이슈 도출
M2 기존 사업과 사례 분석  유사 사업 검토, 중복성과 차별성, 선행 기획의 지적사항
M3 목표 체계와 논리모형   목적, 목표, 성과지표의 목표체계와 논리모형, 세부활동 정렬 점검
M4 타당성 확보            추진체계, 재원 조달, 법제도 위험, 비용 추정과 경제성 분석
M5 심사와 보고 대응       기획보고서 작성, 대면회의와 질의 대응 (RFP 가 요구할 때만)
```

- (신청형 변형) 신청 기관이 작성하는 사업계획(기업 R&D 과제, 상용화 지원사업, 컨소시엄 신청)은 같은 골격에서 모듈별 내용을 조정
    + M1 에는 시장 동향, 정책 동향, 미해결 지점을 배치 (상위계획 부합성은 축약)
    + M2 에는 대상 제품과 기술의 우수성을 성능 수치와 비교 대상으로 제시
    + M3 에는 참여 기관별 역할, 보유 역량, 협업 구조를 배치
    + M4 에는 단계별 검증 계획, 인허가와 제도 진입 경로, 확산 방안을 배치
    + M5 에는 추진 일정, 목표 관리(PDM), 성과지표(KPI), 비목별 예산과 연차 집행계획을 배치
    + KPI 는 정량 지표로 설정

    + 기획위원회는 전문성, 포괄성, 균형성(산학연, 지역, 소속기관) 기준으로 구성
- (비R&D 시설 기본계획과 타당성 조사 관행) 전문과학관 등 공공시설 과업은 현황 진단부터 파급효과까지 순차 전개
    + 현황 진단은 법령과 상위계획(관련법 조항, 중앙부처 기본계획 주기), 국내 시설 현황 통계, 국내외 사례 4-5건(지역 특성 반영 사례, 공모 선정 사례), 지역 여건(공약, 주력산업, 기존 시설 현황)으로 구성

- (법정 대상에서 제도가 정하는 부분) 4단계 골격(환경분석, 현황분석, 목표모델 설계, 통합 이행계획), 요건 분류 체계, 예산 산정 기준(소프트웨어 사업 대가 산정 가이드), 공공 정보화 보안 설계(국가망보안체계 등급 분류)
- (법정 대상에서도 재량인 부분) 모듈 명칭과 분할 방식, Task 구성, 조사 설계, 목표모델의 상세 수준, 이행과제 우선순위 기준
- (법정 대상 밖 IT 기획) 발주기관이 요구한 범위로 모듈과 Task 를 구성
- 법정 대상 밖 IT 기획의 산출물 명칭은 RFP 표기를 사용
- 4단계 골격은 법정 대상 과업의 기본값
- 법정 대상 밖 과업에서 4단계 골격은 참고 예시
- 현황분석은 As-Is 와 To-Be 대비표로 격차를 명시
- 업무절차맵과 To-Be 업무프로세스는 순서도 기호(`flowchart` 블록)로 표현
- 요건은 기능적, 비기능적, 기술적, 프로젝트 지원 요건으로 구분하여 ID 를 부여
- 산출물명의 요구사항과 요건 표기는 가이드 원문을 그대로 사용 (예: 업무 요구사항 분석서, 정보시스템 요건 기술서)
- 예산 산정은 소프트웨어 사업 대가 산정 가이드 등 공인 기준의 명칭과 연도를 밝힌 산정 근거표로 제시
- 순수 소프트웨어 개발 사업은 정보화 골격의 적용 범위 밖
- (정보화 제안 관행) ISP 제안요약서의 통상 장 구성은 전략 및 방법론, 프로젝트 수행, 프로젝트 관리, 프로젝트 지원
    + 전략 및 방법론은 사업 이해도, 추진 전략, 방법론으로 구성
    + 프로젝트 수행은 조직과 인력, 수행방안으로 구성
    + 프로젝트 지원은 품질보증과 기밀보안으로 구성
    + 사업 이해도는 정책 환경, 발주기관 데이터 현황, 발주기관 제약(보안, 데이터, 거버넌스), As-Is 와 To-Be 의 슬라이드 4장
    + 추진전략은 사업 특성과 위험 요인에서 핵심성공요인을 거쳐 도출
    + 전략마다 슬라이드 1장을 배치
    + 전략 슬라이드는 STEP 4단 카드와 Sample 예시로 구성
- (표준 산출물명) ISP·ISMP 수립 공통가이드 제9판의 산출물명을 사용
    + (ISP 예시) 경영환경 분석서, 법·제도 분석서, 업무현황 분석서, 차이 분석서, 정보화 전략 정의서, To-Be 업무프로세스 설계서, To-Be 정보시스템 구조 설계서, To-Be 데이터 구조 설계서, To-Be 기술 및 보안 구조 설계서, 통합 이행계획 수립서
    + (ISMP 예시) 업무 요구사항 분석서, 정보기술 요구사항 분석서, 요구사항 연관표, 정보시스템 요건 기술서
- RFP 가 정한 명칭이 표준 산출물명보다 우선
- 요구사항 분류 ID 코드는 RFP 마다 다름
    + SYR, FUR, PER, SER, QUR, SIR, UIR, DAR, SOR, COR 는 형식 예시
    + 발주기관이 지정한 코드가 형식 예시보다 우선
    + RFP 의 요구사항 코드는 00_rfp.md 핵심 워딩에 등록하여 그대로 사용
    + RFP 에 코드가 없으면 분류명만 사용
- 공공 정보화의 보안 설계는 국가망보안체계(N2SF)의 등급 분류(기밀 C, 민감 S, 공개 O)와 적용 절차(준비, 등급분류, 위협식별, 보안대책 수립, 적절성 평가와 조정)의 워딩을 그대로 사용
- 등급별 보안대책(망분리, 웹격리, 반입문서 무해화, 유출 차단, 접근권한)은 발주기관 보안 지침의 표기를 우선
- 이행계획은 이행과제 정의, 로드맵, 규모 산정과 예산(대가산정 가이드 연도 명시), 구축 사업계획(분리발주 검토, 제안요청서)으로 구성
- PoC 는 목표 설정, 데이터 준비, 모델 선택과 환경, 시범서비스와 성능분석의 Round 구조로 구성
- 성능 조건(동시 접속, 처리량)은 수치로 병기
- (대응 구성) process_redesign, target_model, requirements, system_architecture, data_management, poc_plan, operation_governance, survey_design, priority_matrix, compare, roadmap

## 지원사업 운영 (기업지원, 사업화, 창업, 인력양성 운영기관)

```
M1 정책과 사업 배경     상위 정책과 근거 사업, 지역과 분야 여건, 사업 목적
M2 수요자 현황과 애로   대상 기업과 대상자 현황 통계, 실태조사와 설문, 애로와 요청 사항
M3 프로그램 설계        진단과 선발, 교육, 컨설팅, 네트워킹, 판로와 투자 연계
M4 성과관리             성과목표 체계, 성과지표와 목표값, 증빙과 점검 방식
M5 운영과 집행          추진체계와 인력, 연간 일정, 사업비 편성과 집행계획

- 성과지표 표의 열은 구분, 성과지표, 중간목표, 최종목표(누적), 증빙내역
- 지표는 산출(건수, 개사)과 성과(매출, 투자유치, 고용)를 구분하여 배치
- 사업비는 항목별 편성표와 분기별 집행계획으로 제시

## 연구개발계획 발표 (국가연구개발 신규과제 공모)

```
1 필요성            배경과 정책 동향, 기술 현황과 문제점, 파급효과
2 목표와 내용        최종목표, 단계별과 연차별 목표, 평가항목과 평가지표, 연차별 연구내용
3 추진전략과 체계     추진 전략, 컨소시엄 구성과 기관별 역할, 협업과 위험 관리
4 연구수행 역량      주관과 참여 기관 역량, 연구책임자와 참여 연구자 실적, 보유 인프라
5 활용과 사업화       성과 활용 방안, 사업화 전략, 기대효과
6 연구개발비와 보안   비목별 연구개발비, 안전과 보안조치 이행계획
```

- 번호는 계획서 항목의 장 번호
- 절 구조는 계획서 장 구조를 사용
- 수행 단위는 연차와 세부과제이므로 절 제목은 `[1차년도]`, `[세부과제 1]` 형식
- 기술개발 과제의 대응 검사는 계획서 항목 전수 대응 (`meta.structure` 값 plan)
- 계획서 항목은 `meta.rfp.tasks` 에 등재하고 슬라이드의 `rfpTasks` 로 대응
- 대응 슬라이드가 없는 계획서 항목은 lint FAIL
- (기획연구 예외) R&D 예산과 제도로 발주된 조사와 기획 과제(기술개발사업 기획연구, 사전기획, 상세기획)는 수행 내용을 모듈과 Task 로 설계
    + 서류 양식과 목차는 연구개발계획서를 따름
    + 내용 설계는 사업기획 골격(M1 정책과 환경 분석, M2 기존 사업과 사례 분석, M3 목표 체계와 논리모형, M4 타당성 확보)을 사용
    + 모듈과 Task 는 계획서의 연구내용 항목 안에 배치
    + 모듈 개요와 Task 전수 대응 규칙을 적용
    + 판별 신호는 과업명의 기획연구, 사전기획, 상세기획, 기획과제 표기와 기획보고서 산출물
- 발표 구성은 RFP 와 평가표의 항목 순서를 그대로 따름
- 목차의 장과 절은 제도가 정한 계획서 항목이므로 계획서 항목 전체를 그대로 배치
- 연차별 내용은 사업 기간의 모든 연차를 배치
- 슬라이드마다 연구개발계획서의 대응 쪽 번호를 표기
- 최종목표는 정량 평가지표(항목, 단위, 목표값, 측정 방법, 세계 최고 수준 대비)로 제시
- 연차별 목표는 단계와 연차를 표 1개에 두어 성과물과 연결
- 컨소시엄은 주관 기관과 공동 기관을 번호로 구분
- 기관별 담당 과업과 참여 연구자는 함께 표기
- 이전 평가를 받은 과제는 지적 사항과 반영 결과의 대조표를 배치
- 대조표에는 반영 슬라이드 번호를 병기
- 기술 수준은 비교 대상(국내외 선도 기관, 경쟁 플랫폼)과 수치로 대비
- 연구개발비는 비목별 편성과 연차별 집행으로 제시
- 인건비와 연구시설비는 산출 근거를 병기
- 보안과제는 보안등급, 접근 통제, 자료 관리 절차를 별도 슬라이드로 배치

## 비R&D 공모 발표 (실증, 컨설팅, 바우처, 수요기반 지원사업)

```
1 사업 개요        추진 배경, 사업 목표와 범위, 추진 전략, 제안의 특징
