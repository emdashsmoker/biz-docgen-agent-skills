# 텍스트 규범

## 문장

- 1문장에 1메시지
- 5W1H 각 요소는 문장 안에 1회
- 연결어(그리고, 그러나, 하며, 이는)와 복문은 문장 분리로 해소
- 쉼표는 항목 나열에 사용
- 나열 쉼표는 생략 없이 표기
- 본문은 명사형 종결
- 관형형이 남은 형태("달성할 필요")는 명사구("달성 필요")로 교정
- 서술어를 자른 형태("수립하는 것을 목적")는 문법 오류
- 서술어를 자른 문장은 "수립을 목적으로 추진" 형태로 재작성 (`references/headline-patterns.md` 명사형 변환 규칙)
- 헤드라인 문체는 착수 질의 5번에서 선택 (명사형 기본, 존댓말 선택 가능)
- 존댓말 헤드라인은 하십시오체로 종결 (예: "수립합니다", "확보합니다", "보유하고 있습니다", "추진하겠습니다" 등)
- 본문 문체는 헤드라인 문체와 관계없이 명사형
- 헤드라인과 본문에는 구어체를 쓰지 않음
- 구어체 표지는 추측과 완곡 종결(-듯, -듯함, -인 셈, -하는 편, -할 만함, -로 봄, -로 보임, -로 여겨짐), 설명체 어미(-는데, -인데, -더라, -거든, -잖아), 구어 축약(-하는 게, -할 거, -한 걸, -하는 건), 구어 부사(일단, 약간, 좀, 꽤, 딱, 그냥, 나름) 등
- 구어체 표지는 삭제하거나 격식 표현으로 교체
- 헤드라인 상한은 1줄 50자, 2줄 100자 (50자 초과는 lint WARN, 100자 초과는 lint FAIL)
- A4 판형의 1줄 상한은 43자, 10.83×7.5 판형은 40자, 4:3 판형은 37자 (2줄 상한은 1줄 상한의 2배)
- 글자 수 상한은 한글 환산 글자 수로 적용 (문구 폭을 한글 1자 폭으로 나눈 값. 영문과 공백은 폭만큼 적게 셈)
- 헤드라인은 결론 문장으로 작성 (lint 는 "추진배경" 처럼 공백 없는 2-12자 주제 라벨을 WARN)

## lint FAIL 표현

- em dash 와 en dash
- 대비 구문("X가 아닌 Y")
- 숫자 선언(숫자와 "대" 뒤에 전략, 방안, 과제, 축, 원칙, 목표, 영역이 오는 표현. 예: "3대 전략")
    + (예외) RFP 가 지정한 개수는 슬라이드의 `allowCount` 필드로 숫자 선언 검사에서 제외
- 의미 공백 표현(이러한 맥락에서, 시사하는 바가 큼, 주지하다시피, 말할 것도 없이)
- 과장 수식어(획기적, 혁신적인, 압도적, 매우, 탁월한)
- 메타 서술(본 절에서는, 앞서 제시한, 앞에서 살펴본, 다음 슬라이드에서)
- 평가 내부 어휘(배점, 채점, 방어 논리, 결정 장소, 귀속)
- 대응 선언("누락 없이 반영", "빠짐없이 반영")
- 연결어(그리고, 그러나, 하지만, 그러므로, 그렇기 때문에, 이는)
- 서술어를 자른 명사형("수립하는 것을 목적")
- 본문의 존댓말 종결(합니다, 입니다, 됩니다, 습니다, 십시오)
- 선택한 헤드라인 문체와 다른 헤드라인 종결
- 치환하지 않은 문형 자리(`{{ }}`)
- RFP 핵심 워딩(과업명, 산출물명, 단계명, 대상 명칭)의 변형 (`meta.rfp.wording` 등록 시)

## 검수 확인 표현

- lint 가 검사하지 않는 표현은 심층 검토와 시각 검수에서 확인
    + 자문자답
    + 프레임워크명 노출(MECE, 피라미드)
    + 대상 지칭어의 절마다 반복("본 과업은")
    + 발주기관 정책과 RFP 의 미비를 시사하는 문장 (긍정 서술로 전환)
    + 구어체 표지 ("문장" 절의 목록 기준으로 교정)
    + 두 명사를 "와", "과" 로 이은 나열 ("및" 으로 전환)

## lint WARN 어휘

- 맥락, 패러다임, 인사이트, 함의, 축, 층위, 정립, 선제, 선점, 게이트, 매핑, 컨틴전시, 딥다이브
- 검사 대상은 앞뒤에 다른 한글이 붙지 않은 단어

## 내용 구성

- 분류 기준은 단일 차원
- 분류 항목은 상호배제와 전체포괄을 충족
- 동일 계층 항목은 3-4개 권장
- 5개를 넘는 항목은 그룹으로 묶음
- 슬라이드 1장에 1메시지
- 메시지를 지지하는 구성요소는 3-4개 이하
- 백화점식 나열은 슬라이드 분리로 해소
- Task 묶음 슬라이드의 메시지는 모듈 수준 1문장
- Task 묶음 슬라이드에서 Task 는 메시지의 구성요소
- 상자와 표 셀의 항목은 1개 항목을 1줄에 담음
- 항목이 2줄이 되면 글자 수를 줄임
- 넘칠 때 줄이는 대상은 글자 수와 항목 수 (글꼴 크기 유지)
- 상자가 크면 항목 수를 늘리기 전에 항목별 서술의 구체성부터 검토
- 배경과 목적의 리드는 제목 1문장과 근거 2-3항목으로 구성
- 상자 하나에 항목이 1-2개뿐이면 항목을 보강하여 채움 비율 70% 를 확보
- 불릿 항목 문구는 상자 폭 한 줄의 80-95% 길이로 작성 (가장 긴 글줄이 80% 미만이면 모든 줄의 오른쪽이 비어 보임)
- 종합 상자 항목 문구는 한 줄의 90-100% 를 채우는 비슷한 길이로 작성 (판정 기준은 SKILL.md 디자인 시스템의 가로 채움)
- 표 셀 문구에는 대상, 기준, 수치 가운데 필요한 정보를 병기 (열 폭을 채우는 분량)
- 보강할 내용이 없으면 상자를 줄여 가운데로 모음
- 축소 후에도 어색하면 표현 형식을 바꾸거나 인접 상자와 합침
- 수행 Point 밴드는 헤드라인과 본문에 없는 판단 기준, 산식, 후속 연계, 선정 사유, 적용 시점, 원칙을 담을 때만 작성
- 헤드라인 반복이나 본문 요약만 담은 밴드는 삭제
- 한 줄짜리 산식이나 단서는 `footnotes` 에 기재

## 표기

- 긴 명칭은 어절 단위로 띄어 씀 (상자 안쪽 폭보다 넓은 어절은 중간이 잘림)
- 두 명사의 나열은 라벨, 헤드라인, 본문 모두 "및" 으로 연결 (예: 전략과제 및 세부과제)
    + (예외) RFP 원문 명칭(과업명, 산출물명, 단계명, 대상 명칭)은 원문 표기를 유지
    + (예외) 분야에서 굳어진 관용 명칭은 관용 표기를 유지 (예: BSC 관점명 "학습과 성장")
    + (예외) 두 명사 사이의 관계(사이, 간, 격차, 차이, 일치, 불일치, 연계, 연동, 정렬, 비교, 구분, 분리, 협력)를 나타내는 "와", "과"는 유지 (예: 현행과 기준의 격차, 성과지표와 성과목표의 연계)
    + (예외) 동작의 상대를 나타내는 "와", "과"는 유지 (예: 발주기관과 공유, 사유와 함께 관리, 지역 대학과 공동 운영)
- 절 번호는 숫자와 마침표로 표기 (예: "1.")
- 절 번호의 마침표는 빌더가 자동 보정
- 번호와 기호는 1번만 표기
- 빌더가 붙이는 번호와 기호는 텍스트에서 생략
    + section 은 secNo 의 번호("1.") 없이 작성
    + 슬롯 텍스트는 "-" 나 "·" 같은 기호 없이 작성 (불릿은 빌더가 조판)
    + steps 의 title 은 "STEP 1." 같은 접두 없이 작성 (접두가 필요 없으면 stepLabel 을 "")
    + 번호 계승(1-1.)을 적는 grid 칸은 numbered 를 지정하여 번호가 불릿을 대신하게 함
    + process 의 모듈명은 "M1" 같은 번호 없이 작성 (모듈 번호는 id 필드)
    + 마커가 있는 슬라이드의 본문 첫 줄은 마커와 다른 내용으로 시작
- 기호 반복 규칙의 대상은 직접 입력한 기호 (빌더가 그리는 불릿은 유지)
- 항목이 2개 이상이면 불릿을 유지
- 하위 항목(sub)이 딸린 항목은 1개여도 목록으로 셈 (항목 2개 이상과 같이 불릿 유지)
- 항목이 1개이면 줄바꿈으로 여러 줄이 되어도 불릿 없는 문장으로 표기
    + (표 셀) 아래 표 절의 비교 줄 조건이나 표 전체 조건으로 불릿을 추가한 줄은 예외
    + (모듈 개요 슬라이드) 추진과정, 활용자료, 산출물 상자는 예외로 불릿 표기 (두 조건이 늘 성립하는 표로 봄)
- 같은 계층 항목은 번호와 기호의 유무를 통일
- 출처가 여럿이면 세미콜론으로 이어 한 줄로 표기 (`source` 배열은 자동 결합)
- 출처(`source`, `factSource`)의 문헌 제목과 자료명은 원문 그대로 인용 (em dash 와 en dash 만 하이픈으로 교체)
- 주석과 출처는 ※ 로 시작 (source 와 note 계열 슬롯은 빌드가 자동 부착, 본문 칸에 직접 쓴 주석은 수동 부착)
- ※ 는 근거, 출처, 전제, 단서에만 사용
- 근거와 단서는 note 슬롯이나 footnotes 에 기재하여 ※ 자동 부착을 활용
- 견본 슬라이드의 ※ 문단은 예시 자리
    + 주석으로 쓰면 ※ 로 시작
    + 일반 항목으로 쓰면 ※ 없이 작성
- 본문을 줄여 쓴 문장, 항목 설명, 라벨은 ※ 없이 같은 계층의 글꼴 크기에 맞춤
- 한 상자 안 불릿은 모두 같은 글꼴 크기를 사용
- 대상 지칭어 규칙은 `references/headline-patterns.md` 대상 지칭어 절을 따름
- 모듈 절 제목은 `[Module 1] 모듈명` 형식 (절 번호 뒤 마침표와 겹침 방지)
- Task 마커는 `Task 2. Task명` 형식
- 조직도와 목차의 모듈 항목도 `[Module 1] 모듈명` 형식

## 표

- 셀 1개에 항목이 둘 이상이면 셀 내용과 표 전체를 보고 불릿과 쉼표 나열 중 읽기 쉬운 쪽을 선택
- 선택 기본값은 짧은 명사구의 쉼표 나열, 서술형 항목의 불릿
- 비교 줄은 같은 속성을 대상별로 나란히 놓은 셀 줄. 대상이 열에 놓인 표(모듈 개요표, 대안 비교표)는 행, 대상이 행에 놓인 표(수행실적 표 등)는 열이 비교 줄
- 한 비교 줄의 표기 방식 통일 여부는 그 줄 셀들의 성격을 대조하여 판단
- 불릿 표기를 고른 셀은 항목마다 불릿. 항목 1개는 줄바꿈으로 여러 줄이 되어도 불릿 없음
- 항목 1개 셀의 불릿은 비교 줄 단위로 판정
    + (비교 줄 조건) 한 비교 줄에서 항목 2개 이상 셀이 절반 이상이면 그 줄의 항목 1개 셀에도 모두 불릿. 셀 수에서 머리글 행과 구분 열은 제외
    + (표 전체 조건) 불릿을 붙인 줄이 표의 목록형 줄 대부분이면 남은 목록형 줄에도 줄 전체로 불릿을 붙일 수 있음. 판단 기준은 표 전체의 읽기 편의. 목록형 줄은 셀 하나에 항목이 여러 개 들어갈 수 있는 줄(금액, 기간, 연도처럼 셀마다 값이 하나인 줄은 제외)
    + (줄 단위 적용) 불릿 추가는 줄 전체에 적용. 불릿을 추가한 줄 안에서는 불릿 유무를 섞지 않음
    + (맥락 판단) 위 조건이 모든 표에 기계적으로 들어맞지는 않음. 최종 판단은 표 전체의 맥락을 보고 내림
    + (모듈 개요표) 두 조건이 늘 성립하는 표로 보아 세 행 모두 불릿 (빌더가 자동 적용)
- 불릿을 추가할 줄은 storyboard 작성 단계에서 판정하여 `bulletRows`, `bulletCols` 로 지정 (형식은 `references/templates.md` 표 조판)
- 가로 정렬은 열 단위로 통일
- 열 정렬은 표 전체를 보고 열이 표 안에서 하는 역할로 판정
    + (수량 열) 금액, 개수, 비율, 점수, 가중치 등 숫자와 단위로 된 열은 자릿수 비교가 쉽도록 우측 정렬
    + (한 덩어리로 읽는 열) 분류, 이름, 연도, 연번, 기간, 산식, 짧은 문구 등 셀을 하나의 표현으로 읽는 열은 가운데 정렬
    + (줄을 따라 읽는 열) 불릿 목록, 진단 질문, 서술형 설명(내용, 세부 내용, 주요 활동 열 등)은 좌측 정렬
- 괄호 안에 비중이나 증감을 덧붙인 수량(○○건 (○○%) 등)은 수량 열로 판정
- 숫자가 들어 있어도 조건, 시점, 순서를 나타내는 글자와 섞인 표현(○○점 이상, ○○% (2030년), 4년차, 3단계 등)은 한 덩어리로 읽는 열로 판정
- 같은 덱에서 성격이 같은 열은 표가 달라도 같은 정렬을 사용
- 판정이 어려운 열은 가운데 정렬
- 한 비교 줄의 셀은 모두 한 항목이거나 모두 여러 항목으로 작성 (항목 수를 맞추기 어려운 줄의 불릿은 위 비교 줄 조건을 따름)
- 세로 정렬은 표 전체를 가운데로 통일
- 셀 채움은 테마 색, 틴트, 회색, 흰색만 사용
- 채움이 없는 셀에도 흰색을 지정
- 행 수가 많으면 표를 나누거나 행 높이를 줄여 본문 영역 안에서 끝냄
- 같은 값이 이어지는 셀은 상위 분류가 실제로 이어질 때만 병합
- 병합 여부는 표의 의미와 앞뒤 행의 관계로 판단

## 수치

- 정량 수치는 출처 기관과 기준 시점을 병기
- 합계와 비율은 코드로 검산
- 미확인 수치는 자리 표기 `[확인 필요]` 로 표시 (남으면 lint WARN, `meta.final` 이면 FAIL)
