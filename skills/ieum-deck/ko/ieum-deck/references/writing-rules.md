# 텍스트 규범

## 문장

- 1문장에 1메시지
- 5W1H 각 요소는 문장 안에 1회
- 연결어(그리고, 그러나, 하며, 이는)와 복문은 문장 분리로 해소
- 쉼표는 항목 나열에 사용
- 나열 쉼표는 생략 없이 표기
- 본문은 명사형 종결
- 관형형이 남은 형태("달성할 필요")는 명사구("달성 필요")로 교정
- 서술어를 자른 형태("수립하는 것을 목적")는 문법 오류
- 서술어를 자른 문장은 "수립을 목적으로 추진" 형태로 재작성 (`references/headline-patterns.md` 명사형 변환 규칙)
- 헤드라인 문체는 착수 질의 5번에서 선택 (명사형 기본, 존댓말 선택 가능)
- 존댓말 헤드라인은 하십시오체로 종결 (예: "수립합니다", "확보합니다", "보유하고 있습니다", "추진하겠습니다" 등)
- 본문 문체는 헤드라인 문체와 관계없이 명사형
- 헤드라인과 본문에는 구어체와 비격식체를 쓰지 않음 (종결, 어휘, 표현 등의 구어적 어감과 비격식적 어감 포함)
- 구어체 표지는 추측과 완곡 종결(-듯, -듯함, -인 셈, -하는 편, -할 만함, -로 봄, -로 보임, -로 여겨짐), 설명체 어미(-는데, -인데, -더라, -거든, -잖아), 구어 축약(-하는 게, -할 거, -한 걸, -하는 건), 구어 부사(일단, 약간, 좀, 꽤, 딱, 그냥, 나름) 등
- 구어체 표지는 삭제하거나 격식 표현으로 교체
- 빈자리 명사("것", "곳", "거", "셈", "부분" 등) 대신 가리키는 대상을 구체적인 명사로 표기
- 헤드라인 상한은 1줄 50자, 2줄 100자 (50자 초과는 lint WARN, 100자 초과는 lint FAIL)
- A4 판형의 1줄 상한은 43자, 10.83×7.5 판형은 40자, 4:3 판형은 37자 (2줄 상한은 1줄 상한의 2배)
- 글자 수 상한은 한글 환산 글자 수로 적용 (문구 폭을 한글 1자 폭으로 나눈 값. 영문과 공백은 폭만큼 적게 셈)
- 헤드라인은 결론 문장으로 작성 (lint 는 "추진배경" 처럼 공백 없는 2-12자 주제 라벨을 WARN)

## lint FAIL 표현

- em dash 와 en dash
- 대비 구문("X가 아닌 Y")
- 숫자 선언(숫자와 "대" 뒤에 전략, 방안, 과제, 축, 원칙, 목표, 영역이 오는 표현. 예: "3대 전략")
    + (예외) RFP 가 지정한 개수는 슬라이드의 `allowCount` 필드로 숫자 선언 검사에서 제외
- 의미 공백 표현(이러한 맥락에서, 시사하는 바가 큼, 주지하다시피, 말할 것도 없이)
- 과장 수식어(획기적, 혁신적인, 압도적, 매우, 탁월한)
- 메타 서술(본 절에서는, 앞서 제시한, 앞에서 살펴본, 다음 슬라이드에서)
- 평가 내부 어휘(배점, 채점, 방어 논리, 결정 장소, 귀속)
- 대응 선언("누락 없이 반영", "빠짐없이 반영")
- 연결어(그리고, 그러나, 하지만, 그러므로, 그렇기 때문에, 이는)
- 서술어를 자른 명사형("수립하는 것을 목적")
- 본문의 존댓말 종결(합니다, 입니다, 됩니다, 습니다, 십시오)
- 선택한 헤드라인 문체와 다른 헤드라인 종결
- 치환하지 않은 문형 자리(`{{ }}`)
- RFP 핵심 워딩(과업명, 산출물명, 단계명, 대상 명칭)의 변형 (`meta.rfp.wording` 등록 시)

## 검수 확인 표현

- lint 가 검사하지 않는 표현은 심층 검토와 시각 검수에서 확인
    + 자문자답
    + 프레임워크명 노출(MECE, 피라미드)
    + 대상 지칭어의 절마다 반복("본 과업은")
    + 발주기관 정책과 RFP 의 미비를 시사하는 문장 (긍정 서술로 전환)
    + 구어체 표지 ("문장" 절의 목록 기준으로 교정)
    + 두 명사를 "와", "과" 로 이은 나열 ("및" 으로 전환)

## lint WARN 어휘

- 맥락, 패러다임, 인사이트, 함의, 축, 층위, 정립, 선제, 선점, 게이트, 매핑, 컨틴전시, 딥다이브
- 검사 대상은 앞뒤에 다른 한글이 붙지 않은 단어

## 내용 구성

- 분류 기준은 단일 차원
- 분류 항목은 상호배제와 전체포괄을 충족
- 동일 계층 항목은 3-4개 권장
- 5개를 넘는 항목은 그룹으로 묶음
- 슬라이드 1장에 1메시지
- 메시지를 지지하는 구성요소는 3-4개 이하
- 백화점식 나열은 슬라이드 분리로 해소
- Task 묶음 슬라이드의 메시지는 모듈 수준 1문장
- Task 묶음 슬라이드에서 Task 는 메시지의 구성요소
- 상자와 표 셀의 항목은 1개 항목을 1줄에 담음
- 항목이 2줄이 되면 글자 수를 줄임
- 넘칠 때 줄이는 대상은 글자 수와 항목 수 (글꼴 크기 유지)
- 상자가 크면 항목 수를 늘리기 전에 항목별 서술의 구체성부터 검토
- 배경과 목적의 리드는 제목 1문장과 근거 2-3항목으로 구성
- 상자 하나에 항목이 1-2개뿐이면 항목을 보강하여 채움 비율 70% 를 확보
- 불릿 항목 문구는 상자 폭 한 줄의 80-95% 길이로 작성 (가장 긴 글줄이 80% 미만이면 모든 줄의 오른쪽이 비어 보임)
- 종합 상자 항목 문구는 한 줄의 90-100% 를 채우는 비슷한 길이로 작성 (판정 기준은 SKILL.md 디자인 시스템의 가로 채움)
- 표 셀 문구에는 대상, 기준, 수치 가운데 필요한 정보를 병기 (열 폭을 채우는 분량)
- 보강할 내용이 없으면 상자를 줄여 가운데로 모음
- 축소 후에도 어색하면 표현 형식을 바꾸거나 인접 상자와 합침
- Key Point 밴드는 헤드라인과 본문에 없는 판단 기준, 산식, 후속 연계, 선정 사유, 적용 시점, 원칙 등을 담을 때만 작성
- 헤드라인 반복이나 본문 요약만 담은 밴드는 삭제
- 한 줄짜리 산식이나 단서는 `footnotes` 에 기재
- Key Point 밴드 문장은 띠 안쪽 폭 한 줄의 절반 이상을 채우는 길이로 작성 (가운데 정렬 틴트 상자에서 짧은 문장은 좌우 빈 공간이 커서 허전해 보임)
    + (권장 분량) 띠 안쪽 폭 한 줄의 70-80% 이상
    + (보강 방식) 문장이 담는 대상, 기준, 시점, 주체를 구체화하여 길이를 확보
    + (보강 제외) 수식어, 평가어, 연결어로 길이를 늘리지 않음
    + (문장 구조) 서술어 1개의 단문으로 띠 한 줄 안에 작성
- 보강할 정보가 없는 짧은 밴드는 삭제하거나 내용을 `footnotes` 로 이동

## Key Point 라벨

- 라벨은 Key Point 밴드를 라벨 칸 형식으로 조판하는 덱에서만 작성 (기본 형식인 틴트 상자는 라벨 없음)
- 라벨은 밴드 문장이 어떤 종류의 정보인지 독자에게 알려주는 짧은 명사구로 작성
- 중요도를 선언하는 평가어로 라벨을 만들지 않음
- RFP, 원고, 발주기관 양식에 같은 역할의 표현이 있으면 그 표현을 우선 사용
- 라벨 길이는 라벨 칸 한 줄에 들어가는 분량으로 제한
- 덱 안에서 같은 종류의 내용에는 같은 라벨을 사용
- 덱 단위 라벨(`meta.pointLabel`)은 사용자가 덱 전체에 라벨 1개를 지정한 경우에만 기재

## 표기

- 긴 명칭은 어절 단위로 띄어 씀 (상자 안쪽 폭보다 넓은 어절은 중간이 잘림)
- 두 명사의 나열은 라벨, 헤드라인, 본문 모두 "및" 으로 연결 (예: 전략과제 및 세부과제)
    + (예외) RFP 원문 명칭(과업명, 산출물명, 단계명, 대상 명칭)은 원문 표기를 유지
    + (예외) 분야에서 굳어진 관용 명칭은 관용 표기를 유지 (예: BSC 관점명 "학습과 성장")
    + (예외) 두 명사 사이의 관계(사이, 간, 격차, 차이, 일치, 불일치, 연계, 연동, 정렬, 비교, 구분, 분리, 협력)를 나타내는 "와", "과"는 유지 (예: 현행과 기준의 격차, 성과지표와 성과목표의 연계)
    + (예외) 동작의 상대를 나타내는 "와", "과"는 유지 (예: 발주기관과 공유, 사유와 함께 관리, 지역 대학과 공동 운영)
- 절 번호는 숫자와 마침표로 표기 (예: "1.")
- 절 번호의 마침표는 빌더가 자동 보정
- 번호와 기호는 1번만 표기
- 빌더가 붙이는 번호와 기호는 텍스트에서 생략
    + section 은 secNo 의 번호("1.") 없이 작성
    + 슬롯 텍스트는 "-" 나 "·" 같은 기호 없이 작성 (불릿은 빌더가 조판)
    + steps 의 title 은 "STEP 1." 같은 접두 없이 작성 (접두가 필요 없으면 stepLabel 을 "")
    + 번호 계승(1-1.)을 적는 grid 칸은 numbered 를 지정하여 번호가 불릿을 대신하게 함
    + note 와 footnotes 항목은 ※, "1)" 같은 표기 없이 작성 (표기 방식은 `meta.footnoteStyle`, 내용 유형 라벨은 아래 주석 절, 출처 표기는 아래 출처 표기 규칙)
    + process 의 모듈명은 "M1" 같은 번호 없이 작성 (모듈 번호는 id 필드)
    + 마커가 있는 슬라이드의 본문 첫 줄은 마커와 다른 내용으로 시작
- 기호 반복 규칙의 대상은 직접 입력한 기호 (빌더가 그리는 불릿은 유지)
- 항목이 2개 이상이면 불릿을 유지
- 하위 항목(sub)이 딸린 항목은 1개여도 목록으로 셈 (항목 2개 이상과 같이 불릿 유지)
- 항목이 1개이면 줄바꿈으로 여러 줄이 되어도 불릿 없는 문장으로 표기
    + (표 셀) 아래 표 절의 비교 줄 조건이나 표 전체 조건으로 불릿을 추가한 줄은 예외
    + (모듈 개요 슬라이드) 추진과정, 활용자료, 산출물 상자는 예외로 불릿 표기 (두 조건이 늘 성립하는 표로 봄)
- 같은 계층 항목은 번호와 기호의 유무를 통일
- 출처 항목은 `기관명(연도), 자료명` 형식으로 표기
- 출처가 여럿이면 세미콜론으로 구분 (`source` 배열은 빌드가 결합)
    + (출처 행의 줄 나눔) 빌드는 한 줄을 넘는 출처 행만 1줄에 출처 1개로 조판 (세미콜론은 줄 끝에 남김)
    + (줄 나눔 출처의 정렬) 둘째 출처부터 첫 출처의 시작 위치(출처 표기 뒤)에 정렬 (footnoteSourceMark 를 지정한 ※ 표기 덱은 "※ 출처:" 처럼 ※ 와 출처 표기를 합친 폭 뒤)
    + (출처 번호) 출처에는 번호를 붙이지 않음 (독자는 출처 번호를 본문 인용 번호의 짝으로 읽음)
- 출처(`source`, `factSource`)의 문헌 제목과 자료명은 원문 그대로 인용 (em dash 와 en dash 만 하이픈으로 교체)
- 주석과 출처는 `meta.footnoteStyle` 의 표기로 시작
    + (빌드 부착) note 계열 슬롯, footnotes, source 앞의 표기(※, 번호, 라벨)는 빌드가 `meta.footnoteStyle` 에 맞춰 부착
    + (본문 칸의 주석) 본문 칸에 직접 쓴 주석은 ※ 를 수동 부착 (출처, 산식 등 라벨로 시작하는 주석은 ※ 없이 라벨로 시작)
    + (수동 ※ 의 변환) 번호 표기 덱에서는 수동 부착한 ※ 를 빌드가 덱 표기로 변환
    + (번호 표기 덱의 라벨) 라벨이 없는 항목에만 주석 라벨(footnoteLabel)을 부착 (작성자가 쓴 출처:, 산식: 등의 라벨은 그대로 조판)
    + (번호 표기 덱의 같은 라벨 주석) 2항목 이상의 주석은 라벨이 같거나 모두 없으면 라벨을 첫 줄에만 붙여 1) 2) 로 구분 (둘째 번호부터 첫 번호의 시작 위치에 정렬)
    + (번호 표기 덱의 출처 라벨 주석) 같은 출처 표기로 시작하는 2항목 이상의 주석은 번호 없이 세미콜론으로 구분
    + (번호 표기 덱의 다른 라벨 주석) 라벨이 서로 다른 주석은 번호 없이 줄마다 각자의 라벨을 붙임
    + (직접 쓴 표기) 빌드는 항목 앞에 직접 쓴 ※, *, 번호를 떼고 덱 표기를 붙임 (본문 위치와 짝짓는 위첨자 번호나 * 표기는 지원하지 않음)
- source 첫 항목과 출처를 인용하는 주석 항목은 덱의 sourceLabel 과 같은 출처 표기로 시작 (기본 덱은 "Source:")
    + (두 표기 공통) 직접 쓴 출처 표기는 ※ 없이 그대로 조판 (예: "출처: 기관명(연도), 자료명; 기관명(연도), 자료명")
    + (라벨 보충) 출처 표기가 없는 출처 행에는 빌드가 sourceLabel 을 부착
    + (출처의 ※) `meta.footnoteSourceMark` 가 true 인 ※ 표기 덱은 "※ 출처:" 처럼 ※ 를 붙임 (RFP 양식 등으로 사용자가 요청한 경우에 지정)
    + (직접 쓴 출처의 ※) ※ 표기 덱에서 작성자가 출처 앞에 ※ 를 직접 쓴 항목은 ※ 를 유지
    + (source 배열) 출처 표기는 첫 항목에만 기재 (항목 사이는 빌드가 세미콜론으로 구분)
- 주석 라벨과 출처 표기는 덱 전체에서 같은 언어의 짝으로 통일 (기본 "Note:"와 "Source:", 한글 표기 예: "참조:"와 "출처:", 발주기관 관행 예: "주:"와 "자료:")
    + (덱 라벨) footnoteLabel 과 sourceLabel 은 같은 언어의 짝으로 함께 변경
    + (작성자 출처 표기) 작성자가 쓰는 출처 표기는 덱의 sourceLabel 과 같은 표기로 작성
    + (슬라이드 라벨) 슬라이드 footnoteLabel 과 sourceLabel 은 덱 라벨과 같은 언어로 지정
    + (내용 라벨) "산식:", "기준:" 같은 내용 라벨도 덱 라벨과 같은 언어를 권장 (관행상 다른 언어 표기가 자연스러운 라벨은 작성자가 판단)
- ※ 는 근거, 전제, 단서 등 주석 성격의 문구에만 사용 (출처, 산식 등 라벨로 시작하는 주석은 라벨로 시작)
- 근거와 단서 등은 note 슬롯이나 footnotes 에 기재 (빌드가 표기를 자동 부착)
- 견본 슬라이드의 ※ 문단은 예시 자리
    + 주석으로 쓰면 ※ 로 시작
    + 일반 항목으로 쓰면 ※ 없이 작성
- 본문을 줄여 쓴 문장, 항목 설명, 라벨은 ※ 없이 같은 계층의 글꼴 크기에 맞춤
- 한 상자 안 불릿은 모두 같은 글꼴 크기를 사용
- 대상 지칭어 규칙은 `references/headline-patterns.md` 대상 지칭어 절을 따름
- 모듈 절 제목은 `[Module 1] 모듈명` 형식 (절 번호 뒤 마침표와 겹침 방지)
- Task 마커는 모듈 번호를 포함한 `Task 1-2. Task명` 형식
- 본문에서 Task 를 가리킬 때도 `Task 1-2` 형식으로 표기
- 조직도와 목차의 모듈 항목도 `[Module 1] 모듈명` 형식

## 주석

- 주석(footnotes, note 슬롯)에는 본문의 정확한 해석이나 검증에 필요한 보충 정보를 기재 (보충 대상의 예: 수치, 용어, 판단, 범위 등)
    + (수치) 산식, 단위, 기준 시점, 환산 기준 등 산정 기준
    + (용어) 독자에게 낯선 용어, 약어, 표식의 정의 등
    + (판단) 근거 법령, 상위 지침 등 판단 근거
    + (범위) 전제, 적용 범위, 예외, 예시나 잠정치 여부 등 내용이 성립하는 조건
- 본문 메시지를 이루는 내용은 본문에 작성
- 수치와 사실 등의 출처 자료는 `source` 에 작성
- 주석 항목은 주어와 서술어가 1쌍인 단문으로 작성 (단문 여부는 문장 길이와 관계없이 문장 구조로 판단)
- 같은 대상을 보완하는 단서는 1항목으로 합침
- 특정 단어나 수치 등을 보충하는 주석은 문장 안에 보충 대상을 명시 (예: "매출액은 2024년 결산 기준")
- 독자가 업무 및 일상에서 사용하는 용어와 약어(RFP, 컨설팅, 참여율 등)는 정의 주석과 전체 명칭 병기를 생략
- 용어, 약어, 표식을 정의하는 주석은 `(용어) 설명` 형식으로 작성 (괄호 안 용어가 보충 대상의 명시를 대신함)
    + 괄호 안에는 본문에 쓴 표기를 그대로 기재
    + 설명은 뜻을 풀어 쓴 명사구 1개로 작성 (예: "(입지계수) 특정 지역의 산업 비중을 전국의 같은 산업 비중으로 나눈 값")
    + 설명에는 정의 대상 용어의 반복과 다른 전문용어를 쓰지 않음
    + 약어는 설명 끝 괄호에 전체 명칭을 병기 (예: "(TTL) 여행, 운송, 물류 서비스를 묶은 산업 분류(Travel, transport, and logistics)")
- 주석 항목은 기본적으로 라벨 없이 작성
    + (번호 표기 덱) 빌드가 주석 라벨을 붙여 범례, 기준, 단서 등의 표기를 하나로 맞춤
    + (출처 인용 항목) 출처를 인용하는 항목은 출처 표기 규칙을 따름
- 상자 안에서 수치나 항목명 바로 아래 붙는 설명은 내용 라벨로 시작하도록 권장 (라벨 형식은 공백 없는 한 단어 뒤 콜론)
    + (대상 예) 수치 카드(numbers)의 note 등 상자 내용의 일부로 읽히는 문구 (각주 라벨 "Note:" 와 성격이 맞지 않음)
    + (라벨 예) "산식:"(수치의 계산식), "기준:"(수치의 기준 시점) 등 (수치를 가져온 자료는 덱의 출처 표기로 시작)
- ※ 표기 덱에서 라벨로 시작하는 주석에는 빌드가 ※ 를 붙이지 않음
    + (생략 이유) 라벨이 줄의 성격을 나타냄
    + (맞춤 설정) 발주기관 양식 등으로 ※ 가 필요하면 작성자가 해당 항목 앞에 ※ 를 직접 씀 (빌드가 유지)
- 주석 항목은 내용의 중복과 누락 없이 구성
- 헤드라인, 본문, Key Point 밴드 등에 있는 내용은 주석에서 반복하지 않음
- 주석 수는 슬라이드마다 본문 이해에 필요한 최소로 유지
    + (※ 표기의 기본 개수) 1항목을 기본으로 작성
    + (※ 표기의 2항목 이상) 서로 다른 대상의 단서가 함께 필요한 경우에 사용 (※ 줄이 쌓이면 본문보다 눈에 띔)
    + (번호 표기) ※ 표기와 같은 최소 원칙을 적용 (2항목 이상은 빌드가 번호를 붙여 1항목 1줄로 조판)
    + (슬라이드별 판단) 위 개수는 일반 관행이므로 슬라이드의 내용과 맥락을 보고 최종 판단
- 이어 쓰기는 슬라이드의 `footnoteInline: true` 로 지정 (빌드는 줄 나눔 형태를 이어 쓰기로 자동 전환하지 않음)
- 이어 쓰기 검토 대상은 주석 수 최소 원칙과 출처 기재 원칙을 적용한 뒤에도 아래 상황이 함께 나타나는 슬라이드
    + (본문 넘침) 줄 나눔 형태로 빌드한 슬라이드에서 본문이 넘치거나 겹침 (check_layout FAIL 이나 PNG 로 확인)
    + (줄 감소) 이어 쓰면 하단 주석과 출처 행의 줄 수 합계가 2줄 이상 줄어듦 (빌드 결과로 확인)
- 이어 쓴 주석과 출처 행은 아래 형태로 조판
    + (번호 표기 덱의 주석) "Note: 1) A 2) B 3) C" 처럼 1문단으로 이어 씀
    + (출처 행) "출처: A; B; C" 처럼 1문단으로 이어 씀 (footnoteSourceMark 를 지정한 ※ 표기 덱은 "※ 출처: A; B; C")
    + (※ 표기 덱의 주석) 이어 쓰지 않음 (줄마다 ※ 를 붙이는 형태 유지)
    + (줄을 넘긴 문단) 이어 쓴 문단이 줄을 넘기면 둘째 줄부터 라벨 뒤 위치에 정렬
- 덱 안에서 이어 쓰기 슬라이드는 예외로 두도록 권장 (여러 슬라이드가 해당하면 덱의 주석과 출처 분량을 다시 점검)
- (맥락 판단) 위 라벨과 이어 쓰기 기준은 관행을 정리한 지침이므로 슬라이드 전체의 맥락을 보고 적용 여부를 최종 판단

## 표

- 셀 1개에 항목이 둘 이상이면 셀 내용과 표 전체를 보고 불릿과 쉼표 나열 중 읽기 쉬운 쪽을 선택
- 선택 기본값은 짧은 명사구의 쉼표 나열, 서술형 항목의 불릿
- 비교 줄은 같은 속성을 대상별로 나란히 놓은 셀 줄. 대상이 열에 놓인 표(모듈 개요표, 대안 비교표)는 행, 대상이 행에 놓인 표(수행실적 표 등)는 열이 비교 줄
- 한 비교 줄의 표기 방식 통일 여부는 그 줄 셀들의 성격을 대조하여 판단
- 불릿 표기를 고른 셀은 항목마다 불릿. 항목 1개는 줄바꿈으로 여러 줄이 되어도 불릿 없음
- 항목 1개 셀의 불릿은 비교 줄 단위로 판정
    + (비교 줄 조건) 한 비교 줄에서 항목 2개 이상 셀이 절반 이상이면 그 줄의 항목 1개 셀에도 모두 불릿. 셀 수에서 머리글 행과 구분 열은 제외
    + (표 전체 조건) 불릿을 붙인 줄이 표의 목록형 줄 대부분이면 남은 목록형 줄에도 줄 전체로 불릿을 붙일 수 있음. 판단 기준은 표 전체의 읽기 편의. 목록형 줄은 셀 하나에 항목이 여러 개 들어갈 수 있는 줄(금액, 기간, 연도처럼 셀마다 값이 하나인 줄은 제외)
    + (줄 단위 적용) 불릿 추가는 줄 전체에 적용. 불릿을 추가한 줄 안에서는 불릿 유무를 섞지 않음
    + (맥락 판단) 위 조건이 모든 표에 기계적으로 들어맞지는 않음. 최종 판단은 표 전체의 맥락을 보고 내림
    + (모듈 개요표) 두 조건이 늘 성립하는 표로 보아 세 행 모두 불릿 (빌더가 자동 적용)
- 불릿을 추가할 줄은 storyboard 작성 단계에서 판정하여 `bulletRows`, `bulletCols` 로 지정 (형식은 `references/templates.md` 표 조판)
- 가로 정렬은 열 단위로 통일
- 열 정렬은 표 전체를 보고 열이 표 안에서 하는 역할로 판정
    + (수량 열) 금액, 개수, 비율, 점수, 가중치 등 숫자와 단위로 된 열은 자릿수 비교가 쉽도록 우측 정렬
    + (한 덩어리로 읽는 열) 분류, 이름, 연도, 연번, 기간, 산식, 짧은 문구 등 셀을 하나의 표현으로 읽는 열은 가운데 정렬
    + (줄을 따라 읽는 열) 불릿 목록, 진단 질문, 서술형 설명(내용, 세부 내용, 주요 활동 열 등)은 좌측 정렬
- 괄호 안에 비중이나 증감을 덧붙인 수량(○○건 (○○%) 등)은 수량 열로 판정
- 숫자가 들어 있어도 조건, 시점, 순서를 나타내는 글자와 섞인 표현(○○점 이상, ○○% (2030년), 4년차, 3단계 등)은 한 덩어리로 읽는 열로 판정
- 같은 덱에서 성격이 같은 열은 표가 달라도 같은 정렬을 사용
- 판정이 어려운 열은 가운데 정렬
- 한 비교 줄의 셀은 모두 한 항목이거나 모두 여러 항목으로 작성 (항목 수를 맞추기 어려운 줄의 불릿은 위 비교 줄 조건을 따름)
- 세로 정렬은 표 전체를 가운데로 통일
- 셀 채움은 테마 색, 틴트, 회색, 흰색만 사용
- 채움이 없는 셀에도 흰색을 지정
- 행 수가 많으면 표를 나누거나 행 높이를 줄여 본문 영역 안에서 끝냄
- 같은 값이 이어지는 셀은 상위 분류가 실제로 이어질 때만 병합
- 병합 여부는 표의 의미와 앞뒤 행의 관계로 판단

## 수치

- 정량 수치는 출처 기관과 기준 시점을 병기
- 합계와 비율은 코드로 검산
- 미확인 수치는 자리 표기 `[확인 필요]` 로 표시 (남으면 lint WARN, `meta.final` 이면 FAIL)
