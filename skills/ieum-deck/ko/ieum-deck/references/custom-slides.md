# 커스텀 슬라이드

- 커스텀 슬라이드는 사용자가 제공한 PPTX 의 개별 슬라이드에서 도형 배치를 추출하여 재사용하는 슬라이드
- storyboard 에서는 `"template": "own:N"` 으로 호출 (N 은 원본 PPTX 의 슬라이드 순번)
- 등록 조건은 사용자의 PPTX 제공과 사용 권한 확인
- 스킬 배포본에는 커스텀 슬라이드 데이터가 없음
- 커스텀 슬라이드를 등록하지 않아도 composite 레시피와 파라메트릭 템플릿으로 전체 절차가 동작

## 처리 범위

- 재사용 대상은 개별 슬라이드의 도형 배치

| 구분 | 대상 요소 |
|---|---|
| 원본 그대로 사용 | 도형의 위치와 크기, 선과 채움 색, 표와 차트 구조, 텍스트 상자와 이미지의 자리 |
| 스킬 양식으로 교체 | 서체(나눔고딕), 밴드(절 번호, 헤드라인, 마커), `colorMap` 으로 지정한 색, 기호 글꼴(Wingdings, Symbol) 불릿 문자 |
| 추출 제외 | 슬라이드 마스터와 레이아웃에 있는 도형, 배경 |

## 등록 절차

1. 레이아웃 확인
    + `python3 scripts/own_extract.py --inspect <원본.pptx>`
    + 출력 내용은 레이아웃 이름별 사용 슬라이드와 자리표시자 idx 목록
2. 설정 파일 작성
    + 설정 키 표에 따라 `deck-config.json` 을 작성
    + 설정 파일 없이 추출하면 원문을 그대로 추출
    + 설정 파일이 없으면 모든 슬라이드의 밴드 모드는 full
3. 좌표 추출
    + `python3 scripts/own_extract.py <원본.pptx> <own-deck.json> --config deck-config.json`
    + `identityCheck` 에 걸리는 식별 문구가 남으면 추출 후 목록이 출력됨
4. 슬롯 목록 생성
    + `python3 scripts/own_catalog.py <own-deck.json> <own-slots.md>`
    + 슬롯 목록은 슬라이드별 슬롯 키, 원문 앞부분, 표 크기, 이미지 슬롯, 차트 슬롯을 기록
5. 재현 확인
    + 모든 `own:N` 을 슬롯 없이 1장씩 담은 storyboard 를 빌드
    + 빌드 결과는 `render.sh` 로 PNG 변환
    + 원본 PPTX 는 PDF 로 변환
    + `python3 scripts/compare.py <원본.pdf> <png_dir> <out_dir> 1:1,2:2,...` 로 원본과 재현본을 대조
    + 차분 비율이 큰 슬라이드부터 대조 이미지를 열람
    + 어긋난 슬라이드는 설정 파일(`dropAtoms`, `dropTexts`, `layoutModes`, `bandPlaceholders`)로 보정
6. 등록
    + storyboard 의 `meta.ownDeck` 에 own-deck.json 경로를 기재 (storyboard 파일 기준 상대 경로 허용)
    + 여러 storyboard 에 같은 커스텀 슬라이드를 쓰면 환경변수 `IEUM_DECK_OWN` 으로 지정
    + `meta.ownDeck` 이 환경변수보다 우선

- 등록 없이 `own:N` 을 쓰면 빌드 중단
- 등록 없이 `own:N` 을 쓰면 lint FAIL
- 등록한 커스텀 슬라이드에 없는 번호를 쓰면 lint FAIL

## 설정 키

| 키 | 형식 | 용도 |
|---|---|---|
| `bandPlaceholders` | `{"자리표시자 idx": "secNo, secTitle, tracker, headline, marker, pageNo 중 하나"}` | 원본 자리표시자를 스킬 밴드 역할에 대응. 대응한 자리표시자는 빌더가 밴드로 다시 조판 |
| `layoutModes` | `{"레이아웃 이름": "full, noMarker, headerOnly, blank 중 하나"}` | 레이아웃별 밴드 모드. 미지정 레이아웃은 full |
| `identityText` | 정규식 | 회사명 등 식별 문구. 일치한 도형에 식별 태그를 부여 |
| `identityCheck` | 정규식 | 추출 후 남은 식별 문구의 점검 기준 |
| `generalize` | `[{"pattern", "replace", "slides": [N]}]` | 식별 문구를 자리 표기로 바꾸는 규칙. `slides` 가 없으면 전 슬라이드에 적용 |
| `identityPicSlides` | `[N]` | 그림을 로고 등 식별 요소로 취급할 슬라이드 |
| `zeroTableSlides` | `[N]` | 표 안 숫자를 0 으로 바꿀 슬라이드 (실제 재무 수치 등) |
| `dropAtoms` | `{"N": ["도형 이름"]}` | 재생에서 제외할 도형 |
| `dropTexts` | `{"N": ["문구 전체"]}` | 재생에서 제외할 텍스트 도형 (문구 전체 일치) |
| `roles` | `{"역할": [N]}` | lint 가 슬라이드의 기능을 판정하는 근거 |
| `descriptions` | `{"N": "용도 설명"}` | 슬롯 목록 문서에 기재할 슬라이드 용도 |
| `colorMap` | `{"원본 RGB": "tokens.js COLOR 키"}` | 테마를 바꿀 때 함께 바뀔 원본 색 |

- 회사명 자리에 `__COMPANY__` 를 치환 문구로 두면 빌드가 `meta.company` 로 치환
- 실제 인명, 실적 금액, 연도 같은 사실 정보를 `generalize` 로 `[회사 확인]` 등 자리 표기로 바꾸면 lint 가 남은 자리 표기를 검사

## 역할

- lint 는 템플릿 이름으로 슬라이드의 기능을 판정
- 커스텀 슬라이드는 `roles` 에 기능별 슬라이드 번호를 등록 (`own:N` 번호만으로는 기능 판정 불가)
- 예를 들어 원본 19번 슬라이드가 모듈 개요이면 `{"roles": {"module_overview": [19]}}` 로 등록

| 역할 | 등록 대상 슬라이드 | lint 판정 |
|---|---|---|
| `module_overview` | 모듈 개요표 | 모듈 개요 슬라이드로 인정 |
| `org_project` | 수행조직도 | 수행조직도로 인정하여 투입인력과 인력 일치를 검사 |
| `people_table` | 투입인력표 | 투입인력표로 인정하여 인력 일치와 중간 빈 행을 검사 |
| `pm_profile` | 책임자 프로필 | 인력 일치와 사실 정보 출처를 검사 |
| `company_fact` | 회사 개요, 조직, 재무, 실적 | 사실 정보 출처(`factSource`)를 검사 |
| `collaboration` | 전문가 협업 구조 | 조직 계열 슬라이드로 인정 |

## 슬롯 치환

- 슬롯 키는 `own-slots.md` 의 해당 `## own:N` 절에서 확인
    + (원문 키) `"~원문 앞부분"` 은 원문 앞부분이 일치하는 텍스트 상자 (공백 무시, 권장)
    + (순번 키) `t{k}` 는 텍스트가 있는 도형의 출현 순번
    + (표 셀) `tb{k}.r{i}c{j}` 는 k 번째 표의 i 행 j 열 (0 부터)
    + (이미지) `img{k}` 값은 경로나 data URI
    + (차트) `ch{k}` 값은 차트 spec(`{categories, series}`)
- 값을 `""` 로 주면 해당 상자를 생략
- 같은 행의 열 상자가 생략되면 남은 열이 원래 폭 전체로 재배분
- 세로로 쌓인 목록 상자는 생략해도 남은 상자의 크기가 그대로이므로 항목을 채워 사용
- 한 상자의 절반 이상을 비워야 하면 항목 수가 맞는 다른 커스텀 슬라이드나 composite 레시피를 선택
- 원문 차트 데이터, 표 값, 항목 문구는 과업 내용으로 교체
- 슬롯 텍스트의 상한은 원문 줄 수
- 슬롯 텍스트의 하한은 채움 비율 70%
- 치환 문구가 상자 용량을 넘기면 lint WARN
- 넘친 슬롯은 글자 수나 항목 수를 줄여 해소

## 재생 보정

- 원문 그대로인 텍스트는 원본 서체와 나눔고딕의 폭 차이를 실측 폭 기반 축소(하한 9pt)로 흡수
- 원본 글꼴 크기가 같은 형제 상자는 같은 축소율을 사용
- 치환한 텍스트는 본문 하한 11pt 를 지킴
- 치환한 텍스트가 넘치면 문단 간격만 줄임 (글꼴 크기 유지)
- 축소를 거친 슬라이드는 check_layout 의 11pt 하한 검사에서 제외
- 제외 판정은 빌드가 남기는 `<파일명>.build.json` 의 등록 정보를 사용
- `<파일명>.build.json` 은 pptx 와 같은 폴더에 둠
- 아이콘 크기의 이미지 슬롯을 비우면 주변 라벨 문구에 맞는 도형 조합 아이콘을 자동 배치
    + (자물쇠) 물리, 출입
    + (방패) 기술 보안
    + (체크리스트) 관리 보안, 점검
    + (달력) 일정, 보고
    + (디스크) 데이터
    + (대시보드) WBS, 진도
    + (문서 파쇄기) 파쇄
    + (톱니) 시사점, 도구
    + (인물) 인원
- 로고 슬롯을 비우면 로고를 생략
- 큰 이미지 슬롯을 비우면 자리 상자로 대체
- 표 옆의 삽화 자리를 비우면 표 확장이나 주제 아이콘으로 빈 면적을 흡수
- 도넛 차트 안 텍스트는 구멍 영역을 세로로 나누어 순서대로 배치
- 도넛 링 두께는 중앙 흰 원으로 유지 (렌더러가 구멍 크기 설정을 무시해도 비례 보장)

## 레시피 병용

- 내용이 맞는 커스텀 슬라이드가 있으면 `own:N` 을 먼저 사용
- 맞는 커스텀 슬라이드가 없으면 composite 레시피나 파라메트릭 템플릿을 사용
- 커스텀 슬라이드와 레시피는 밴드, 서체, 색 토큰을 공유
- 한 발표자료에 커스텀 슬라이드와 레시피를 섞어도 양식이 유지됨
- 슬라이드 다양성 검사는 `own:N` 번호별로 다른 구성으로 셈
