# 심층 검토

## 수행 기준

- 수행 시점은 절차 7단계의 check_layout 통과 직후
- 수행 횟수는 1회
- 검토 대상은 배점 10점 이상 세부평가항목에 귀속된 슬라이드 (`evalItems` 기준)
- 검토 범위는 lint 와 check_layout 이 잡지 못하는 결함
- 규칙 밖 결함의 판단과 조정은 SKILL.md 의 규칙 밖 결함 판단 절과 시각 조정 재량 절을 따름
- 검토자 역할은 평가위원
- 기록은 검토 항목의 질문에 답하는 형식으로 작성
- 결함마다 슬라이드 ID 와 수정 방향을 `state.json` 의 review 항목에 기재
- 경고 처리는 SKILL.md 완료 조건을 따름
- 파일 전달 시점은 SKILL.md 절차 절을 따름

## 검토 항목

| 항목 | 질문 | 결함 예시 |
|---|---|---|
| 수치 무결성 | 비율의 분자와 분모가 같은 기준 시점인가. 두 지표의 곱과 나눗셈이 세 번째 지표와 맞는가. 같은 사실을 가리키는 수치가 두 값으로 존재하는가 | 2023년 예산 대비 2025년 집행률. 총 과제 수 120과 세부 합계 118 |
| 출처 신뢰도 | 인용 수치마다 별첨으로 제출 가능한 자료인가. 유료 리포트와 출처 미상 보도치가 있는가. 업계 상위 목록에서 널리 알려진 기관이 누락되었는가 | 언론 보도의 시장 규모. 출처 없는 성장률 |
| 논리 비약 | 자료에서 결론으로 가는 중간 단계가 있는가. 스톡과 플로우, 금액과 건수처럼 조건이 다른 사실을 등치했는가. 인용 수치가 반대 결론을 지지하는가 | 특허 출원 증가를 기술 경쟁력 확보로 단정 |
| 이면 니즈 대응 | 00_strategy.md 의 이면 니즈 가설에 답하는 슬라이드가 있는가 | 감사 지적 대응 모듈 부재 |
| 변별력 | 경쟁사가 같은 문장을 쓸 수 있는가. 제안사만 쓸 수 있는 근거(실적, 데이터, 인력)가 붙어 있는가. 전략 기둥에서 RFP 과업 내용과 제도 의무를 지워도 수단이 남는가 | "풍부한 경험을 바탕으로". "요구 산출물의 충실한 작성" |
| RFP 대응 | 슬라이드 내용이 대응 RFP 과업 원문의 요구를 모두 담는가. RFP 가 요구한 산출물명과 핵심 워딩의 표준 표기가 그대로 있는가 | 과업 원문이 정한 조사 대상의 일부 누락. 산출물명 변형 |
| 발주기관 존중 | 발주기관 정책과 RFP 의 미비를 시사하는 문장이 있는가 | "기존 지표가 부실하여" |

## 수정 후 확인

- 발견한 결함은 storyboard 에서 수정
- 수정 후 lint 와 빌드를 재실행
- 문체 일괄 수정 후에도 lint 와 빌드를 재실행 (lint FAIL 표현의 재유입 방지)
- 수행조직과 책임자 프로필이 함께 있으면 리더 호칭의 통일 여부를 확인
- 기존 슬라이드 수정 후에는 원본과 도형 좌표를 대조
- 좌표 대조 결과에는 의도한 변경만 남아야 함
- check_layout 은 pptx 와 같은 폴더의 `<파일명>.build.json` 을 함께 읽음
- pptx 와 `<파일명>.build.json` 은 같은 폴더에 둠
