# composite 레시피

- composite 템플릿은 칸 격자와 블록으로 분석 슬라이드 1장을 조판
- storyboard 에는 격자 비율, 블록 종류, 문구만 기재
- 칸과 블록의 좌표는 `scripts/composite.js` 가 계산
- 레시피는 기획과 컨설팅 슬라이드에서 반복되는 격자와 블록 조합의 견본
- 레시피별 견본 슬라이드는 `assets/recipe-demos.json` 에 있음
- 견본은 `slots.recipe` 값으로 찾음
- lint 의 슬라이드 다양성 검사는 `composite:<레시피 이름>` 을 구성 1개로 셈

## 사용 절차

1. 슬라이드에 담을 내용 유형을 레시피 목록의 용도 열에서 찾음
2. `assets/recipe-demos.json` 에서 같은 `recipe` 값의 견본을 찾아 `slots` 를 복사
3. 견본 문구와 견본 수치(○○, 예시 수치)를 과업 내용으로 교체
4. 필수 내용 열의 항목을 모두 채움 (자료가 없는 항목은 사용자에게 요청)
5. 빌드 경고와 `check_layout.py` 결과로 넘침과 채움을 확인

- 칸 수는 내용 단위 수에 맞춤
- 블록 안 항목 수는 자료 분량에 맞춤
- 맞는 레시피가 없으면 격자와 블록을 직접 조합
- 직접 조합한 composite 는 `recipe` 를 비움
- `recipe` 가 없는 composite 는 격자 칸 수와 블록 종류 조합이 같을 때 같은 구성으로 셈
- 직접 만든 조합을 한 발표자료에서 반복해 쓰면 영문 소문자와 밑줄로 된 레시피 이름을 부여
- 회사 사실 정보 레시피(`company_profile`, `finance_status`, `record_cards`, `infra_tiles`, `pm_profile`, `case_card`)는 `factSource` 를 기재 (부재 시 lint WARN)

## 격자

| 필드 | 설명 |
|---|---|
| `slots.cols` | 1행 격자의 칸 폭 비율 배열. 예: `[1, 1.2]` |
| `slots.rows` | 여러 행 격자. `[{"h": 행 높이 비율, "cols": [칸 폭 비율]}]` |
| `slots.regions` | 칸 내용 배열. 왼쪽 위 칸부터 행 순서로 나열 |
| `regions[].title` | 칸 제목. 가운데 정렬 글자와 회색 밑줄로 표시 |
| `regions[].caption` | 칸 캡션. 굵은 좌측 정렬 한 줄로 표시 (`title` 과 둘 중 하나만 지정) |
| `regions[].block` | 칸에 담을 블록 1개 |
| `regions[].blocks` | 칸에 위에서 아래로 쌓을 블록 배열. 블록별 `h` 는 높이 비율 (기본 1) |
| `block.caption` | 블록 위 캡션. 한 칸에 블록을 여러 개 쌓을 때 블록별 제목으로 사용 (`image` 블록의 caption 은 이미지 아래 설명으로 조판) |
| `regions[].note` | 칸 아래 주석. ※ 가 없으면 빌더가 붙임 |
| `slots.flow` | true 이면 같은 행의 칸 사이에 오른쪽 화살표 |
| `slots.rowFlow` | true 이면 행 사이에 아래쪽 화살표 |
| `slots.numbered` | true 이면 칸 제목 앞에 ①, ②, ③ 번호 |
| `slots.dividers` | true 이면 칸 사이와 행 사이에 회색 구분선 (4분면 차트 배치). 행마다 같은 위치의 세로선은 한 줄로 연결 (가로선과 십자로 교차) |
| `slots.point` | 본문 아래 수행 Point 밴드 문구 (라벨은 슬라이드 `pointLabel`, `meta.pointLabel`, `meta.labels.common.pointLabel` 순). 헤드라인과 본문에 없는 판단 기준, 산식, 후속 연계, 선정 사유, 적용 시점, 원칙을 담을 때만 사용 |
| `slots.conclusion` | 본문 아래 결론 밴드 문구 |

- 칸 수와 `regions` 수가 다르면 빌드 경고
- 칸과 행 사이 간격은 `composite.js` 상단 상수로 고정
    + 칸 사이 0.3인치 (`flow` 나 `dividers` 가 있으면 0.6인치)
    + 행 사이 0.3인치 (`rowFlow` 가 있으면 0.45인치, `dividers` 가 있으면 0.5인치)
    + 한 칸 안 블록 사이 0.2인치
- (자연 높이) 행 높이를 정할 때 블록이 목표로 삼는 높이
- (수용 높이) 상자 안을 비우지 않고 블록이 늘어날 수 있는 높이의 상한
- 내용 높이를 재는 블록(`table`, `bullets`, `text`, `stack`, `labeled`, `grid`, `vsteps`, `chevrons`, `flow`, `numbers`, `valuechain`, `zones`)은 내용 필요 높이의 1.6배를 자연 높이로 삼음
- `summary` 는 확대 없는 내용 필요 높이를 자연 높이로 삼음
- `tree`, `governance` 는 상자 높이와 연결선 길이의 기본값으로 자연 높이를 산정
- `timeline` 은 사건 상자 문구, `funnel` 은 단계별 기준 문구의 필요 높이로 자연 높이를 산정
- `pyramid`, `matrix`, `cycle` 은 선호 높이를 자연 높이로 삼음
- 도식 블록(`chart`, `flowchart`, `logicmodel`, `goalsystem`, `house`, `porter`, `canvas`, `market`, `image`)은 칸 높이를 채움
- 도식 블록이 없는 행의 높이는 빌더가 내용 높이로 산정
- 행 높이 비율(`rows[].h`)은 도식 블록이 있는 행의 높이 배분에 사용
- 블록은 상자 안을 비우지 않는 수용 높이까지 늘어남
    + `table` 은 행 높이 상한까지 (글자만 있는 한 줄 행 0.5인치, 여러 줄 행은 줄 간격 1.3배를 담는 높이(0.8인치 이하), 하베이 볼이 있는 표 0.8인치)
    + `stack`, `labeled`, `grid`, `vsteps`, 세로 `flow`, `zones` 는 상자 사이 간격까지
    + `tree` 는 연결선 길이와 2단 상자 간격까지
    + `governance` 는 계선 상자 높이(0.62인치)와 화살표 구간(0.6인치)까지
    + `funnel` 은 단계 띠 높이 0.9인치까지
    + `matrix` 는 사분면 평면이 정사각형에 가까워질 때까지 (평면 폭은 높이의 1.25배 이하, 평면과 범례 묶음은 칸 가운데)
    + `pyramid` 와 `cycle` 은 도형 크기까지
    + 그 외 글 상자 블록은 자연 높이의 1.2배까지
- 한 행의 높이는 행 안 칸들이 모두 채울 수 있는 높이(칸별 수용 높이의 최소)까지만 늘어남
- 수용 높이가 행 높이보다 작은 칸은 칸 제목 아래 남는 높이의 세로 가운데에 배치
- 표 1개만 담은 칸은 행 높이보다 0.3인치 이하로 짧으면 행 높이를 늘려 이웃 칸과 위아래 끝을 맞춤
- 칸 주석(`note`)은 칸 내용 바로 아래에 배치
- 같은 행에 주석 칸이 있으면 이웃 칸도 주석 높이만큼 내용 하단을 올려 행 안 칸들의 하단을 맞춤
- 남는 높이는 도식 행, 블록 수용 높이, 행 사이 간격(0.55인치 상한), 세로 가운데 여백 순으로 배분
- 한 칸에 도식 블록과 글 상자 블록을 쌓으면 글 상자 블록에 내용 높이를 먼저 주고 남는 높이를 도식 블록에 배분
- 칸 높이가 블록 내용 필요 높이보다 작으면 빌드가 넘침 위험을 경고 (항목 축소나 격자 조정으로 해소)
- 남는 높이가 커서 묶음이 작아 보이면 비중 열, 하베이 볼 열처럼 정보가 늘어나는 요소로 보완
- 수행 Point 밴드가 헤드라인 반복이나 본문 요약만 담으면 밴드를 삭제하고 본문 높이를 늘림
- 한 줄짜리 산식이나 단서는 `footnotes` 에 기재
- 묶음이 본문 높이의 70% 미만이면 `check_layout.py` 가 경고
- 본문 세로 채움 경고는 항목 보강이나 구성 교체로 해소
- 출처(`source`)와 각주(`footnotes`)는 슬라이드 공통 필드를 사용

## 블록

| kind | 용도 | 필드 |
|---|---|---|
| `table` | 행과 열 비교 | `head[]`, `rows[][]`. 셀 값은 문자열, 항목 배열, ● ◐ ○(하베이 볼). 열 폭은 자동 산정. 열 정렬은 `align[]` 으로 지정 (`references/templates.md` 표 조판) |
| `bullets` | 항목 나열 | `head`(선택), `items[]` |
| `text` | 한 문장 메시지 | `text`, `style`(navy, tint, box, plain. 기본 box) |
| `stack` | 제목 상자의 세로 적층 | `items[{head, items 또는 text, headFill, fill}]`. `headFill` 과 `fill` 의 값은 tint |
| `summary` | 종합 상자 (결론 띠와 대응 항목을 테두리 하나에 담은 도형) | `lead`(한 문장 결론), `items[{head, items 또는 text}]` |
| `labeled` | 왼쪽 라벨과 오른쪽 내용의 행 | `rows[{label, items 또는 text}]`, `labelW`(칸 폭 대비 비율) |
| `grid` | 라벨 열과 칸 격자 | `head[]`(선택), `rows[{label, cells[], sz}]`, `labelW`, `style`(hierarchy 이면 계층도 조판). 칸 값은 문자열 또는 `{text 또는 items, fill, span, bold, color, shape, numbered}`. `fill` 값은 navy 또는 tint. `shape` 값 db 는 저장소 원통. `color` 값은 navy. `numbered` 가 true 이면 항목 앞 번호(1-1. 등)가 불릿을 대신함. `sz` 는 위계를 두는 행의 글꼴 크기(pt). `flow` 가 true 이면 칸 열 사이에 오른쪽 화살표 (현황에서 목표로 가는 격차 표시) |
| `vsteps` | 세로 단계와 단계별 설명 | `steps[{title, items 또는 text}]`, `arrows`(기본 true), `label`(단계 번호 앞 접두. "" 이면 번호 생략) |
| `chevrons` | 가로 셰브론과 단계별 설명 | `steps[{title, items 또는 text}]` |
| `flowchart` | 순서도 | `lanes[]`(수행 주체, 선택), `nodes[{id, type, text, lane, col, fill}]`, `edges[{from, to, label, route}]`. `type` 값은 start, end, process, decision. `fill` 값은 tint(시스템 수행 업무). `route` 값은 hv(가로 먼저, 기본) 또는 vh(세로 먼저) |
| `zones` | 구간 구성도 (시스템 구성도) | `zones[{title, items[]}]`, `band{label, items[]}`(선택). 구성요소 값은 문자열 또는 `{text, fill, shape}`. `shape` 값 db 는 저장소 원통, `fill` 값 tint 는 성격이 다른 요소 |
| `valuechain` | 가치사슬 (지원 기능 띠, 단계 셰브론, 단계별 행, 공통 기반 띠) | `stageLabel`, `stages[]`, `support{label, bands[{title, items 또는 text}]}`(선택), `rows[{label, cells[]}]`, `base{label, text}`(선택), `labelW`. 칸 값은 문자열 또는 `{text 또는 items, mark}`. `mark` 가 true 인 칸은 틴트 채움과 굵은 글자로 표시 |
| `goalsystem` | 사업목표체계 (비전, 목적, 목표 띠와 성과 목표, 전략분야, 전략과제 열) | `vision`, `purpose`, `goal`, `performance[{title, quant, qual} 또는 {title, items}]`, `strategies[{title, text}]`(text 선택), `tasks[[{title, text}]]`, `labels`(행 라벨과 quant, qual 접두어 변경, 선택). 같은 순번의 성과 목표, 전략분야, 전략과제 묶음이 한 열 |
| `house` | 비전하우스 (미션 띠, 비전 지붕, 전략목표 기둥 머리, 전략과제 기둥 몸체, 핵심가치 기단) | `mission`, `vision`, `pillars[{title, items}]`, `base[]`(핵심가치, 선택), `numbered`(기본 true), `labels`(행 라벨 변경, 선택) |
| `porter` | 전통형 가치사슬 (지원 활동 띠, 본원적 활동 열, 담당 부서 행, 오른쪽 화살촉) | `support[{title, text 또는 items}]`, `primary[{title, items, owner, mark}]`, `supportLabel`, `primaryLabel`, `ownerLabel`, `tip`(화살촉 안 문구). `mark` 가 true 인 활동은 담당 칸을 음영으로 표시 |
| `logicmodel` | 사업 논리모형 (배치 고정) | `issue[]`, `goal[]`, `beneficiary[]`, `input[]`, `activity[]`, `output[]`, `outcome[]`, `assumption[]`, `labels`(같은 키로 항목 제목 변경, 선택) |
| `canvas` | 비즈니스 모델 캔버스 9블록 (배치 고정) | `partners`, `activities`, `resources`, `value`, `relationships`, `channels`, `segments`, `cost`, `revenue`(각 문구 배열), `numbered`(작성 순서 번호), `labels`(같은 키로 블록 제목 변경, 선택) |
| `market` | 시장 규모 TAM, SAM, SOM (포갠 원 3개와 설명 행) | `levels[{label, name, value, items[]}]` (바깥 원부터 안쪽 원 순서) |
| `flow` | 화살표로 잇는 상자 흐름 | `nodes[{title, items 또는 text, fill}]`, `dir`(h 또는 v). `fill` 값은 navy |
| `matrix` | 2×2 매트릭스와 항목 배치 | `x{label, low, high}`, `y{label, low, high}` (y 축 이름과 양끝 표기는 세로 글자로 조판. low 는 아래 끝, high 는 위 끝), `quadrants[좌상, 우상, 좌하, 우하]`, `items[{label, x, y}]`, `focus`(강조 사분면 순번 0-3), `legend`, `numbered` |
| `pyramid` | 계층 피라미드 | `levels[]`(위층부터), `side[]`(층별 설명, 선택) |
| `cycle` | 순환 단계 | `stages[{title, text}]`, `center` |
| `tree` | 2단 트리 | `root`, `children[{text, children[]}]`, `top`(뿌리 위 상위 주체, 선택), `sides[{side, text, dash}]`(뿌리 좌우 주체, 선택). `side` 값은 left 또는 right, `dash` 가 true 이면 점선 |
| `timeline` | 시간축과 시점별 사건 상자 (추진 경과, 연혁) | `events[{when, title, items 또는 text, mark}]`. `mark` 가 true 인 사건(현재 시점)은 채운 표식과 틴트 상자 |
| `funnel` | 깔때기 (후보에서 최종까지 단계별 선별) | `stages[{label, value, cells[] 또는 items}]` (위 단계부터), `head[]`(설명 열 제목, 선택), `funnelHead`(깔때기 열 제목, 선택). 띠 안에 단계 이름과 대상 수, 오른쪽 칸에 단계별 설명. `head` 가 있으면 `cells` 를 열 순서대로 조판 |
| `governance` | 추진체계도 (가운데 관리 계선과 좌우 심의, 협력 주체) | `spine[]`(연구개발비 전달 순서의 주체), `sides[{at, side, text, dash}]`. `at` 은 연결할 계선 주체 순번(0부터), `side` 값은 left 또는 right, `dash` 가 true 이면 점선(협력) |
| `numbers` | 핵심 수치 타일 | `items[{value, label, note}]` |
| `chart` | 네이티브 차트 | `chart{type, barDir, categories, series, grouping, highlight, numFmt}`. `numFmt` 는 데이터 레이블과 값 축의 숫자 서식 (예: "0.0" 은 소수 첫째 자리까지. 지정하지 않으면 막대와 선 차트는 정수로 반올림하여 표시) |
| `image` | 이미지 또는 자리 상자 | `src`(경로 또는 data URI), `caption`(이미지 아래 설명), `label`(자리 상자 문구) |

- 블록 라벨(valuechain, porter 의 라벨 필드와 goalsystem, house, logicmodel, canvas 의 labels)의 덱 공통 값은 `meta.labels` 의 블록 이름 키로 지정 (`references/templates.md` 라벨 슬롯 절)
- 블록 본문 항목(`items` 와 칸, 행, 단계의 `text`)의 줄바꿈은 항목 구분으로 조판 (항목마다 불릿)
- 라벨, 제목, 결론 띠(`lead`), `text` 블록 문구의 줄바꿈은 개행으로 조판
- `matrix` 의 `x`, `y` 는 사분면 안 위치를 0-1 비율로 지정 (0 은 낮음, 1 은 높음)
- `matrix` 에 `items` 가 있으면 번호 표식과 오른쪽 범례를 조판
- `matrix` 의 `legend` 가 false 이고 `numbered` 가 true 이면 번호 표식만 조판 (번호별 항목은 이웃 표에 기재)
- `grid` 의 `span` 은 아래 행 칸과의 대응으로 읽힘
- 일반 `grid` 의 칸 사이 가로 간격은 0.14인치 (행 라벨과 칸 사이 간격과 같은 값)
- `grid` 의 `style` 이 hierarchy 이면 라벨은 회색 글자로 표시 (비전체계, 목표체계, 목표모델)
- hierarchy 격자의 칸 사이 간격은 0.2인치 (계층을 여백으로 구분)
- `zones` 는 구성요소 상자 1개에 요소 이름 1개를 담음
- `zones` 의 구간 사이에는 점선 구분선을 둠
- `chevrons` 아래 상자는 좌측을 셰브론 꼬리 모서리, 우측을 셰브론 어깨(꼭짓점이 좁아지기 시작하는 지점)에 맞춰 자동 배치
- `flowchart` 기호는 시작과 종료 타원, 처리 사각형, 판단 마름모
- `flowchart` 의 lane 은 행 번호, col 은 열 번호 (0부터)
- `flowchart` 의 lanes 를 생략하면 라벨 없는 행을 lane 최댓값까지 둠
- `flowchart` 기호마다 (lane, col) 칸을 하나씩 지정 (같은 칸의 기호는 겹치므로 빌드 경고. col 을 생략하면 0열)
- 같은 행의 바로 왼쪽 기호로 가는 연결은 직선으로 잇고 분기 라벨은 두 기호 사이 틈에 둠
- 되돌림 연결(같은 행의 왼쪽 기호로 가는 연결)은 기호 아래로 돌아감
- 두 연결선이 같은 선분을 지나면 한쪽의 `route` 를 바꿈
- 기관 기능의 가치사슬은 `porter` 로, 산업의 공급 단계 가치사슬은 `valuechain` 으로 작성
- 가치사슬 진단 칸 오른쪽에는 `summary` 칸을 두어 진단에서 도출한 개선 방향이나 확보 과제를 기재 (value_chain, industry_chain)
- `porter` 의 지원 활동 띠와 본원적 활동 열, 담당 부서 행은 오른쪽 끝을 화살촉 밑변에 맞춤
- `porter` 의 본원적 활동 열은 4-5개, 열마다 주요 업무 3-4개를 기재
- `porter` 의 지원 활동 띠는 한 줄 높이의 얇은 띠로 고정하고 남는 높이는 본원적 활동 열이 받음 (본원적 활동이 주 영역)
- `porter` 의 지원 활동 설명은 띠 폭의 80-95% 길이로 작성
- `porter` 의 화살촉은 활동 묶음과 0.1인치 간격을 두고 오른쪽 이웃 칸이 있으면 꼭짓점과 이웃 칸 사이에 0.2인치 간격을 둠
- `valuechain` 의 지원 기능 띠는 본원적 기능 셰브론 위에 전 단계 폭으로 배치
- `valuechain` 의 공통 기반 띠는 단계별 행 아래에 전 단계 폭으로 배치 (단계별로 나눠 적을 내용은 행으로 작성)
- `valuechain` 행 칸은 셰브론 꼬리 모서리에서 어깨까지의 폭으로 자동 배치
- `valuechain` 의 지원 기능 띠와 공통 기반 띠는 좌우 끝을 단계별 행 칸의 좌우 끝에 맞춤
- `logicmodel` 의 항목 이름, 번호, 배치는 국가연구개발사업 예비타당성조사 수행 세부지침(2024)의 논리모형 구조를 그대로 따름
- `logicmodel` 의 문제/이슈와 가정은 항목이 2개 이상이면 전폭 상자 안에 항목을 가로로 나란히 두고 세로 구분선으로 나눔
- `logicmodel` 의 목표와 수혜자 상자는 지침 원형대로 같은 폭으로 조판
- `logicmodel` 의 목표와 수혜자는 넓은 상자이므로 항목마다 기준값, 목표 시점, 대상 규모를 병기
- `canvas` 는 비즈니스 모델 캔버스 원형 배치를 따름 (상단 5열: 핵심 파트너, 핵심 활동과 핵심 자원, 가치 제안, 고객 관계와 채널, 고객 세그먼트. 하단 2칸: 비용 구조, 수익원). 블록 이름과 자리는 원형 그대로 유지
- `canvas` 의 `numbered` 번호는 캔버스 작성 순서 (고객 세그먼트 1, 가치 제안 2, 채널 3, 고객 관계 4, 수익원 5, 핵심 자원 6, 핵심 활동 7, 핵심 파트너 8, 비용 구조 9)
- `governance` 의 계선은 위에서 아래로 연구개발비가 전달되는 순서(주관 부처, 전문기관, 사업단, 연구개발기관)로 작성
- `governance` 계선의 첫 주체는 테마 색 채움으로 조판
- `governance` 의 좌우 주체는 연결할 계선 주체와 같은 높이에 배치
- `governance` 의 실선은 심의, 점선은 협력 관계를 표시 (선의 의미는 칸 주석 `note` 에 기재)
- `governance` 의 좌우 주체 상자가 주체명의 가장 긴 어절보다 좁으면 계선 상자 폭을 줄여 좌우 상자 폭을 확보 (그래도 모자라면 빌드 경고)
- `tree` 의 `top` 과 `sides` 는 위원회 운영체계처럼 상위 부처, 운영 주관, 실무 지원 주체를 뿌리 주위에 둘 때 사용 (선의 의미는 칸 주석 `note` 에 기재)
- `goalsystem` 과 `house` 는 왼쪽 행 라벨 열(회색 굵은 글자)과 위계 행으로 조판
- `goalsystem` 은 계층도 격자(`grid` style hierarchy)와 같은 서식 (비전 테마 색 칸, 사업 목표 틴트 칸, 나머지 흰 칸, 층 사이 여백)
- `house` 의 비전은 테마 색 사다리꼴 지붕으로 표시
- `goalsystem` 의 성과 목표는 정량 목표와 정성 목표를 `quant`, `qual` 로 나눠 기재
- `house` 의 기둥은 전략목표 제목과 전략과제 2-3개로 작성하고 기둥은 3-4개
- `house` 는 전략목표 앞에 1., 전략과제 앞에 1-1. 번호를 자동으로 붙임 (번호가 불릿을 대신함)
- `house` 의 핵심가치(`base`)는 선택 항목
    + 값이 있으면 값마다 칸을 나눠 기단에 표시
    + 값이 없으면 기둥 아래를 바닥 띠로 닫음
- 저장소(데이터베이스, 문서 저장소)는 `grid` 칸과 `zones` 구성요소에 `shape` 값 db 를 지정하여 원통으로 표시
- `timeline` 의 시점은 왼쪽에서 오른쪽으로 시간순. 사건은 3-6개
- `timeline` 은 추진 경과(연월)와 수행 일정(주차, 제출 시점)에 함께 사용
- `funnel` 의 단계는 3-5개. 위 단계는 옅은 색, 아래 단계는 짙은 색으로 조판
- `funnel` 옅은 띠의 대상 수는 테마 색 글자로 조판 (띠 색과 대비 3:1 미만이면 본문 글자색)
- `funnel` 설명 열은 선별 기준과 방법, 참여 주체처럼 단계마다 같은 항목을 둠 (첫 단계에는 수집 경로별 건수)
- `funnel` 은 후보 과제 선별과 대표성과 선정처럼 대상 수가 줄어드는 절차에 사용
- 영역별 분석 칸 오른쪽에 종합 열을 두는 구성은 `flow` 로 두 칸을 잇고 종합 열은 `summary` 하나로 작성 (pest_scan, benchmark_cases, findings_synthesis)
- `summary` 는 위쪽 테마 색 띠에 한 문장 결론, 아래에 대응 항목 2-4개를 두고 항목 사이를 가는 구분선으로 나눔
- `summary` 항목 제목은 대응 내용의 이름으로 작성 (예: 재원 분담 조정, 전문 인력 확보)
- `summary` 항목마다 내용 2-3개를 작성
- `summary` 항목 내용은 상자 폭 한 줄의 90-100% 길이로 작성 (한 줄을 넘기면 빌드 경고)
- `summary` 는 이웃 분석 칸 높이에 맞춰 칸 높이를 채움
- `summary` 칸이 넓어 항목 문구가 짧아 보이면 `cols` 에서 종합 열 비율을 줄임 (예: 분석 칸 2.8, 종합 칸 1)
- 단계 절차(셰브론, 흐름)의 결과를 종합하는 칸은 절차 오른쪽에 `summary` 로 둠 (workforce_estimation)
- `numbers` 아래 행에 수치와 같은 수의 `bullets` 칸을 두면 수치별 시사점이 열 단위로 대응 (key_numbers)
- `matrix` 와 번호 열이 있는 `table` 을 나란히 두면 사분면 배치와 항목별 조치가 번호로 대응 (priority_matrix, risk_plan)
- `market` 은 하단을 맞춘 원 3개 안에 약칭과 규모를 배치
- `market` 의 오른쪽 설명 행에는 시장 이름, 정의, 산출 근거를 배치
- `market` 의 규모에는 기준 연도와 출처를 병기
- `market` 설명 행은 원 높이를 같은 몫으로 나누고 원 안 약칭을 행 가운데 높이에 두어 수평 연결선 한 줄로 대응
- `market` 설명 칸 폭은 가장 긴 문구 길이에 맞추고 원, 연결선, 설명 칸 묶음을 칸 가운데에 배치 (문구가 칸 폭을 넘으면 칸 폭 전체 사용)
- 칸 제목이 없는 `market`, `matrix` 가 칸 폭보다 좁게 가운데 배치되면 결론 밴드와 수행 Point 밴드의 좌우 끝을 도식의 좌우 끝에 맞춤
- `market` 설명 행은 시장별 정의, 산출식, 성장 추세나 대상 범위 3개 항목으로 채움
- 아래 행과 대응 관계가 없는 칸은 전체 폭 1칸으로 작성 (예: 비전체계의 미션, 비전, 목표)
- `chart` 칸이 폭 2.4인치나 높이 1.2인치보다 작으면 빌드 경고 (레이블 겹침)
- `chart` 의 유형 선택과 레이블 규칙은 SKILL.md 디자인 시스템의 차트 항목을 따름
- 항목 2개 이상을 `items` 배열로 주면 불릿을 붙여 좌측 정렬로 조판
- 항목 1개(`text` 나 항목 1개인 `items`)는 줄바꿈으로 여러 줄이 되어도 불릿 없이 가운데 정렬로 조판
- 항목 2개 이상을 담는 상자는 항목 글줄이 상자 안쪽 폭에서 차지하는 평균 비율이 65% 미만이거나 가장 긴 글줄의 비율이 80% 미만이면 빌드 경고 (상자 글 채움)
- `summary` 는 결론 칸이므로 평균 90%, 가장 긴 글줄 95% 를 하한으로 판정 (열 폭을 가장 긴 항목에 맞추고 나머지 항목을 비슷한 길이로 작성)
- 불릿 상자 항목 문구는 상자 폭 한 줄의 80-95% 길이로 작성
    + 짧은 문구는 대상, 기준, 수치를 병기
    + 긴 문구는 두 항목으로 나눔
- 상자 글 채움 경고가 칸 폭 때문이면 `cols` 비율을 줄이거나 칸 수를 늘림

## 레시피 목록

- 그룹 분류 기준은 슬라이드 내용의 기능
- 그룹 순서는 현황 진단, 분석 결과, 전략 수립, 사업기획, 조직진단, 정보화, 성과관리, 사업관리, 제안사 소개
- 그룹 안 순서는 과업에서 산출물이 만들어지는 순서
- 구성 열은 칸 순서대로 블록 종류를 기재
- 행이 둘 이상이면 (상단), (중단), (하단) 으로 행을 구분
- 한 칸에 블록이 둘 이상이면 위에서 아래 순서로 `+` 로 이음
- 헤드라인 문형은 `references/headline-patterns.md` 의 주제별 문형을 사용
