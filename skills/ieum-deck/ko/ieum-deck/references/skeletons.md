# 목차 골격

- 목차는 RFP 와 문서 목적에 따라 설계
- RFP 가 목차나 평가항목 순서를 지정하면 그 순서를 그대로 사용
- 평가항목 병기형 헤더는 section 에 항목 번호를 병기 (예: "1) 과업 이해도")
- 경로형 헤더는 section 에 "주제 〉 세부" 형식으로 기재 (착수 질의 13번)

## 제안 발표자료 기본 골격

- RFP 가 목차를 지정하지 않은 제안 발표자료에 적용

| 장 | 절 후보 | 구성 | 분량 (20분 발표 30-45장 기준) |
|---|---|---|---|
| Ⅰ. 제안개요 | 배경 및 목적, 목표 및 범위, 추진전략, 추진 프로세스, 제안의 특징, 기대효과 | purpose, scope, strategy, process, features, output_utilization (책임자와 실적 강조 시 pm_profile, case_card, infra_tiles) | 5-8 |
| Ⅱ. 제안업체 현황 | 일반현황, 조직도, 경영상태, 유사 실적 | company2slides.py 산출 공통 파트 (company_profile, bullets 또는 orgchart, finance_status, table 또는 record_cards) | 3-5 |
| Ⅲ. 사업수행계획 | 모듈별 개요(`[Module 1] 모듈명`), Task, Task 묶음, 방법론, 산출물 예시 | module_overview, composite 레시피(`references/recipes.md`), task, task_multi, steps, illustrative | 15-25 (모듈당 2-8) |
| Ⅳ. 사업관리부문 | 추진일정, 수행조직, 투입인력, 관리 방법론, 위험 관리, 보안, 산출물 활용, 사후지원, 추가제안 | gantt, org, table 또는 staff_card, company2slides.py 산출 관리 슬라이드(사업관리 레시피), risk_plan, output_utilization | 6-10 |

- 과업 범위는 시간적 범위(과업 기간과 계획 기간), 공간적 범위(대상 지역이나 기관), 내용적 범위(모듈과 과업 항목)로 구분하여 제시
- 기대효과는 과업 산출물별 활용 방안과 함께 제시 (output_utilization)
- RFP 가 사회적 가치(일자리, 지역, 약자 지원, 안전)를 평가항목으로 두면 사업관리부문에 이행 방안 1장을 배치
- 전문가 협업체계 레시피의 사용 범위는 SKILL.md 구성 선택 절을 따름
- 인력 평가항목은 책임자 프로필 슬라이드에 귀속
- 관리 평가항목은 사업관리부문 슬라이드에 귀속
- 정량 평가항목(신용등급, 실적 건수)은 슬라이드 배정 대상에서 제외
- 작성 순서는 배경과 필요성, 추진전략, 모듈별 수행계획, 산출물과 기대효과, 공통 파트 배치

## 보고회 발표자료

| 단계 | 구성 | 분량 |
|---|---|---|
| 착수보고 | 과업 개요, 추진 방향과 전략, 모듈별 수행계획, 일정과 조직, 협조 요청 사항 | 40-55 |
| 중간보고 | 진행 경과, 착수보고 의견 반영 결과, 모듈별 중간 결과(분석 슬라이드 중심), 잔여 과업 계획, 협의 사항 | 30-40 |
| 최종보고 | 과업 개요와 추진 경과, 결과 요약, 모듈별 결과(분석, 전략, 과제), 이행계획, 기대효과, 의견 반영 결과, 후속 제안 | 50-60 |

- 결과 요약은 과업 개요 뒤에 1-3장으로 배치 (분석 요약과 SWOT, 전략체계, 과제 목록)
- 추진 경과는 보고회, 위원회, 자문회의의 일자와 주요 논의를 시간순으로 제시 (history_timeline)
- 분석 장의 끝에는 시사점 슬라이드 1장을 배치
- 시사점 슬라이드는 분석 결과의 시사점을 전략 이슈로 연결 (findings_synthesis)
- 의견 반영 결과는 앞 단계 보고회와 자문회의 의견별 반영 내용과 위치를 대조 (comment_response)

## 연구개발계획 발표

- 국가연구개발 신규과제 공모의 연구개발계획서 발표에 적용

| 장 | 절 후보 | 분량 |
|---|---|---|
| Ⅰ. 연구개발과제의 필요성 | 배경과 필요성, 기술 현황과 문제점, 파급효과 | 4-6 |
| Ⅱ. 목표 및 내용 | 최종목표와 평가지표, 단계별과 연차별 목표, 수행일정과 주요 결과물 | 6-10 |
| Ⅲ. 추진전략 및 추진체계 | 추진 전략, 컨소시엄 구성과 기관별 역할, 위험 관리 | 3-5 |
| Ⅳ. 연구수행 역량 | 기관 역량, 연구책임자와 참여 연구자 실적, 보유 인프라 | 3-5 |
| Ⅴ. 활용방안 및 기대효과 | 성과 활용, 사업화 전략, 기대효과 | 2-4 |
| Ⅵ. 연구개발비와 보안 | 비목별 연구개발비(budget_plan), 안전과 보안조치 이행계획 | 1-3 |

- `meta.structure` 는 plan (모듈과 Task 검사 대신 계획서 항목 전수 대응을 검사)
- 기획연구(R&D 예산으로 발주된 조사와 기획 과제)는 예외
    + `meta.structure` 는 module
    + 모듈과 Task 는 Ⅱ장 연구내용에 배치
- 목차와 절 순서는 RFP 와 평가표를 따름
- 표의 장 구성은 지정공모형 기준 예시
- 계획서가 정한 항목과 연차는 모두 배치
- 서면 평가를 거친 과제는 Ⅰ장 앞에 지적 사항 반영 대조표 1장을 배치 (comment_response)
- 슬라이드마다 연구개발계획서의 대응 쪽 번호를 `markerNote` 에 표기

## 비R&D 공모 발표

- 실증, 컨설팅, 바우처, 수요기반 지원사업 공모 발표에 적용

| 장 | 절 후보 | 분량 |
|---|---|---|
| Ⅰ. 사업 개요 | 추진 배경, 사업 목표와 범위, 추진 전략, 제안의 특징 | 4-6 |
| Ⅱ. 참여자 현황 | 주관기관, 참여기관, 참여인력, 사업 실적 | 3-5 |
| Ⅲ. 수행부문 A | 대상 발굴, 수행 방안, 효과성 검증, 시험 검증, 운영 방안 | 6-10 |
| Ⅳ. 수행부문 B | 수행부문 A 와 같은 하위 절 구성 (부문 수만큼 반복) | 6-10 |
| Ⅴ. 확산과 성과 | 생태계 활성화, 산업화와 사업화, 일자리, 향후 계획 | 3-5 |
| Ⅵ. 운영관리 | 성과보고, 추진체계, 사업비(budget_plan) | 2-3 |

- `meta.structure` 는 sections (모듈과 Task 검사 대신 RFP 항목 전수 대응을 검사)
- 장과 절의 명칭은 RFP 과업 항목을 그대로 사용
- 수요와 공급이 나뉘는 사업은 Ⅱ장을 수요 기관과 공급 기업으로 나눔
- RFP 요구 항목과 슬라이드의 대응은 섹션대장으로 관리

## 지원사업 운영 제안

- 기업지원, 사업화, 창업, 인력양성 운영기관 공모에 적용

| 장 | 절 후보 | 분량 |
|---|---|---|
| Ⅰ. 제안 개요 | 추진 배경, 대상 현황, 추진 필요성(현장 조사), 과업 범위, 추진 목표 | 5-7 |
| Ⅱ. 수행기관 현황 | 일반현황, 조직과 인력, 유사 운영 실적, 보유 인프라와 네트워크 | 3-5 |
| Ⅲ. 사업 수행계획 | 프로그램별 세부 계획 (진단, 교육, 컨설팅, 네트워킹, 판로와 투자) | 10-18 |
| Ⅳ. 성과관리 | 성과목표 체계, 성과지표와 목표값, 증빙과 점검, 기대효과 | 3-5 |
| Ⅴ. 사업비 사용계획 | 비목별 편성, 분기별 집행계획 | 1-2 |

## 사업기획 신청형 발표

- 기업 R&D 과제와 상용화 과제 공모의 신청 발표에 적용

| 장 | 절 후보 | 분량 |
|---|---|---|
| Ⅰ. 사업 개요 | 배경과 필요성, 사업 정보, 제품과 기술 우수성, 컨소시엄 역량, 추진 전략 | 6-10 |
| Ⅱ. 세부 추진계획 | 모듈별 과업, 검증 계획, 제도 진입, 확산과 마케팅 | 10-16 |
| Ⅲ. 사업 관리계획 | 추진 일정, 목표 관리(PDM), 성과지표(KPI) | 3-4 |
| Ⅳ. 소요 예산 | 예산 편성 내역, 집행 계획 | 1-2 |
| Ⅴ. 기대효과 | 기술 효과, 사업 효과, 사회 효과 | 1-2 |

## 일반 기획 PPT

- 민간 기획서, 사내 보고, 교육 자료에 적용
- 모듈 골격은 `references/methods.md` 의 과업 유형 판별을 따름 (신규 사업과 서비스는 사업기획, 중장기 계획은 전략기획, 시스템 구축 기획은 정보화)
- 목차의 장은 선택한 골격의 모듈로 구성
- 장 명칭은 주제에 맞게 조정
- 파라메트릭 템플릿과 composite 레시피를 그대로 사용
- RFP 해부, 배점 귀속, 제도 워딩, 섹션대장은 생략
- Task 전수 대응과 모듈 개요 규칙은 수행계획 부분이 있을 때만 적용

## 브리핑 덱

- 적용 대상은 SKILL.md 브리핑 덱 절을 따름
- 기본 흐름은 결론, 근거, 조치 사항 (필요하면 배경 슬라이드 1장 추가)
- 첫 슬라이드에 결론을 배치
- 이후 슬라이드는 결론의 근거를 제시
- 상세 근거는 부록 슬라이드로 분리
- 구성은 다른 산출 대상과 같은 기준으로 내용에 맞게 선택

## 보고서형 PPT

- 절 1개당 슬라이드 1장
- 절의 논점은 bullets 패널로 나란히 배치 (md2storyboard 초안은 슬라이드당 패널 5개까지 배치하고 넘치는 패널은 다음 슬라이드로 분리)
- 패널 5개 초안은 bullets 권장 열 수(1-4)를 넘으므로 storyboard 작성 단계에서 패널을 합치거나 다른 구성으로 교체
- 분량 상한 없음
- 장 말미에 종합 슬라이드(conclusion 또는 findings_synthesis)를 배치
- 개요 장 뒤에 결과 요약 1-3장을 배치
- section 에 절 번호를 유지하여 절이 이어지는 헤더를 구성
- 출처 행(source)을 모든 슬라이드에 유지
- 초안은 `md2storyboard.py --kind report` 로 생성
- 생성한 초안은 헤드라인과 패널을 다듬어 완성
